# 本项目与参考项目的价差套利流程对比

参考实现：本地目录 `crypto-trading-open-main`（`arbitrage_monitor_v2`）。  
本项目：`dex-arbitr` P1，默认只监控。扫描发现对齐参考 V2（毛价差 ≥ 0.1%），见 [价差扫描与发现.md](价差扫描与发现.md)。格子字段见 [项目说明.md](项目说明.md)。

---

## 1. 滑点还走「买一买二买三」吗？

**决策不走档。** 小额默认只看卖一/买一：Ask1、Bid1 数量够 `base_qty` 就按一档算；不够记 `thin_book`，不吃第二档。

对齐参考项目：决策 `net = raw − fee`，**不预扣滑点**。滑点用在 **成交之后**，按实际成交价相对决策价扣：

```
买入实滑点 = (成交价 − Ask1) / Ask1 × 100
卖出实滑点 = (Bid1 − 成交价) / Bid1 × 100
```

`cost.default_slip_pct: 0.01` 是成交后 overrun 阈值，超过只记账/告警，不再把方向从决策里丢掉。

走档 VWAP 函数还留着，仅成交后估滑点用。

## 2. 本项目流程（P1，先监控）

`monitor_only: true` 时只记账、打代币关键行，**不会下单**。

**默认 `scan.enabled: true`**（对齐参考监控 V2，本阶段实际在跑）：

```
各所 WS 只写内存盘口（三所两两配对）
    → 每 50ms 扫交集
    → raw = (卖所买一 − 买所卖一) / 买所卖一 × 100
    → 同协议 raw ≥ 0.1% 记机会
    → 跨 DEX（SoDEX）再扣 24h nat，residual ≥ 0.1% 才上榜
    → 控制台和文件打过线币关键行
    → 不走深、不跑格子、不下单
```

**`scan.enabled: false` 才走下面这条格子链**（确认 `intent=open` 是否站得住，再考虑接线发单）：

```
两边 WS 订单簿
    → 盘口过期 / 卖一买一数量不够  →  skip（不算开仓）
    → raw = (卖所买一 − 买所卖一) / 买所卖一 × 100
    → net = raw − 手续费（不预扣滑点）
    → SQLite 记 raw；nat 优先用库里快照，之后定期重算
    → res = net − max(nat, 0)     无快照则 res=0，不开仓
    → res ≥ T1(0.03%) 且站稳 1 秒 → intent=open
    → 规划：taker 高的一所先挂限价，成交后再对另一所市价
    → 挂着期间 res 不够或超时 → 撤未成交单
    → 若已经成交（价差没了也一样）→ 另一边仍市价对冲，避免单边
    → monitor_only → 只打日志 / skip_send，不发到交易所
```

### 当前手续费（写入 venue 配置）

| | maker | taker |
|--|--|--|
| Lighter 主网 | 0.005% | 0.005% |
| RH | 0.012% | 0.035% |

- 两边都吃：0.005 + 0.035 = **0.040%**
- 现在默认先挂后吃（RH taker 更高 → RH 先挂）：0.012 + 0.005 = **0.017%**
- 两边 taker 相同：比 maker，谁挂更便宜谁先挂；maker 也相同 → 两边都吃

### 开仓看的数（仅格子路径）

`res ≥ 0.03%`，不是 `raw`。扫描默认路径只看 `raw ≥ 0.1%`，不看 `res`。

## 3. 参考项目流程（`crypto-trading-open-main`）

两条线：

**A. 分段网格（生产主路径 `main_unified.py`）**

```
多所 WS 订单簿
    → 可成交 raw（卖一/买一）
    → 格子：T1 开第一格，每 grid_step 加一格，最多 max_segments
    → 决策常用原始 spread_pct 对 T1（扣费配置未完全接到格子）
    → 先在 priority 高、常为 limit 的所挂单，成交后再对 Lighter 吃单
    → 拆单、残余量、单腿补单、失败回滚、reduce-only
    → 平仓用「平仓视角」重算盘口，FIFO 按格减仓
```

**B. V3 基础套利（`run_arbitrage_execution_v3.py`）**

```
raw − 两边手续费 = net
net − max(历史中位数, 0) ≥ 阈值 → 开仓
另有资金费率方向 / 年化条件
盈利/止损/费率反转 → 平仓
同样走双腿执行器
```

默认下单不是「永远双市价」，而是 `limit_market`：一挂一吃。只有两腿都配成 market 才双吃。

## 4. 对照表

| | 本项目 | 参考项目 |
|--|--|--|
| 语言 / 形态 | Rust 单进程 | Python，监控 + 执行框架 |
| 交易所 | 两个 Lighter 实例 | 多所（EdgeX、Backpack、Lighter…） |
| 可成交价差 | 卖一/买一，相同 | 相同 |
| 决策扣费 | 按实际下单方式（挂+吃或双吃） | 网格常看毛价差；V3 扣费减中位数 |
| 滑点 | 决策不预扣；成交后按实际成交价扣 | 决策少走深；执行用 slippage 挂/撤 |
| 天然价差 | SQLite 快照，重启直接用，定期重算 | V3 有；分段网格不依赖 |
| 格子 | 公式在，决策按 1 格 | 多格、FIFO、拆单、残余量 |
| 下单 | 规划了先挂后吃；签名未接线 | 实盘执行 + 补单 + 回滚 |
| 资金费率 | 无 | V3 可独立条件 |
| 默认目标 | **先监控，确认 open** | 可监控也可实盘 |

## 5. 以后怎么对比

盯本项目面板时记：

1. 有没有连续的 `intent=open`（不是一跳）
2. 当时 `raw` / `net` / `nat` / `res`（`slip` 决策为 0）
3. `skip_stale` / `skip_spread` 是过滤，不是错过的开仓
4. 同一段行情，参考项目若只看毛价差过 T1，可能更早喊开；本项目要 `res` 过 0.03%

确认识别稳定后，再关 `monitor_only` 并接线签名。在此之前不要当实盘。
