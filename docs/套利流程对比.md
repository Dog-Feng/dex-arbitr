# 套利流程对比

左边：`crypto-trading-open-main`（见 [参考项目套利流程.md](参考项目套利流程.md)）  
右边：本仓库（见 [本系统套利流程.md](本系统套利流程.md)）

结论先说：**主逻辑对齐参考统一分段网格**（`UnifiedOrchestrator` + `UnifiedDecisionEngine`）。扫描环对齐监控 V2。V3 价差+资金费率只拆成滤网挂在网格外面，没有当成开平仓引擎。

---

## 1. 对上哪条入口

| 参考入口 | 本仓库 |
|----------|--------|
| `main_unified.py` 分段网格 | **主路径**：`execution.enabled` → `loop_unified` + `GridEngine` |
| `run_arbitrage_monitor_v2.py` | `scan.enabled` → `loop_scan`（与执行互斥） |
| `run_arbitrage_execution_v3.py` | **没有**这条主路径。扣费、nat、费率否决从这里抽出。V3 自身流程见 [参考项目V3套利流程.md](参考项目V3套利流程.md) |

本仓库不会在「价差两边都没油水」时靠资金费率去开仓，也不会一个币只开一整仓等到止盈点一次性全出。

---

## 2. 分段网格逐项

### 2.1 格子本身

| 功能 | 参考 | 本项目 |
|------|------|--------|
| 开仓阈值 `[T1, T1+step, …]` 共 `max_segments` 格 | 有 | **有** |
| 平仓阈值 `[T0, T1, T2, …]`，T0 = T1 × 0.4 | 有（写死 0.4） | **有**（`t0_ratio` 可配，默认 0.4） |
| 涨到 Tn 加到 n 格；回落跌破 T(n−1) 才减 | 有 | **有** |
| 格数向上取整 | 有 | **有** |
| 判据用毛价差 | 有 | **有**（开仓、平仓格子都看 raw） |
| 开仓门槛随所对费率抬高 | 无 | **没有**（门槛就是配置的 T1） |
| 按币独立 T1/step/格数 | 有 | **没有**（全局一套，只 `base_qty` 按币） |
| `segment_quantity_ratio` | 配置有，热路径基本不用 | **没有** |
| 对称平仓 / 按段利润阈 | 配置有；热路径没走 | **没有** |

最大差别曾经是开仓看净边；现已对齐参考，开仓也看毛价差。

### 2.2 开仓 / 平仓 / 持续性

| 功能 | 参考 | 本项目 |
|------|------|--------|
| 价差 < T1 → Hold | 有 | **有** |
| 持续性够了才下单 | 有（宽松/严格秒桶） | **有**（只有 `persistence_ms` 连续满 N 毫秒，掉线清零） |
| 空仓时价差直接落在第 n 格 → 一次开满 | 有 | **有** |
| 成交后清持续性 | `_reset_spread_persistence` | `grid.forget(slot)`，成功失败都清 |
| 先平后开 | 有 | **有** |
| 有仓锁方向 | 有 | **有** |
| 止损 | 统一引擎里没有 | **没有**（往返净利止损已关掉） |
| 盘口薄跳过平仓 | 有 | **有**（格子/剥头皮本笔量一档不够 → 丢掉平仓意图） |
| reduce-only 仍允许平 | 有 | **有** |

持续性**不要**对齐参考秒桶。保持 `persistence_ms: 1000`；假信号多再 1500–2000；不要低于 500。

### 2.3 执行与风控

| 功能 | 参考 | 本项目 |
|------|------|--------|
| 先挂后吃，失败回滚 | 有 | **有** |
| maker 挂进点差内侧 | 有 | **有**（`maker_inside_ticks`） |
| 价格稳定性（极值窗口） | 有 | **有** |
| 人工介入 / 记账不可信 | 有 | **有** |
| reduce-only + 整点探针 | 有 | **有** |
| 全局限额、退避 | 有 | **有**（名义改成 USDC，不用币本位） |
| 剥头皮 | 有 | **有**（默认开；`scalping_enabled`） |
| 开仓拆单 + 缺口补齐 | 有 | **有**（每轮 `目标格−已持格`；`split_order_size` 可拆开/平） |
| 双限价 | 有 | 配置有 `limit_maker`，不是热路径默认 |
| 休市 | 有 | **没有** |
| 多腿（不同币两条腿） | 有 | **没有** |

## 3. 从 V3 搬过来、但只当滤网

| 搬过来的 | 在参考 V3 里 | 在本项目里 |
|----------|--------------|------------|
| 扣手续费后再看净边 | 开仓主条件 | 只给监控/扫描展示，不进格子 |
| 跨 DEX 扣天然价差 | 开仓主条件；不够点或过期直接拒绝 | 只给监控/扫描展示 residual；开仓看 raw |
| 资金费率年化阈值 + 持续分钟 | 可当**开仓理由**（费率套利） | **只否决开仓 / 持仓退出**，不是开仓理由 |
| 往返净利止损 | 平仓三点之一 | **没有**（统一引擎没有，已从网格热路径关掉） |
| 盈利 ≥ P 全平 | 正常离场 | **没有**（正常离场是格子回落） |
| 费率套利开仓 | 价差没油水时的第二条路径 | **没有** |

一句话：**加减仓跟网格走（开平都看毛价差）；费率会不会抽血、持仓过久要不要跑，跟 V3 滤网走。**

---

## 4. 刻意不同（不是漏实现）

| 点 | 为什么这样 |
|----|------------|
| reduce-only / 退避只挡开仓 | 挡平仓等于把仓锁在交易所里 |
| 持续性用毫秒连续窗口 | 秒桶实现重，行为接近「简化版严格」；已确认不对齐宽松/严格 |
| 名义限额用 USDC | 币本位跨 BTC/ETH/小币不可比 |
| 余额 warn/close 默认 0 | 参考默认 1000/500 会把小额账户一启动清仓 |

---

## 5. 本项目缺的（网格链上参考有）

宽松/严格秒桶、逐币网格参数、休市、多腿。

剥头皮已对齐参考 `SEG-SCALP`（默认开）。这些不是「下一步必须对齐」。要对齐先单独开需求，不要和滤网、定仓混在一次改动里。
