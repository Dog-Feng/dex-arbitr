# 价差扫描与发现

版本：与仓库代码同步  
对齐：`crypto-trading-open-main` 套利监控 V2（`OpportunityFinder` + 分析环）  
本阶段：**只发现、只监控**。不改格子公式，不接线发单。

格子 / `res` / 先挂后吃仍以 [项目说明.md](项目说明.md) 为准，扫描模式默认**不跑**那条开仓链。

---

## 1. 要复刻什么

参考项目**不是**一币一线程，也不是全市场深度 + `res` 开仓。它是：

1. 先圈各所两两都有的永续（他们用成交量名单；我们用启动时 REST 交集，白名单留空即全部）。三所则是 C(3,2) 条所对。
2. 各所 WS 回调**只入内存**，不算价差。
3. 单独一条分析环，每隔十几毫秒扫一遍已订阅的币。
4. 用 **Bid1/Ask1 毛价差**：`(卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100`。
5. `spread_pct ≥ min_spread_pct`（V2 默认 **0.1%**）记为机会。
6. 按毛价差从大到小排序，界面只看 Top-N。
7. 同一 `币+买所+卖所` 续上持续时间（`age`）。

本仓库用 Rust 复刻上述监控逻辑。不复刻：拆单、FIFO 多格、签名下单、资金费率独立开仓。

---

## 2. 和本项目旧路径的关系

| | 扫描发现（本阶段默认） | 旧 P1 格子路径（`scan.enabled: false`） |
|--|--|--|
| 币 | 各所两两永续交集，可不写白名单 | `whitelist: [BTC]` |
| 发现门槛 | 毛价差 `raw ≥ 0.1%` | `res ≥ 0.03%` 且满 10 点 |
| 盘口 | WS 只更新内存 | 每条更新都走 `on_pair` |
| 走深 / 格子 | 不做 | 做（公式不改） |
| 下单 | 不做 | 仍 `monitor_only` / 未接线 |

扫描负责「哪些币现在价差大」；以后要开仓再把 Top 里的币交给格子，不在本阶段做。

---

## 3. 流程

```
启动
  → 各所 REST list_perps
  → 标准化 pair_id，两两取交集（可选 whitelist 再滤一层）
  → 各所一条 WS（Lighter 订 order_book，SoDEX 订 allBookTicker）
  → 回调：books[(venue, pair_id)] = 最新 BBO，立即返回

分析环（默认 50ms）
  → for 每个已匹配的币
       两边盘口齐了？新鲜？BBO 合法？
       两个方向算 raw
       raw ≥ 0.1% → 候选（续 age 或新建）
       跨 DEX（SoDEX ↔ Lighter）：再扣 24h 中位数 nat，residual ≥ 0.1% 才上榜
  → 按 residual / raw 降序
  → 控制台和文件只打过线币的关键行（上榜 / 变化 / 定时 / gone）
```

不按币开线程。与参考项目一样：所级 IO + 一条分析环。

---

## 4. 机会定义（对齐 V2）

```
key        = {pair_id}|{buy}|{sell}
raw        = (sell.bid − buy.ask) / buy.ask × 100
opportunity  iff  两边 BBO 合法且未过期 且  raw ≥ min_spread_pct
                 跨 DEX 还要 residual = raw − max(nat,0) ≥ min_spread_pct（满 10 点）
排序       = residual 从大到小（同协议家族 residual=raw）
age        = 该 key 首次过线至今
本轮没有的 key 从追踪表删掉（参考：过期即移除）
```

同协议扫描**不扣**手续费、**不减** `nat`、**不走**多档滑点。  
跨 DEX（SoDEX ↔ Lighter）扫描会写 SQLite，上榜看 `residual = raw − max(nat,0)`。深度不够只影响「能不能显示一档」，不拿 `base_qty` 走簿。

## 5. 配置

`config/default.yaml`：

```yaml
pairs:
  whitelist: []          # 空 = 交集内全部永续；填 [BTC] 则只扫这些

scan:
  enabled: true
  min_spread_pct: "0.1"  # 与参考 monitor_v2 一致，单位 %
  analysis_interval_ms: 50
  watch_top: 20
  cross_use_natural: true
  log_interval_secs: 30
```

`scan.enabled: false` 时回到旧的单币格子监控。

---

## 6. 控制台与文件（扫描模式）

控制台和 `data/logs/dex-arbitr.log.YYYY-MM-DD` 同一套行，只打过线币：

```
pair=SOL-USD-PERP buy=lighter_rh sell=lighter raw=+0.1420% age=3.1s
pair=ETH-USD-PERP buy=sodex sell=lighter raw=+0.41% nat=+0.28% res=+0.13% age=2.0s
pair=ETH-USD-PERP buy=sodex sell=lighter gone
```

| 字段 | 含义 |
|------|------|
| `pair` / `buy` / `sell` | 币、买所、卖所 |
| `raw` / `nat` / `res` | 毛价差；跨 DEX 中位数；residual |
| `age` | 该方向持续过线的时间 |
| `gone` | 掉到门槛以下 |

长时间没有任何代币行，表示价差经常不到门槛，不是没扫。

## 7. 明确不做（本阶段）

- 改 `grid.rs` / T1 / 分段加仓  
- `place()` / `cancel()` / 关 `monitor_only`  
- 扫描结果直接 `intent=open`  
- 按成交量自动踢出（参考是离线筛的；我们先用交集。以后可加名义深度）  
- 更多所两两连边（已接 Lighter + RH + SoDEX）  
- 资金费率差作为独立发现条件  

---

## 8. 以后怎么接到格子

扫描稳定后：把 `watch_top` 里连续出现的币写进短名单（或自动晋升 K 个），**只对这 K 个**订深度、走 `res` 和格子。宇宙继续用轻量 BBO 扫。开仓条件仍用项目说明里的 `res`，不要用扫描的 0.1% raw 直接下单。
