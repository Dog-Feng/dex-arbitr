# 本系统套利流程

版本：与仓库代码同步（2026-08-27）  
入口：`src/main.rs` → `Controller::run`。本文只写本仓库实际怎么跑，不对照参考项目。对照见 [套利流程对比.md](套利流程对比.md)。

---

## 1. 启动

```
cargo run
  → AppConfig::load()          # config/default.yaml + config/venues/{id}.yaml
  → infra::init_log()          # stderr + data/logs 按天滚动
  → Controller::run(cfg)
```

`cargo run --bin live-test` 只做单所查账户 / 下单 / 撤单，**不进套利环**。

`Controller::run` 顺序：

1. 按 `venues` 建适配器：`sodex` → `SodexAdapter`，`entropy` → `EntropyAdapter`，其余（`lighter` / `lighter_rh`）→ `LighterAdapter`。没配私钥也能监控。
2. 打开价差历史库（`history.enabled`）：SQLite 样本 + 天然价差中位数，给跨 DEX 扣基差用。
3. 起 HTTP（`http.enabled`）：默认 `127.0.0.1:8090`，静态页在 `web/`。页面必须由本进程提供，配置和交易所列表才填得上（`/api/config`、`/api/venues`）。
4. `bootstrap()` 只建盘口 channel。接着 `load_available_pairs()`：各所 `list_perps()` → 符号归一 → `match_all_pairs` 两两交集，**不订阅 WS**。有 HTTP 时等页面点「启动套利」才 `activate_pairs`（按 `pairs.enabled` 过滤、校验 `base_qty`、再订 BBO）；无 HTTP 则立刻按 yaml 激活。
5. 刷新余额 / 持仓 / 资金费率，起后台刷新任务。
6. 按配置进三条环之一。

当前 `config/default.yaml`：`execution.enabled: false`、`scan.enabled: false`，因此默认走 **事件格子环**。要跑统一决策环需把 `execution.enabled` 设为 `true`。

---

## 2. 三条环（互斥，优先级 execution > scan > events）

| 条件 | 环 | 间隔 | 下单 |
|------|----|------|------|
| `execution.enabled: true` | `loop_unified` | `loop_interval_ms`（默认 100ms） | 是（还受 `monitor_only` / `paper_trading`） |
| 仅 `scan.enabled: true` | `loop_scan` | `analysis_interval_ms`（默认 50ms） | 否，只扫毛价差 |
| 两者都关 | `loop_events` | 每次盘口事件 | 格子决策；`monitor_only` 时不发单 |

WebSocket 回调一律只写内存盘口 `books[(所, pair_id)]`，不算价差。价差只在环里算。

---

## 3. 统一决策环（主套利路径）

`tick_execution` 每 100ms：

1. **有持仓 / 挂单 / 对冲中的 pair 先跑**（先平后开；挂单监视不能停）。
2. reduce-only 探针、裸腿补对冲。
3. 其余 pair 才考虑开新仓，受 `max_concurrent_pairs` 和 in-flight 限制。

每条 pair 进 `process_pair`：

```
挂单监视（若有 pending，盯到撤或成交，后面门槛一律跳过）
  → 空仓且所不在 active_venues → 跳过（已有仓继续平）
  → 缺盘口 / 非法 BBO
  → 空仓还查一档深度；有仓只查数据质量（薄盘口不挡平仓）
  → 价格稳定性采样（每轮都记）
  → 有仓锁定持仓方向；空仓双向取优
  → 从 pairs.enabled 读固定每格数量；未配置则跳过
  → 采样 raw、扣费得 net；跨 DEX 采样 nat 得 residual（只给监控/扫描，不进格子）
  → GridEngine.decide → Open / Close / Hold
  → 仅 Open 做容量校验（保证金 + 一档深度）；Close 不被容量拦住
  → 稳定性 / 人工介入 / reduce-only / 费率 / 限额 / 退避
  → plan_hedge → limit-then-market
  → monitor_only 只记 skip_send
     paper 模拟成交写内存持仓
     live 经 exchange_sidecar 发单 + journal
  → 成功或失败都 grid.forget(slot)，下一笔重新攒持续性
```

状态按 `slot_key(pair_id, venue_a, venue_b)` 隔离，不是按币。三所两两组合下同一币有最多 3 条 pair。

## 4. 分段网格（决策核）

实现：`src/domain/grid.rs` 的 `GridEngine`。赌的是价差在区间里扩缩，不要求一次回到零。

```
开仓阈值  [T1, T1+step, T1+2×step, …]  共 max_segments 格
平仓阈值  [T0, T1, T2, …]              T0 = T1 × t0_ratio（默认 0.4）
```

默认：`T1=0.05%`，`grid_step=0.05%`，`max_segments=3`（便宜所对可 override 更密）。

| 规则 | 行为 |
|------|------|
| 空仓、毛价差落在第 n 格 | 目标 = n 格；`split_order_size=0` 时一次开满，否则先下一截 |
| 涨到 Tn / 吃不满 | 目标持仓 n 格，不够就补（用量差，不是格数差） |
| 回落 | 必须跌破 T(n−1) 才进入减仓候选（滞后，防 T1 附近抖动） |
| 跌破 T0 | 目标 0 格，格数够就发（方案 A / D1-c，无往返止盈闸、无止损） |
| 格数 | 向上取整（`ROUND_CEILING`） |
| 开仓判据 | **毛价差 raw**（不扣手续费、不扣 nat） |
| 平仓格子 | 格数看**开仓视角 raw**（页面「毛价差」）。平仓视角只记往返、验一档厚度；拿不到仍 Hold。减格不要求往返净利为正 |
| 止盈 / 止损 | **无**。盈利性由 T1/step 相对该所对往返费自己扛 |
| 入场门槛 | 该所对配置的 T1，不按费率抬高；T1 低于往返费会打 warn |
| 剥头皮 | 默认关。便宜所对（lighter↔entropy）可 override 打开；触发格建议 2 |
| 盘口薄 | 格子/剥头皮平仓：本笔量一档不够 → 丢掉平仓意图。费率/超时/余额清仓不走这条 |
| 持续性 | 默认 `bucket` 秒桶（宽松/严格，对齐参考）。`window` 保留原 `persistence_ms` 连续窗口。成交后 `forget` |
| 方向 | 有仓锁死建仓方向，不再双向取优 |

秒桶：`spread_persistence_seconds <= 1` 时参考实现是达标即放行。宽松=每个自然秒至少一次达标才累加，中间空秒清零；严格=墙钟窗口内每笔都达标。要切回旧逻辑设 `persistence_mode: window`。

T1 / step / 格数在 `pairs.defaults`，可被单个 symbol 或 `overrides` 所对覆盖。`base_qty` 只在 symbol 上指定，开仓后冻进 `Position.base_qty`，持仓周期不再改。

## 5. 价差公式

全部百分比，可成交价差，不用中间价。

```
raw  = (卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100
fee  = 先挂所 maker + 后吃所 taker   # limit_then_market
net  = raw − fee
nat  = 该 pair + 该方向 24h raw 中位数（SQLite）
res  = net − max(nat, 0)            # 监控/扫描上榜；开仓格子看 raw
```

决策只看卖一/买一，不预扣滑点。一档数量不够 → `thin_book`：空仓挡开仓；有仓时格子/剥头皮本笔平仓量不够则丢掉平仓意图。滑点在成交后按实际成交价算。

谁先挂：taker 更高的所先挂限价；相同再比 maker。当前 RH taker 更高，所以 RH 先挂、对边后吃。

## 6. 容量校验与执行

**数量**来自 `pairs.enabled[].base_qty`，不再按保证金除格数定仓。

**容量校验**（`src/app/sizing.rs` 的 `check_capacity`）：本次 Open 的 `qty` 在两腿保证金（已扣占用、乘使用率）和一档深度（`depth_pct`）上是否撑得住。只拦 Open，不拦 Close。占用按 `qty × 当前 mid / 杠杆` 重估。

**规划**（`exec/planner.rs`）：默认 `limit_then_market`。第一腿挂进点差内侧 `maker_inside_ticks` 个 tick。挂着期间开仓价差不够或超时 → 撤；已成交则另一边仍市价对冲。平仓单不因价差变化撤。

**执行**（`exec/executor.rs` + Go `exchange_sidecar`）：

| 开关 | 行为 |
|------|------|
| `monitor_only` | 规划 + 日志，不发单、不占 pending |
| `paper_trading` | 按 BBO 模拟两腿，写内存持仓 |
| 两者都关 | sidecar 实盘；写 journal |

第二腿失败：紧急反向平第一腿；平不掉记裸腿。`hedge_failed_legs` 只补本进程执行期间的失败腿。

## 7. 挂在网格外的滤网

加减仓跟网格走。下面这些**不是**开平仓引擎，只挡「开得值不值 / 会不会抽血 / 亏太多要不要跑」：

| 模块 | 作用 | 挡开仓 | 挡平仓 |
|------|------|--------|--------|
| 扣费 + 跨 DEX 扣 nat | 监控/扫描展示 residual | 否（开仓看 raw） | 否（减格也看开仓视角毛价差） |
| 价格稳定性 | 窗口极值波动超阈值 | 是（格子加格） | 是（格子减格；超时/余额/费率清仓除外） |
| 人工介入 | 记账不可信 | 是 | 是 |
| reduce-only | 交易所只许减仓 | 是 | **否** |
| 资金费率年化 + 持续分钟 | 净支付过大 | 立刻否决 | 持续满分钟才平 |
| 每日开仓次数 / 持仓时长 | 限额 | 是 | 超时会平 |
| 余额 warn/close | 账户过瘦 | warn 停开 | close 才平 |
| 名义敞口 | 单币 / 合计 USDC | 是 | 否 |
| 错误退避 | nonce/限流按所指数退避 | 是 | **否** |

原则：点差过宽、价格稳定性对**格子加减格**都拦。费率/超时/余额清仓不走价格稳定性；reduce-only 和错误退避只拦开不拦平。格子/剥头皮减格在一档不够时丢掉意图（对齐参考）。只有记账不可信才挡风控平仓。

没有 V3 那条「价差没油水就靠资金费率开仓」的路径。没有「盈利 ≥ P 全平」的止盈；正常离场是格子回落。打开剥头皮后离场改成「价差收敛且毛价差回吐达标才减到目标格」，仍不是一次性全平。

---

## 8. 扫描环（不下单）

仅 `scan.enabled: true` 且 `execution.enabled: false`。每 50ms 扫内存盘口：两边齐则算两个方向的 raw；`raw ≥ 0.1%` 上榜。跨 DEX 且 `cross_use_natural` 时看 `res = raw − max(nat,0)`。同协议家族（主网 ↔ RH）不扣 nat。控制台只打过线币的关键行。

## 9. 关键类型

```
Pair             pair_id + 两腿 VenueMarket；slot_key 隔离状态
Bbo              bid/ask/qty + ts
NetSpread        buy, sell, raw_pct, fee_pct, net_pct
Position         slot 上的对锁仓：buy, sell, qty, grid, entry_net
Intent           Open | Close | Hold
HedgePlan        数量、买卖所、先挂后吃两腿
```
