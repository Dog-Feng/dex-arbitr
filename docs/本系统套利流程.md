# 本系统套利流程

版本：与仓库代码同步（2026-08-31）  
入口：`src/main.rs` → `Controller::run`。本文只写本仓库实际怎么跑，不对照参考项目。对照见 [套利流程对比.md](套利流程对比.md)。

---

## 1. 启动

启动用 **`.\target\release\dex-arbitr.exe`**（Windows）或 `./target/release/dex-arbitr`，`RUST_LOG=info`。不要 `cargo run`（盘口会刷屏，且编不过正在跑的 exe）。

```
release 二进制
  → AppConfig::load()          # config/default.yaml + config/venues/{id}.yaml
  → infra::init_log()          # stderr + data/logs 按天滚动
  → Controller::run(cfg)
```

`cargo run --bin live-test` 只做单所查账户 / 下单 / 撤单 / 查所方盈亏，**不进套利环**。

`Controller::run` 顺序：

1. 按 `venues` 建适配器：`sodex` → `SodexAdapter`，`entropy` → `EntropyAdapter`，其余（`lighter` / `lighter_rh`）→ `LighterAdapter`。没配私钥也能监控。
2. 打开价差历史库（`history.enabled`）：SQLite 样本 + 天然价差中位数，给跨 DEX 扣基差用。
3. 起 HTTP（`http.enabled`）：默认 `127.0.0.1:8090`，静态页是 **`web/dist`**（Vue 构建产物），不是 `web/src`。改前端后 `cd web && npm run build`；`assets/app.js` 无 hash，旧页面可能要 Ctrl+F5。页面必须由本进程提供，配置和交易所列表才填得上（`/api/config`、`/api/venues`）。
4. `bootstrap()` 只建盘口 channel。接着 `load_available_pairs()`：各所 `list_perps()` → 符号归一 → `match_all_pairs` 两两交集，**不订阅 WS**。有 HTTP 时等页面点「启动套利」才 `activate_pairs`（按 `pairs.enabled` 过滤、校验 `base_qty`、再订 BBO）；无 HTTP 则立刻按 yaml 激活。
5. 刷新余额 / 持仓 / 资金费率，起后台刷新任务。
6. 按配置进三条环之一。

当前 `config/default.yaml`：`execution.enabled: false`、`scan.enabled: false`，因此默认走 **事件格子环**。要跑统一决策环需把 `execution.enabled` 设为 `true`。

## 2. 三条环（互斥，优先级 execution > scan > events）

| 条件 | 环 | 间隔 | 下单 |
|------|----|------|------|
| `execution.enabled: true` | `loop_unified` | `loop_interval_ms`（默认 100ms） | 是（还受 `monitor_only` / `paper_trading`） |
| 仅 `scan.enabled: true` 或页面启动扫描 | `loop_scan` | `analysis_interval_ms`（默认 50ms） | 否，σ−Δ 发现 |
| 两者都关 | `loop_events` | 每次盘口事件 | 格子决策；`monitor_only` 时不发单 |

WebSocket 回调一律只写内存盘口 `books[(所, pair_id)]`，不算价差。价差只在环里算。

---

## 3. 统一决策环（主套利路径）

`tick_execution` 每 100ms：

1. **有持仓 / 挂单 / 对冲中的 pair 先跑**（先平后开；挂单监视不能停）。
2. 裸腿补对冲（`hedge_failed_legs`，只补本进程执行失败的腿）。
3. 其余 pair 才考虑开新仓，受 `max_concurrent_pairs` 和 in-flight 限制。

每条 pair 进 `process_pair`：

```
挂单监视（若有 pending，盯到撤或成交，后面门槛一律跳过）
  → 空仓且所不在 active_venues → 跳过（已有仓继续平）
  → 缺盘口 / 非法 BBO / 不新鲜
  → 空仓还查一档深度；有仓只查数据质量（薄盘口不挡强制离场）
  → L=`legs[0]`，R=`legs[1]`；k>0 空 L 多 R
  → 从 pairs.enabled 读固定每格数量；未配置则跳过
  → 合法盘口入窗（1Hz）：跨所 mid 得 μ；各所买卖点差得中枢
  → 满 μ 窗才允许开仓；满点差窗才有 C。空仓 C 未满不开；有仓 C 未满暂用 C=0
  → 每拍 Δ = max((target% + F + C)/(1−2h), F+C)；C = 两所 live 中枢平均，不冻
  → 采样 raw、扣费得 net；跨 DEX 采样 nat 得 residual（只给监控/扫描，不进 STEP）
  → WindowGridEngine.decide → Open / Close / Hold
  → 仅 Open 做容量校验（保证金 + 一档深度）；Close 不被容量拦住
  → 人工介入（开和平都挡）
  → plan_hedge 后 force_market_taker（阶段 1 双腿市价，不看 yaml order.style）
  → monitor_only 只记 skip_send
     paper 模拟成交写内存持仓
     live 经 exchange_sidecar 发单 + journal
  → 成功或失败都 window_grid.forget(slot)，下一笔重新攒持续性
```

状态按 `slot_key(pair_id, venue_a, venue_b)` 隔离，不是按币。三所两两组合下同一币有最多 3 条 pair。

## 4. 滑动窗口 STEP（决策核）

实现：`src/domain/window_grid.rs` 的 `WindowGridEngine`。相对窗口均值 μ 追有符号 STEP，不是绝对 T1。详见 [滑动窗口-阶段1-追STEP.md](滑动窗口-阶段1-追STEP.md)。

```
raw = (s_exec − μ) / Δ
Δ = max((target% + F + C) / (1−2h), F+C)     F = 四腿市价费；C = 两所点差中枢平均；h = step_hysteresis
k ∈ {−N … +N}              N = max_segments
加仓：raw ≥ k+1 − h
减仓：raw ≤ k−1 + h
过零必须先回 0；到 ±N 停加不停减
```

默认：`target_bp=1`，`max_segments=3`。`h` 代码缺省 0.25，当前 yaml `"0"`。满 `window_samples` 个秒级点才有 μ 和各所点差中枢（代码默认 10000 ≈ 2h47m；当前 yaml 写 1000 ≈ 17 分钟）。`h=0.25` 时一格只锁 0.5Δ；`h=0` 满格才开、回到 μ 才平。C 每拍 live、不冻；滑点 / 资金费 / nat 不加进 Δ。

| 规则 | 行为 |
|------|------|
| 未满 μ 窗 | Hold，不开仓（「采样 n/cap」） |
| 未满点差窗、空仓 | 不开仓（「点差 n0/cap n1/cap」） |
| 未满点差窗、有仓 | 暂用 C=0，仍可减格 |
| 空仓、残差站住 1−h 格 | `0→+1`（空 L 多 R）；负边则 `0→−1` |
| 已有仓 | 只 ±1，不跳步 |
| 开仓判据 | **相对 μ 的 raw**（不扣 nat） |
| 平仓视角 | 只记往返、验一档厚度；拿不到仍 Hold |
| 止盈 / 止损 | **无**。盈利性由 Δ 相对四腿费 + 两所点差中枢平均自己扛 |
| 剥头皮 / T1 / T0 | **已删除** |
| 盘口薄 | 格子平仓：本笔量一档不够 → 丢掉平仓意图 |
| 持续性 | `persistence_ms` 时间窗 + `persistence_min_hits` 累计达标。成交后 `forget` |
| 方向 | L=`legs[0]`，R=`legs[1]`；k>0 空 L 多 R。阶段 1 强制双腿市价 |

`target_bp` / `max_segments` 在 `pairs.defaults`，可被单个 symbol 或 `overrides` 所对覆盖。`base_qty` 只在 symbol 上指定，开仓后冻进 `Position.base_qty`，持仓周期不再改。

同一拍合法盘口还给 **每个所** 采买卖点差 \(c=(\mathrm{ask}-\mathrm{bid})/\mathrm{mid}\times 100\)，窗口长度与 μ 相同。满窗均值即该所**点差中枢**。有仓不冻。两所中枢的算术平均 \(C=(\mu_{c,A}+\mu_{c,B})/2\) 每拍折进 Δ。快照字段 `venue_stats`；配置页「交易所持仓」一行一个已加载所（点差中枢 / 本次成交名义 / 持仓汇总）。匹配瞬间 `round_trip_spread` 常为 0，满窗后才有 C。

## 5. 价差公式

全部百分比，可成交价差，不用中间价。

```
raw  = (卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100
fee  = 双腿 taker                         # 阶段 1 市价
net  = raw − fee
nat  = 该 pair + 该方向 24h raw 中位数（SQLite）
res  = net − max(nat, 0)            # 监控/扫描上榜；开仓格子看 raw
```

决策只看卖一/买一，不预扣滑点。一档数量不够 → `thin_book`：空仓挡开仓；有仓时格子本笔平仓量不够则丢掉平仓意图。滑点在成交后按实际成交价算。

yaml `order.style` 仍默认 `limit_then_market`（阶段 2 用）。阶段 1 发单不走「谁先挂」。

## 6. 容量校验与执行

**数量**来自 `pairs.enabled[].base_qty`，不再按保证金除格数定仓。

**容量校验**（`src/app/sizing.rs` 的 `check_capacity`）：本次 Open 的 `qty` 在两腿保证金（已扣占用、乘使用率）和一档深度（`depth_pct`）上是否撑得住。只拦 Open，不拦 Close。占用按 `qty × 当前 mid / 杠杆` 重估。

**规划**（`exec/planner.rs`）：阶段 1 在 `plan_hedge` 之后 `force_market_taker`。`HedgeExecutor::run_plan` 看 **`plan.style`**，不看 yaml `order.style`。yaml 默认 LTM 时也不会挂 Post-only。

**执行**（`exec/executor.rs` + Go `exchange_sidecar`）：

HTTP 开着时是否发单看页面「启动套利」；关着看 `execution.enabled`。点启动即经 sidecar 实盘。

阶段 1 与阶段 2 **确认窗口相同、回滚不同**。市价或 IOC 发出后，sidecar 等**该 `order_id` 的私有 WS** 最多 `order.ioc_fill_wait_ms`（默认 1 秒，可改 2/3 秒）；没有推送再 **REST 查一次该单**；仍没量当作失败。不用账户缓存仓位差，也不再做激进限价 IOC。

`place` 已成功但成交认不到（`SECOND_LEG_UNKNOWN`）**不再发下一张市价单**：不紧急平、不重试、不自动裸腿补单。认不到 ≠ 没成交，再发会叠仓。

- **分流**：`symmetric_limit=false` 才走阶段 1 开仓条件（μ / 点差窗 / 持续性 / 容量）。`true` 时本拍进邻档，不走 `WindowGridEngine`。F=0 只拦阶段 2。
- **阶段 1 双市价**：两腿**同时** `place`，各自 `ioc_fill_wait_ms`+查一次。都确认 → 按 `min` 记账，多出来的腿市价平掉（平仓认不到则整轮不记账）。都没成 → 结束。一腿确认、一腿确定没成 → 市价平已成的那腿（最多 3 次）。任一腿认不到 → **两边都不再发**（含紧急平），人工核对两所。
- **阶段 2 邻档**：第一腿限价挂着，确认成交后才发第二腿市价。第二腿失败 → 立刻市价平第一腿。第二腿不明 → 不平第一腿。**F=0 只拦阶段 2 挂单**（面板「费率未加载」）。点停止后已发出的邻档成交**不再**市价对冲 / 紧急平。面板「邻档 n/2」是内存 pending；成功日志 `limit_market: first leg posted`。
- 回滚：纯市价，每次同样「`ioc_fill_wait_ms` 推送 + 查一次」。未确认再发，最多 3 次；仍未确认 → `NAKED_FIRST_LEG`，挂人工介入。
- Lighter：WS 的 orders 是市场 id map，成交还要订 `account_all_trades`。解析账户/市场精度不能拆对象，否则挂单报 `decimals unknown`、余额报 `snapshot unavailable`。

`hedge_failed_legs` 只补本进程执行期间的失败腿。启动时已有的 Foreign 仓只告警，不自动补对冲。

**平仓盈亏**（执行带列 **本次 bp** = API `pnl_pct` × 100，即 `0.02` = 2 bp）：开仓均净边 + 本笔两腿成交价平仓毛边 − 双腿 taker 费。paper 同样有数。缺成交价时退回决策盘口估的往返。不把交易所累计已实现加进来（资金费、同币其它仓、各所字段口径会打歪）。`live-test fill-pnl` 仍可单独核对所方已实现。

成交价必须是**真实均价**。sidecar 市价单若把滑点保护限价（信号 × (1±`max_slippage_pct`)）当成 `avg_price`，每腿会多记约 10 bp 假亏，开+平约 20 bp，和所方历史对不上。现网：Entropy 用下单响应 `avgPx` / `userFills`，缺则留空；Lighter IOC 不回保护限价。上层若看到成交价贴着保护限价，改用决策 BBO 记账。

进程只提供 `web/dist`：改 Vue 后 `cd web && npm run build`；`app.js` 无 hash，浏览器可能要 Ctrl+F5。

## 7. 挂在网格外的门

加减仓跟网格走。`risk` 整段（稳定性、费率闸、限额、reduce-only 探针、退避）已拆掉，后续重做。现在还拦的：

| 模块 | 作用 | 挡开仓 | 挡平仓 |
|------|------|--------|--------|
| 盘口新鲜 / 合法 BBO | `data_freshness_ms` | 是 | 是（没有盘口无法下单） |
| 一档深度 | 空仓 `books_tradable`；格子平仓量不够 → 丢意图 | 是 | 格子减格：是；强制离场不走这条 |
| 容量 / 保证金 | `check_capacity` | 是 | **否** |
| 人工介入 | 记账不可信 | 是 | 是 |
| 扣费 + 跨 DEX 扣 nat | 监控/扫描展示 residual | 否（开仓看 raw） | 否 |

没有 V3 那条「价差没油水就靠资金费率开仓」的路径。没有「盈利 ≥ P 全平」的止盈；正常离场是 STEP 朝 μ 收回。

## 8. 扫描环（不下单）

页面「启动扫描」走 `/api/scan/start`，不校验 `pairs` / `base_qty`。与执行互斥。流程见 [扫描方案.md](扫描方案.md)。

每 `analysis_interval_ms` 读内存盘口；入窗仍 1Hz。满 `scan.window_samples` 后按 σ−Δ 排序，每币一行最优两所，推 `snap.scan`。候选币会补订宇宙里同币的其它所，用来填各 DEX 列的价格均值 / 点差均值。

---

## 8.1 持仓对账

账户刷新后 `audit_memory_positions`：两腿反向时按重叠对冲量 `min(|a|,|b|)` 校正内存。实盘少则缩内存；实盘多则在上限内抬内存（漏记成交），后续平仓才平得干净。单次最多抬到 `max(4×当前量, 当前量+8×base_qty)`，再大的跳变只告警（同一槽位 30 秒一次）。两腿同号视为对冲量 0。Foreign 裸仓不自动补对冲。已经按内存全平、所上还剩对冲残仓时，对账认领不了，需手工 reduce-only。

## 9. 关键类型

```
Pair             pair_id + 两腿 VenueMarket；slot_key 隔离状态
Bbo              bid/ask/qty + ts
NetSpread        buy, sell, raw_pct, fee_pct, net_pct
Position         slot 上的对锁仓：buy, sell, qty, grid, entry_net
Intent           Open | Close | Hold
HedgePlan        数量、买卖所、两腿（阶段 1 均为 market_taker）
```

相关源码：`src/app/controller.rs`、`src/domain/window_grid.rs`、`src/app/window_spread.rs`、`src/app/sizing.rs`、`src/exec/`、`src/exchange/`（行情 HTTP/WSS 见 `net.rs`）。

空仓面板「毛价差」是 \((\mathrm{mid}_L-\mathrm{mid}_R)/\mathrm{avg}\times 100\)（有符号）。下单耗时：sidecar 从本地签名计到交易所收单回包（不含 nonce/锁/成交回查），配置页「签名→确认」列 `sign+send=合计ms · 全链路wallms`；日志 `{venue} place rtt`。Lighter / SoDEX / Entropy 同一口径，见 [新增DEX对齐清单.md](新增DEX对齐清单.md) §4.9。
