# 配置参考

`config/default.yaml` 是唯一全局配置文件，启动时与 `config/venues/*.yaml` 合并读取。
所有字段都有默认值，只需覆盖你想改的。

字段按功能块排列，每块只列出**实际需要决策的项**，纯说明性注释不重复搬进来。

---

## 1. system

| 字段 | 默认 | 说明 |
|---|---|---|
| `monitor_only` | `false` | `true` = 只监控不发单（扫描和决策都跑，但 `spawn_run_plan` 不执行）。安全模式，随时可热改（改配置后重启） |
| `data_freshness_ms` | `3000` | 盘口超过这么多毫秒没有更新就视为过期，停止开平仓决策 |
| `log_dir` | `data/logs` | 日志目录，按天滚动 |

---

## 2. venues

列表，填入要接入的所 ID。目前支持：`lighter`、`lighter_rh`、`sodex`、`entropy`。

每个 ID 对应 `config/venues/{id}.yaml`（`lighter_rh` 例外，映射到 `lighter_robinhood.yaml`）。

---

## 3. pairs

只有列在 `enabled` 里的交易对才进决策环。启动时仍加载各所交集全集（`GET /api/pairs/available`），勾选并填了 `base_qty` 后才订阅、才开仓。

| 字段 | 默认 | 说明 |
|---|---|---|
| `defaults.max_segments` | `3` | 未单独指定时的 \|STEP\| 上限（`max_step`） |
| `defaults.target_bp` | `"1"` | 扣完 \(F+C\) 后要剩的净利（bp）。1 bp = 0.01%。阶段 1：\(F=2\times(t_A+t_B)\)，\(C=\) 两所点差中枢平均。阶段 2：\(F=2\times(\mathrm{maker}_{挂}+\mathrm{taker}_{市})\)，\(C=\) 市价所中枢。Δ = max((目标% + F + C)/(1−2h), F+C)。滑点/资金费/nat 不加 |
| `defaults.split_order_size` | `0` | 单笔最大开/平仓量。0 = 不拆 |
| `enabled[].symbol` | 必填 | 如 `BTC` |
| `enabled[].base_qty` | 必填 | 每格币数。不可被所对 override |
| `enabled[].overrides` | `[]` | 按所对覆盖 `target_bp` / `max_segments`。`venues` 两个 id，顺序无关 |

已删除：`initial_spread_threshold`（绝对 T1）、`t0_ratio`、`scalping_*`。窗口参数在 `grid` 段。

---

## 4. execution

控制决策环是否启动以及如何运行。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | `false` = 回到纯扫描模式（`scan.enabled` 控制） |
| `loop_interval_ms` | `100` | 决策环的 tick 间隔（毫秒）。调小会增加 CPU 和 REST 频率，一般不需要改 |
| `paper_trading` | `false` | `true` = 走完整决策链但不向交易所发单，内存持仓会更新 |
| `hedge_failed_legs` | `true` | 启动时发现遗留裸腿（上次执行失败留下），是否自动补对冲 |

---

## 5. sizing（容量校验）

不再定仓。这里只校验「按配置的每格数量开得起吗」。

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_concurrent_pairs` | `1` | 同时持仓的最大 pair 数（活跃槽位 = 持仓 + pending 开仓）。加大前确认保证金足够 |
| `leverage_multiplier` | `2` | 保证金校验用的杠杆倍数。两所的杠杆相同时用这个全局值；不同时在 venue 配置里单独写 |
| `depth_pct` | `50` | 单笔下单量不得超过一档量的这个比例。50 = 最多用 L1 数量的一半 |
| `refresh_balance_secs` | `1` | 账户余额和各所原始仓刷新间隔（秒）。页面「交易所持仓」里的**持仓**列跟这个走；点差中枢跟入窗，交易量跟成交回调 |
| `margin_utilization_pct` | `90` | 可用余额用到多少比例再停开。90 = 留 10% 缓冲 |
| `fallback_available_usdc` | `500` | SoDEX 余额接口返回空时的回退值 |

---

## 6. live_test

| 字段 | 默认 | 说明 |
|---|---|---|
| `dex_test_mode` | `false` | 单所小额验证模式，`true` 时下单量被夹到 `max_qty` |
| `max_qty` | `0.001` | `dex_test_mode` 下的单笔最大量（币本位）。正常套利时 `dex_test_mode: false`，这个字段不生效 |
| `journal_path` | `data/executions.sqlite` | 执行日志 SQLite 路径。页面执行带「本次 bp」读 `pnl_pct`（成交价往返），不读所方累计已实现。见 [本系统套利流程.md](本系统套利流程.md) §6 |

---

## 7. http

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉则不起 HTTP 服务 |
| `bind` | `127.0.0.1:8090` | 监听地址。`auth_token` 为空时程序自动回落到 `127.0.0.1`，即使写了公网地址 |
| `auth_token` | `""` | Bearer token。空 = 不鉴权但只本机可访问；设值后对外暴露。`/api/positions` 含余额和持仓，不要无 token 公网开放 |
| `web_root` | `web/dist` | 进程只提供这份构建产物，不读 `web/src`。改 Vue 后 `cd web && npm run build`。产物文件名固定为 `assets/app.js`（无 hash），浏览器可能要 Ctrl+F5 |

页面每 250ms 拉 `/api/snapshot`。服务端 HTTP/1 应答后拆连接（不用 keep-alive），避免 Linux 默认 1024 FD 被空闲 socket 打满。

---

## 8. scan

页面「启动扫描」打开扫描环，与执行互斥。热改三项：`watch_top` / `analysis_interval_ms` / `scan.window_samples`（不要绑 `history.min_points`）。细则见 [扫描方案.md](扫描方案.md)。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 启动扫描时由页面打开；与执行互斥 |
| `analysis_interval_ms` | `50` | 扫描环间隔（毫秒），下限 10。入窗仍 1Hz |
| `watch_top` | `20` | 扫描表最多几行（按币，不是按所对） |
| `window_samples` | yaml `120` | 满这么多个秒级点才打分 |
| `min_volume_24h_usdc` | yaml `"3000000"` | 单所该币 24h 合约名义下限。写成 0 时仍按 1000 万 |
| `coarse_refresh_secs` | `60` | 粗筛重跑。结果为空则保留当前候选 |
| `max_own_spread_pct` | `"0.15"` | 现码不作硬门；点差之和只用于候选排序 |
| `min_level_notional_usdc` | `"200"` | 现码不作硬门 |
| `candidate_cap` | `0` = `max(watch_top×4, 40)` | 长订 WS 上限 |

## 9. grid（滑动窗口）

| 字段 | 默认 | 说明 |
|---|---|---|
| `persistence_ms` | `1000` | 检查时间窗（毫秒）。决策环 100ms 时 1 秒大约查 10 次 |
| `persistence_min_hits` | `5` | 时间窗内累计达标次数（填 5 或 7）。0 = 连续不掉线（中间掉一次就清零） |
| `window_samples` | `10000`（代码默认） | 满这么多个秒级点才有 μ（跨所 mid 价差）和各所点差中枢。当前 yaml 写 `1000`（约 17 分钟）；10000 ≈ 2h47m |
| `sample_interval_ms` | `1000` | 入窗间隔。1000 = 1Hz。跨所 \(s\)：同桶覆盖为最后一次；各所买卖点差：同桶同所多次取平均 |
| `step_hysteresis` | 代码 `0.25`；yaml `"0"` | 加仓 raw ≥ k+1−h，减仓 raw ≤ k−1+h。必须 &lt; 0.5。0.25 时一格锁 0.5Δ；0 = 满格才开、回到 μ 才平 |
| `symmetric_limit` | `false` | `true` = 阶段 2 邻档限价。页面启动套利时可热改 |
| `quote_reprice_ratio` | `"0.2"` | 空仓 \(\lvert\mu_{\mathrm{live}}-\mu_{\mathrm{quote}}\rvert\ge\) 该比例 ×Δ 才撤邻档重挂 |
| `min_quote_gap_ratio` | `"0.3"` | 加仓档：可执行价差离格线至少这么多 ×Δ 才新挂。减仓档不走这条 |

**判据**：μ 满窗后相对中枢追有符号 STEP（±1、过零须经 0、到 ±N 停加不停减）。空仓还要点差窗满才开；有仓点差未满暂用 C=0。阶段 1 强制双腿市价（跟 plan，不看 yaml `order.style`）；F=0 **不拦**开仓。阶段 2 F=0 **不挂邻档**（面板「费率未加载」；yaml 免费档 `"0"` 也会踩到）。配置页芯片发黄只按往返费估 Δ（没有 live C）。详见 [滑动窗口-阶段1-追STEP.md](滑动窗口-阶段1-追STEP.md)、[滑动窗口-阶段2-对称挂限价.md](滑动窗口-阶段2-对称挂限价.md)。

## 10. order（下单）

| 字段 | 默认 | 说明 |
|---|---|---|
| `style` | `limit_then_market` | yaml/页面默认。阶段 1 热路径**忽略**此项，发单跟 `plan.style=market_taker`。阶段 2 才用 LTM：费率高的所先挂限价，成交后对手所市价 |
| `limit_timeout_ms` | `2000` | 追逐型限价（非邻档）单轮最长等待。邻档第一腿不走这个 |
| `adjacent_timeout_ms` | `0` | 邻档第一腿存活毫秒。0 = 只按事件撤（对面先成 / 改价 / 边没了），不按秒转市价。面板「邻档 n/2」是内存 pending，不是 DEX 查单 |
| `maker_inside_ticks` | `1` | 阶段 1 追逐限价：往点差**内侧**挪几个 tick。阶段 2 邻档：买 ≤ bid−n tick、卖 ≥ ask+n tick（离盘口再退开；代码至少按 1）。0 在邻档路径仍按 1 |
| `limit_retry_count` | `3` | 第一腿最多重试几轮（每轮用最新盘口重算价格，部分成交累积） |

---

## 11. cost（成本参数）

| 字段 | 默认 | 说明 |
|---|---|---|
| `default_slip_pct` | `0.01` | 决策不预扣滑点；成交后用实际成交价扣，超过这个值记 overrun 日志 |
| `max_slippage_pct` | `0.1` | 市价单滑点保护上限（%）。以**决策信号价**（不是下单时盘口）为基准，超出则交易所直接拒单 |
| `emergency_slippage_multiplier` | `50` | 平仓/紧急平仓/补对冲时把 `max_slippage_pct` 放大这么多倍。对齐参考「紧急平仓 50× 滑点」——平不掉的风险远大于穿档成本 |

---

## 12. history（天然价差）

开关、窗长、采样间隔、重算间隔已写死代码默认（开库、5s 采样、24h 窗、30 分钟重算）。页面只热改 `min_points`（样本数）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `db_path` | `data/spreads.sqlite` | 历史快照 SQLite 路径 |
| `min_points` | `10` | 至少这么多个点才出中位数 |
| `max_age_secs` | `200` | 样本过期秒数 |

---

## 13. 已拆掉的 `risk` 段

稳定性、费率闸、限额、reduce-only 探针、错误退避整段已从配置和热路径拿掉，后续重做。现在仍拦：盘口新鲜度、一档深度、保证金/容量、人工介入。阶段 2 另拦：F=0 不挂邻档、Foreign/裸腿不挂、输掉竞态冷却 3 秒。一档不够空仓记 `thin_book`，有仓时格子平仓量不够则丢掉减格意图。

## 14. 快速配置指南

**小额测试**（固定每格数量，单币）：

```yaml
execution:
  paper_trading: true   # 先 paper 验证
sizing:
  max_concurrent_pairs: 1
pairs:
  defaults:
    target_bp: "1"
  enabled:
    - symbol: BTC
      base_qty: "0.001"
```

**转正式运行**（多币，注意保证金）：

```yaml
execution:
  paper_trading: false
sizing:
  max_concurrent_pairs: 3
pairs:
  enabled:
    - symbol: BTC
      base_qty: "0.001"
    - symbol: ETH
      base_qty: "0.02"
```

**只监控**（不发单，看价差分布）：

```yaml
system:
  monitor_only: true
execution:
  enabled: false
scan:
  enabled: true
  watch_top: 20
  analysis_interval_ms: 50
```
