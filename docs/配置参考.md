# 配置参考

`config/default.yaml` 是唯一全局配置文件，启动时与 `config/venues/*.yaml` 合并读取。
所有字段都有默认值，只需覆盖你想改的。

字段按功能块排列，每块只列出**实际需要决策的项**，纯说明性注释不重复搬进来。

---

## 1. system

| 字段 | 默认 | 说明 |
|---|---|---|
| `monitor_only` | `false` | `true` = 只监控不发单（扫描和决策都跑，但 `spawn_run_plan` 不执行）。安全模式，随时可热改（改配置后重启） |
| `data_freshness_ms` | `3000` | 盘口超过这么多毫秒没有更新就视为过期，停止开平仓决策 |
| `log_dir` | `data/logs` | 日志目录，按天滚动 |

---

## 2. venues

列表，填入要接入的所 ID。目前支持：`lighter`、`lighter_rh`、`sodex`、`entropy`。

每个 ID 对应 `config/venues/{id}.yaml`（`lighter_rh` 例外，映射到 `lighter_robinhood.yaml`）。

---

## 3. pairs

只有列在 `enabled` 里的交易对才进决策环。启动时仍加载各所交集全集（`GET /api/pairs/available`），勾选并填了 `base_qty` 后才订阅、才开仓。

| 字段 | 默认 | 说明 |
|---|---|---|
| `defaults.max_segments` | `3` | 未单独指定时的格数 |
| `defaults.initial_spread_threshold` | `0.05` | 默认 T1（%） |
| `defaults.grid_step` | `0.05` | 默认格距（%） |
| `defaults.t0_ratio` | `0.4` | T0 = T1 × 该系数 |
| `defaults.scalping_enabled` | `false` | 默认关剥头皮 |
| `defaults.scalping_trigger_segment` | `2` | 进入剥头皮的开仓视角格子 |
| `enabled[].symbol` | 必填 | 如 `BTC` |
| `enabled[].base_qty` | 必填 | 每格币数。不可被所对 override |
| `enabled[].overrides` | `[]` | 按所对覆盖 T1/step/格数/剥头皮。`venues` 两个 id，顺序无关 |

`grid` 段只留持续性（`persistence_*`）。阈值在 `pairs.defaults` / `enabled` / `overrides`。

---

## 4. execution

控制决策环是否启动以及如何运行。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | `false` = 回到纯扫描模式（`scan.enabled` 控制） |
| `loop_interval_ms` | `100` | 决策环的 tick 间隔（毫秒）。调小会增加 CPU 和 REST 频率，一般不需要改 |
| `paper_trading` | `false` | `true` = 走完整决策链但不向交易所发单，内存持仓会更新 |
| `hedge_failed_legs` | `true` | 启动时发现遗留裸腿（上次执行失败留下），是否自动补对冲 |

---

## 5. sizing（容量校验）

不再定仓。这里只校验「按配置的每格数量开得起吗」。

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_concurrent_pairs` | `1` | 同时持仓的最大 pair 数（活跃槽位 = 持仓 + pending 开仓）。加大前确认保证金足够 |
| `leverage_multiplier` | `2` | 保证金校验用的杠杆倍数。两所的杠杆相同时用这个全局值；不同时在 venue 配置里单独写 |
| `depth_pct` | `50` | 单笔下单量不得超过一档量的这个比例。50 = 最多用 L1 数量的一半 |
| `refresh_balance_secs` | `1` | 账户余额和交易所持仓刷新间隔（秒）。页面「交易所持仓」跟这个走 |
| `margin_utilization_pct` | `90` | 可用余额用到多少比例再停开。90 = 留 10% 缓冲 |
| `fallback_available_usdc` | `500` | SoDEX 余额接口返回空时的回退值 |

---

## 6. live_test

| 字段 | 默认 | 说明 |
|---|---|---|
| `dex_test_mode` | `false` | 单所小额验证模式，`true` 时下单量被夹到 `max_qty` |
| `max_qty` | `0.001` | `dex_test_mode` 下的单笔最大量（币本位）。正常套利时 `dex_test_mode: false`，这个字段不生效 |
| `journal_path` | `data/executions.sqlite` | 执行日志 SQLite 路径。平仓行 `pnl_usdc` 是两所已实现盈亏之和，见 [本系统套利流程.md](本系统套利流程.md) §6 |

---

## 7. http

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉则不起 HTTP 服务 |
| `bind` | `127.0.0.1:8090` | 监听地址。`auth_token` 为空时程序自动回落到 `127.0.0.1`，即使写了公网地址 |
| `auth_token` | `""` | Bearer token。空 = 不鉴权但只本机可访问；设值后对外暴露。`/api/positions` 含余额和持仓，不要无 token 公网开放 |
| `web_root` | `web/dist` | Vue 构建产物。改前端后需 `cd web && npm run build` |

---

## 8. scan

`execution.enabled: false` 时才用扫描环；执行模式下 `scan` 字段不生效。

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_spread_pct` | `0.1` | 毛价差低于此值不上报（0.1 = 0.1%） |
| `watch_top` | `20` | 保留并显示毛价差最高的 Top N 币 |
| `cross_use_natural` | `true` | 跨 DEX（Lighter ↔ SoDEX）时用 `residual = raw − nat` 上榜，而非纯 `raw` |
| `log_interval_secs` | `30` | 同一币仍在榜时的最小重新打印间隔（新上榜/下榜立即打） |

---

## 9. grid（持续性）

阈值已下沉到 `pairs.defaults` / `enabled` / `overrides`。这里只留持续性。

| 字段 | 默认 | 说明 |
|---|---|---|
| `persistence_mode` | `bucket` | `bucket` = 参考宽松/严格秒桶；`window` = 原 `persistence_ms` 连续窗口 |
| `spread_persistence_seconds` | `1` | 秒桶要连续满足的秒数。对齐参考：`<= 1` 达标即放行 |
| `strict_persistence_check` | `true` | `true` = 严格（窗口内每笔达标）；`false` = 宽松（每秒至少一次） |
| `persistence_ms` | `1000` | 仅 `window` 模式：信号首次出现后连续满这么多毫秒 |

**格子判据（D1-c / 方案 A）**：开仓、减格都看开仓视角毛价差（页面「毛价差」）vs T1/T0 滞后。格数够就发，不要求往返净利为正。无往返止盈闸、无止损。盈利性靠 T1/step 相对该所对往返费。平仓视角只记 journal、验一档厚度。旧方案 B 见已废弃的 `docs/平仓判据备选方案B.md`。

---

## 10. order（下单）

| 字段 | 默认 | 说明 |
|---|---|---|
| `style` | `limit_then_market` | 下单风格。`limit_then_market` = 费率高的所先挂限价，成交后对手所市价对冲；`market_taker` = 两腿同时市价；`limit_maker` = 两腿限价 |
| `limit_timeout_ms` | `2000` | 第一腿限价单最多挂多久（毫秒），超时则撤单重试 |
| `maker_inside_ticks` | `1` | 限价单往点差内侧挪几个 tick。0 = 贴盘口排队（2 秒内成交概率极低）；1 = 内侧一档（对齐参考） |
| `limit_retry_count` | `3` | 第一腿最多重试几轮（每轮用最新盘口重算价格，部分成交累积） |

---

## 11. cost（成本参数）

| 字段 | 默认 | 说明 |
|---|---|---|
| `default_slip_pct` | `0.01` | 决策不预扣滑点；成交后用实际成交价扣，超过这个值记 overrun 日志 |
| `max_slippage_pct` | `0.1` | 市价单滑点保护上限（%）。以**决策信号价**（不是下单时盘口）为基准，超出则交易所直接拒单 |
| `emergency_slippage_multiplier` | `50` | 平仓/紧急平仓/补对冲时把 `max_slippage_pct` 放大这么多倍。对齐参考「紧急平仓 50× 滑点」——平不掉的风险远大于穿档成本 |

---

## 12. history（天然价差）

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉则跨 DEX 开仓不扣天然基差，`residual = net` |
| `db_path` | `data/spreads.sqlite` | 历史快照 SQLite 路径 |
| `window_hours` | `24` | 取多少小时内的样本算中位数天然价差 |
| `min_points` | `10` | 快照点数低于这个值时不开仓（数据不够可信） |
| `refresh_interval_secs` | `1800` | 多久重算一次中位数（秒）。30 分钟 = 跟上市场结构变化但不过于频繁 |

## 13. risk（风控）

### 盘口质量

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_book_qty.BTC` | `0.001` | BTC 一档最小厚度（币本位）。开仓时两腿都要满足 |
| `min_book_qty.ETH` | `0.01` | ETH 一档最小厚度 |
| `max_venue_spread_pct` | `0.05` | 单所自身买卖点差上限（%），不是跨所毛价差。超过记 `wide_book`，**加格和减格都不做**。对齐参考 `max_local_orderbook_spread_pct` |

### 价格稳定性

窗口内 `(max−min)/min×100` 超阈值则格子加格、减格都不做。超时/余额/费率清仓不走这道门。两个字段任一为 0 则关闭该检查。

| 字段 | 默认 | 说明 |
|---|---|---|
| `price_stability_window_secs` | `1` | 观察窗口（秒）。对齐参考 `price_stability_window_seconds` |
| `price_stability_threshold_pct` | `0.01` | 允许的最大波动（%）。超过说明近期有插针，挂单风险大。对齐参考同名字段 |

### Reduce-only 探针

交易所报 code=21740 时拉闸，每小时整点发探针验证是否恢复。

| 字段 | 默认 | 说明 |
|---|---|---|
| `reduce_only_probe_enabled` | `true` | 关掉则拉闸只能重启清除 |
| `reduce_only_probe_second` | `5` | 探针在每小时的第几秒触发（`HH:00:05` 起 60 秒窗口） |

### 资金费率

| 字段 | 默认 | 说明 |
|---|---|---|
| `funding_annual_threshold_pct` | `10` | 年化净支付超过此值（%/年）则拒绝开仓。持仓侧超过阈值后开始计时，达到持续性门限才平仓。0 = 关闭 |
| `funding_unfavorable_duration_minutes` | `60` | 费率不利**持续**多少分钟才触发强制平仓。防止瞬时读数抖动引起无意义的开平 |
| `funding_refresh_secs` | `60` | 费率刷新间隔（秒）。两个所都是小时结算，不需要高频拉 |

### 全局限额

这些限额**只拦开仓**，平仓不受影响。强制平仓类（超时、余额）拦的是 Hold 信号，会让现有仓位走平仓路径。

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_daily_opens` | `100` | 每日最大**开仓**次数（本地时间自然日）。0 = 不限 |
| `max_position_hours` | `168` | 持仓超过此小时数**强制全平**（7 天）。对冲仓不会爆仓，但资金费率和手续费在持续流血。0 = 不限 |

### 余额下限

默认全部关闭（0）的语义仍成立，但当前 `config/default.yaml` 已写成 warn=`50` / close=`20`（D1-c 删止损后的兜底）。参考项目的 warn=1000/close=500 是大账户量级，直接启用会让小额账户一启动就被清仓，**务必按实际账户规模配**。

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_balance_warn_usdc` | `50` | 低于此值停止该所**开仓**（仓位不动）。0 = 关闭 |
| `min_balance_close_usdc` | `20` | 低于此值**强制平掉该所全部仓位**。必须小于 warn。0 = 关闭 |

### 持仓名义敞口上限

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_single_token_notional_usdc` | `0` | 单币最大名义敞口（USDC，建仓名义）。BTC/ETH/小币同一口径可比。0 = 不限 |
| `max_total_notional_usdc` | `0` | 全部持仓名义之和上限（USDC）。0 = 不限 |

**为什么用名义而非币本位**：币本位（参考项目的 `max_single_token_position`）跨币种不可比——10 BTC 是天量，10 DOGE 是零头，而且「所有币数量之和」没有物理意义（不同量纲直接相加）。名义 USDC 一个数管所有币，配一次就能用。用**建仓名义**而非实时市值：盘口拿不到时限额判定仍然有效。

### 错误退避

nonce 冲突（code=21104）和限流（429/23000）按**所**退避，任一腿退避中则该 pair 停开仓，平仓不受影响。

| 字段 | 默认 | 说明 |
|---|---|---|
| `backoff_min_secs` | `120` | 首次错误后的退避时间（秒） |
| `backoff_max_secs` | `3600` | 退避上限（秒） |
| `backoff_multiplier` | `2` | 连续错误时退避时间 × 该倍数（指数退避） |
| `backoff_reset_secs` | `600` | 多久没有新错误就把阶梯清零。防止一次偶发错误把某所压到最长退避后再也回不来 |

## 14. 快速配置指南

**小额测试**（固定每格数量，单币）：

```yaml
execution:
  paper_trading: true   # 先 paper 验证
sizing:
  max_concurrent_pairs: 1
pairs:
  enabled:
    - symbol: BTC
      base_qty: "0.001"
```

**转正式运行**（多币，注意保证金）：

```yaml
execution:
  paper_trading: false
sizing:
  max_concurrent_pairs: 3
pairs:
  enabled:
    - symbol: BTC
      base_qty: "0.001"
    - symbol: ETH
      base_qty: "0.02"
risk:
  min_balance_warn_usdc: "500"
  min_balance_close_usdc: "200"
  max_single_token_notional_usdc: "300"
  max_total_notional_usdc: "800"
```

**只监控**（不发单，看价差分布）：

```yaml
system:
  monitor_only: true
execution:
  enabled: false
scan:
  enabled: true
  min_spread_pct: "0.05"
```
