# 实盘验证指南

小额验证各 DEX 账户/下单/撤单，通过后再接入主流程闭环。

## 1. 构建 exchange_sidecar（Go，无需 Python）

```bash
cd scripts/exchange_sidecar
go mod tidy
go build -o exchange_sidecar .    # Linux
go build -o exchange_sidecar.exe  # Windows
```

- **Lighter / Lighter RH**：`lighter-go` 签名 + REST（`scripts/exchange_sidecar/lighter.go`）
- **SoDEX**：官方 `sodex-go-sdk-public`（`scripts/exchange_sidecar/sodex.go`）
- **Entropy**：Hyperliquid HIP-3（dex=`io`），签名走 HL L1；`account_address` 为主账户，`private_key` 为已授权 API 钱包
- **EIP-712**：SoDEX 签名链 ID 为 `eip712_chain_id: 286623`（与 `chain_id: 623` 不同）

Rust 通过 `src/exchange/bridge.rs` 调用 sidecar（stdin JSON）。可选环境变量 `DEX_EXCHANGE_SIDECAR` 指定二进制路径。

## 2. live-test CLI

```bash
# 账户 / 余额 / 持仓 / 市场
cargo run --bin live-test -- account lighter
cargo run --bin live-test -- balance sodex
cargo run --bin live-test -- positions lighter_rh
cargo run --bin live-test -- markets entropy

# 市价（受 live_test.max_qty 上限，见下文 dex_test_mode）
cargo run --bin live-test -- market lighter BTC buy 0.001

# 限价 maker（post-only，远离盘口才会驻留）
cargo run --bin live-test -- limit lighter BTC sell 0.001 95000

# taker 限价（IOC aggressive_limit，价格要能穿越盘口）
cargo run --bin live-test -- aggressive entropy SNDK buy 0.007 1480

# 撤单
cargo run --bin live-test -- cancel lighter BTC <order_id>

# 平仓后读所方已实现盈亏（Entropy = closedPnl；Lighter = 成交 ask/bid_account_pnl）
cargo run --bin live-test -- fill-pnl entropy SNDK <order_id>
cargo run --bin live-test -- fill-pnl lighter BTC <order_id>

# 复盘 tape
cargo run --bin live-test -- recap
```

执行记录写入 `data/executions.sqlite`（`live_test.journal_path`）。

## 3. 接入主流程（闭环）

`config/default.yaml` 示例：

```yaml
system:
  monitor_only: false
execution:
  enabled: true
  paper_trading: false   # 走 exchange_sidecar 实盘
scan:
  enabled: false
sizing:
  max_concurrent_pairs: 1
  fallback_available_usdc: "100"  # bridge 余额失败时勿用；优先 sidecar account
pairs:
  enabled:
    - symbol: BTC
      base_qty: "0.001"
live_test:
  dex_test_mode: false   # 价差套利主流程：false，走 pairs.enabled 的每格数量
  max_qty: "0.001"       # 仅 dex_test_mode: true 或 live-test CLI 时使用
```

数量写在 `pairs.enabled[].base_qty`（每格币数），`sizing` 只校验保证金和一档深度，不再按名义定仓。

`live_test.dex_test_mode`：
- **`false`（默认）**：主流程 `dex-arbitr` 按配置的每格数量下单，不受 `max_qty` 截断。
- **`true`**：主流程实盘单笔仍 capped 在 `max_qty`，用于 DEX 联调（优先用 `live-test` CLI）。

流程：**监控 WS → 决策环 → 读 base_qty → check_capacity → HedgePlan → executor → PositionStore + journal**。

limit-then-market 实盘：

1. 第一腿 SoDEX/Lighter 限价经 **exchange_sidecar** 异步下单（不阻塞决策 tick）  
2. `pending` 监视：poll 成交、超时/价差消失撤单（**撤单前再 poll**，避免已成交仍不对冲）  
3. 成交后第二腿市价；日志关键字：`post first leg completed`、`spawn hedge second leg`、`hedge second leg executed`  
4. **`max_concurrent_pairs` 占槽后仍每 tick 处理 pending/hedging**，否则挂单监视会中断  
5. sidecar 默认 45s 超时，环境变量 `DEX_SIDECAR_TIMEOUT_SECS` 可调  

## 4. 前后端（验证通过后）

页面：`web/`（Vue 3 + Naive UI）。启用 HTTP 后由主进程提供 `web/dist` 与 API。改前端先 `cd web && npm run build`：

```yaml
http:
  enabled: true
  bind: "0.0.0.0:8090"   # 公网监听；防火墙需放行 8090/TCP
  web_root: web/dist
  auth_token: "your-secret"  # 留空则 /api 无鉴权（不推荐公网）
```

浏览器：`http://<公网IP>:8090/`。若配置了 `auth_token`，前端需在请求头带 `Authorization: Bearer <token>`。

| 路径 | 说明 |
|------|------|
| `GET /api/health` | 健康检查 |
| `GET /api/snapshot` | 价差表 + 持仓 + 统计（页面轮询） |
| `GET /api/pairs` | 价差表 |
| `GET /api/positions` | 持仓与余额 |
| `GET /api/executions` | 执行带 / 复盘（SQLite journal） |

## 5. 风险

- 先用 **live-test** 单所、单币、**≤ max_qty** 验证
- 部署前确认 `scripts/exchange_sidecar/exchange_sidecar` 已构建
- Lighter 撤单需有效 numeric `client_order_index`
- 异常时查 sidecar stderr / 交易所 API 返回

## 6. Linux 部署要点

```bash
sudo apt install -y golang-go   # Go ≥ 1.22
cd ~/dex-arbitr
git pull
cd scripts/exchange_sidecar && go build -o exchange_sidecar . && cd ../..
cd web && npm install && npm run build && cd ..
cargo build --release
export RUST_LOG=info
./target/release/dex-arbitr
# 停止：Ctrl+C。页面 http://127.0.0.1:8090/
```

无需 Python / pip。盯盘用前台，不要 `nohup` / systemd。
