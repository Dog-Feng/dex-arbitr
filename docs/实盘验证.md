# 实盘验证指南

小额验证各 DEX 账户/下单/撤单，通过后再接入主流程闭环。

## 1. 安装桥接依赖

```bash
pip install -r scripts/requirements-exchange.txt
cd scripts/sodex_bridge && go build -o sodex_bridge.exe .
```

- **Lighter**：`lighter-python` + 各所 `config/venues/*.yaml` 密钥
- **SoDEX**：`private_key` + `api_key_name`（`X-API-Key` 名称，不是地址）；交易走 `scripts/sodex_bridge`（官方 Go SDK，对齐 `internal/exchange/sodex.go`）
- **EIP-712**：签名链 ID 为 `eip712_chain_id: 286623`（与 `chain_id: 623` 不同）

桥接脚本：`scripts/exchange_bridge.py`（Rust 适配器在密钥就绪时自动调用）。

## 2. live-test CLI

```bash
# 账户 / 余额 / 持仓
cargo run --bin live-test -- account lighter
cargo run --bin live-test -- balance sodex
cargo run --bin live-test -- positions lighter_rh

# 市价（受 live_test.max_qty 上限，见下文 dex_test_mode）
cargo run --bin live-test -- market lighter BTC buy 0.001

# 限价 maker
cargo run --bin live-test -- limit lighter BTC sell 0.001 95000

# 撤单
cargo run --bin live-test -- cancel lighter BTC <order_id>

# 复盘 tape
cargo run --bin live-test -- recap
```

执行记录写入 `data/executions.sqlite`（`live_test.journal_path`）。

## 3. 接入主流程（闭环）

`config/default.yaml` 示例：

```yaml
system:
  monitor_only: false
execution:
  enabled: true
  paper_trading: false   # 走 exchange_bridge 实盘
scan:
  enabled: false
sizing:
  mode: fixed              # 初期：fixed；稳定后改 margin
  fixed_notional_usdc: "20"
  max_concurrent_pairs: 1
  min_notional_usdc: "20"
  max_notional_usdc: "50"
  fallback_available_usdc: "100"  # 余额 REST 失败时勿用；优先 bridge account
live_test:
  dex_test_mode: false   # 价差套利主流程：false，走 sizing 定仓
  max_qty: "0.001"       # 仅 dex_test_mode: true 或 live-test CLI 时使用
```

| 模式 | 配置 | 说明 |
|------|------|------|
| `fixed` | `fixed_notional_usdc: "20"` | 初期测试：每笔固定 20 USDC 名义 |
| `margin` | `leverage_multiplier` + min/max | 稳定后：保证金短板 × 杠杆 |

`live_test.dex_test_mode`：
- **`false`（默认）**：主流程 `dex-arbitr` 按 `sizing` 名义定仓下单，不受 `max_qty` 截断。
- **`true`**：主流程实盘单笔仍 capped 在 `max_qty`，用于在主进程里做 DEX 联调（一般不推荐，优先用 `live-test` CLI）。

流程：**监控 WS → 决策环 → resolve_qty（fixed 或 margin）→ HedgePlan → executor → PositionStore + journal**。

limit-then-market 实盘：第一腿限价挂出后由 `pending` 监视；成交/超时后第二腿市价（与参考项目一致）。

## 4. 前后端（验证通过后）

页面原型：`web/index.html`。启用 HTTP 后由主进程一并提供静态页与 API：

```yaml
http:
  enabled: true
  bind: "0.0.0.0:8090"   # 公网监听；防火墙需放行 8090/TCP
  web_root: web
  auth_token: "your-secret"  # 留空则 /api 无鉴权（不推荐公网）
```

浏览器：`http://<公网IP>:8090/`。若配置了 `auth_token`，前端需在请求头带 `Authorization: Bearer <token>`。

| 路径 | 说明 |
|------|------|
| `GET /api/health` | 健康检查 |
| `GET /api/snapshot` | 价差表 + 持仓 + 统计（页面轮询） |
| `GET /api/pairs` | 价差表 |
| `GET /api/positions` | 持仓与余额 |
| `GET /api/executions` | 执行带 / 复盘（SQLite journal） |

## 5. 风险

- 先用 **live-test** 单所、单币、**≤ max_qty** 验证
- SoDEX 需先构建 `sodex_bridge.exe`；异常时查 bridge stderr / Go SDK 返回
- Lighter 需本机 `lighter-python`；撤单需有效 `order_index`
