## 1. 做什么

在 **Lighter 主网**（USDC）、**Lighter Robinhood**（USDG）、**SoDEX**（vUSDC / `BTC-USD`）和 **Entropy**（Hyperliquid HIP-3，`dex=io`）的永续订单簿之间做价差对冲：一侧开多、一侧开空，锁住可成交价差。稳定币按 **1:1**（`BTC-USDC` ≡ `BTC-USDG` ≡ `BTC-USD`）。热路径不搬家、不兑币、不跨链。

Lighter 主网和 RH 共用一个适配器、两份 venue 配置。SoDEX 见 `src/exchange/sodex.rs`，Entropy 见 `src/exchange/entropy.rs`。扫描按 **所的两两组合** 比价（四所时 C(4,2)=6 条所对）。

当前 `config/default.yaml`：**`execution.enabled: false`、`scan.enabled: false`**，启动后走事件格子环（盘口回调触发决策）。要跑完整套利把 `execution.enabled` 打开：统一决策环（分段网格 + 固定每格数量 + limit-then-market）。`paper_trading: false` 且 `monitor_only: false` 时经 Go **`exchange_sidecar`** 发真实单。  
`scan.enabled: true` 且执行关闭：只扫毛价差 Top-N（对齐参考监控 V2），不下单。执行与扫描互斥。

| 阶段 | 状态 | 内容 |
|------|------|------|
| 扫描 | 可用 | 交集扫描、毛价差 Top-N（对齐参考 V2） |
| 决策/执行 | 可用 | 统一决策环、分段网格、固定每格数量、paper / live、journal |
| 监控页 | 可用 | HTTP API + Vue 页（`web/dist`，须用进程地址打开，默认 `127.0.0.1:8090`） |
| 实盘 | 可用 | sidecar 下单；资金费率是滤网，不是独立开仓路径 |

## 2. 架构与目录

单 crate、单进程。页面不直连交易所。新交易所只加适配器 + 配置，Controller 流程不变。

```
启动 main
  → 读 config/default.yaml + venues
  → Controller：bootstrap 建 channel；load_available_pairs 拉各所交集（不订 WS）
  → 有 HTTP：页面勾选交易对后点「启动套利」才 activate_pairs 并订阅
  → 无 HTTP：立刻按 yaml pairs.enabled 激活
  → execution.enabled: true
        WS 写内存 → 每 100ms 统一环：先平后开 → 格子 → 容量校验 → HedgePlan
        → paper：内存持仓；live：exchange_sidecar 下单 + journal
  → execution.enabled: false && scan.enabled: true
        WS 只写内存 → 每 50ms 毛价差 Top-N → 日志
  → 两者都 false（当前默认）
        每条盘口事件走格子 / nat / res
```

完整步骤见 [本系统套利流程.md](本系统套利流程.md)。

```
dex-arbitr/
├── config/default.yaml + venues/*.yaml
├── scripts/exchange_sidecar/        # Go 实盘（Lighter / SoDEX / Entropy）
├── web/                             # Vue 3 + Naive UI 源码；构建到 web/dist
├── web/参考项目.html                # 参考终端布局原型，不接本进程 API
├── docs/                            # 流程、对比、配置、部署
├── src/main.rs                      # 读配置、起 Controller
├── src/app/controller.rs            # 三分叉 + process_pair
├── src/domain/grid.rs               # 分段网格
├── src/exec/                        # 规划 / 先挂后吃
├── src/exchange/                    # Lighter / SoDEX / Entropy / sidecar bridge
└── src/infra/api.rs                 # /api/* + 静态页
```

另：`src/bin/live_test.rs` — 单所小额验证 CLI（account / markets / fill-pnl / market / cancel / recap）。

正式密钥文件 `config/venues/*.yaml`（含 `entropy.yaml`）**不进 git**。没有正式文件时，`load_venue` 回退到对应 `*.example.yaml`（`cargo test` 依赖这个）。

## 3. 端到端流程

启动后按配置三分叉（优先级：`execution` > `scan` > 事件格子）。逐步说明见 [本系统套利流程.md](本系统套利流程.md)；与参考项目逐项对照见 [套利流程对比.md](套利流程对比.md)。

当前默认不是扫描：`execution` / `scan` 都关，走 §3.3 事件格子。打开 `execution.enabled` 才是 §3.2 统一执行环。

### 3.1 扫描发现（对齐参考监控 V2）

```
启动
  → 加载各所（密钥可空）
  → 各所 REST 拉永续（适配器 whitelist 传空，不过滤）
  → 标准化 pair_id，各所两两交集 = available（供页面勾选）
  → 点启动后才按 pairs.enabled 订阅 WS（Lighter 订 order_book，SoDEX 订 allBookTicker）
  → 回调只写 books[(所, pair_id)]，不算价差

每 50ms
  → 缺一侧 / 过期 / 非法 BBO → wait / stale / invalid
  → 两边齐：两个方向 raw = (卖 Bid1 − 买 Ask1) / 买 Ask1 × 100
  → raw ≥ 0.1% → 候选（同方向续 age）；跨 DEX 再看 residual
  → 控制台和文件打过线币的关键行
```

同协议（主网 ↔ RH）不扣费、不减 `nat`。  
SoDEX 与 Lighter **不同链**，扫描会采 raw 中位数当天然基差；`res = raw − max(nat,0) ≥ 0.1%` 才上榜。  
`nat` 写在 SQLite 快照表：库里已有则启动直接用，不必再等 10 个新点；之后每 `refresh_interval_secs` 用 24h 样本重算。首次、该方向还没有快照时记 `cross_hold`。  
决策只看卖一/买一，不走深、不预扣滑点、不下单。  
`opp=0` 且 `ready>0`：有盘口，只是没有币过门槛。

### 3.2 统一执行环（`execution.enabled: true`，P1.5）

对齐参考项目 **检测 → 决策 → 执行 → 仓位** 主路径。`paper_trading: true` 模拟成交；`paper_trading: false` 经 **exchange_sidecar** 实盘下单并写 journal。

```
启动（load_available_pairs 拉交集；activate_pairs 后才订 WS）
  → 周期性 refresh 各所余额/持仓（bridge account；失败时用 sizing.fallback_available_usdc）
  → 每 loop_interval_ms（默认 100ms）：
      ① 有持仓的 pair 优先（先平后开）
      ② 从 pairs.enabled 读固定每格数量 base_qty（未配置则跳过）
      ③ books_tradable / best_sequenced_spread
      ④ SQLite 采样 + nat；res = net − max(nat, 0)
      ⑤ GridEngine.decide → Open / Close / Hold
      ⑥ 仅 Open 做容量校验 check_capacity（保证金 + 一档深度）；Close 不拦
      ⑦ 槽位：open_count + pending ≤ max_concurrent_pairs
      ⑧ plan_hedge → limit-then-market 计划
      ⑨ monitor_only → 只记 skip_send
         paper_trading → 模拟成交 → HedgeExecutor → PositionStore
         live → bridge place/cancel → journal + PositionStore
```

**容量校验**（`src/app/sizing.rs` 的 `check_capacity`，不再定仓）：

数量来自配置的 `base_qty`，校验只回答「按这个量开得起吗」。不过则 skip `no_margin` / `thin_book`（面板「保证金不足」/「盘口过薄」），不改数量。

```
每所可用 = 该所稳定币余额 − 已占用保证金（reserved_margin_by_venue：qty × mid / 杠杆）
本笔占用 = base_qty × 加仓格数 × mid / 杠杆
保证金不够 → no_margin
一档数量 < base_qty / (depth_pct/100) → thin_book
```

配置页：勾选对的 `base_qty` 必须 > 0、≥ 该所对 `min_qty`、且符合 `qty_precision`，否则标红并拦保存/启动。有效 T1 / step / T1→T0 收敛低于该所对往返费时芯片变黄，**不硬拦**（启动后日志同样 warn）。

挂单监视（limit-then-market 实盘）：

1. 第一腿：taker 更高的所挂限价（maker），价格挂进**点差内侧** `order.maker_inside_ticks` 个 tick（买 `Ask1 − tick`、卖 `Bid1 + tick`，并保证不穿价）。贴自家 bid/ask 是队尾最被动的位置，配 2 秒超时几乎不可能成交。
2. post / hedge 在后台 task，不阻塞 100ms 决策环。执行 task 直接读**共享盘口**，不再用 spawn 时刻的快照。
3. **挂单监视排在所有盘口门槛之前**：单子挂出去就必须盯到撤单或成交，盘口变薄/过期都不能让监视停摆。
4. 开仓单价差跌破入场门槛、或超过 `limit_timeout_ms` → 置撤单标志。**平仓单不因价差变化撤**，要走完。
5. 每轮结束一定撤掉余量；撤单前后各查一次（撤单竞态窗口内成交仍对冲）。撤不掉 → 上报 `orphan_order` 并**停止重试**，写 journal 等人工处理。
6. 第一腿最多挂 `order.limit_retry_count` 轮，每轮用最新盘口重算价格，部分成交**累积**（baseline 逐轮滚动，不重复计数）。
7. 累计成交量低于第二腿最小下单量 → 反向平掉第一腿（`limit_min_qty_unmet`），不发注定被拒的单。
8. 第二腿数量 = 第一腿**累计实际成交量**；持仓回写也用实际成交量，不是计划量。
9. exchange_sidecar 超时分两档：写操作（place / cancel）**100s**，必须比 sidecar 内部的 90s 长；只读查询（account / order_status）**12s**。子进程带 `kill_on_drop`，超时会真的杀掉——否则一个「已放弃」的 place 仍可能把单发出去。

### 3.2.1 匹配对数量与交易范围（易混淆）

**进决策环的只有 `pairs.enabled` 里勾选且 `base_qty` 合法的交易对。** 启动仍加载各所交集全集（`GET /api/pairs/available`），但**不订阅**；点「启动套利」才 `activate_pairs`。不要和下面这些搞混：

| 字段 | 含义 | 不是 |
|------|------|------|
| `pairs.enabled` | 勾选的 base + 每格数量；未列入则只出现在配置表，不开仓 | — |
| `pairs.defaults` | 未单独指定时的 T1 / step / 格数 / 剥头皮 | 交易范围 |
| `sizing.depth_pct: 50` | 单笔不得超过 L1 数量的 **50%** | 50 个交易对 |
| `scan.analysis_interval_ms: 50` | 扫描环间隔 **50ms** | 50 个交易对 |
| `scan.watch_top: 20` | 仅 **scan 模式**日志/面板 Top-N | 执行模式下的监控数量 |

四所时同一 `BTC-USD-PERP` 最多出现在 **C(4,2)=6** 条所对里。`available` 条数可以很多；真正订阅的是 enabled ∩ 所选交易所。不合格的 `base_qty`（低于 min_qty 或精度不对）该所对 skip 并打 ERROR，不整体 bail。

Web 页（`http://127.0.0.1:8090`）：

| 显示 | 来源 | 含义 |
|------|------|------|
| 配置表「可用所对」 | `/api/pairs/available` | 各所交集，按 symbol 聚合 |
| 顶栏 **匹配对** | `stats.matched_pairs` | 已激活（订阅）的内部 `Pair` 条数 |
| 表格 **共 N 个** | `snap.pairs` | 按 `pair_id` 去重后的价差行 |

实盘建议：配置页只勾 BTC/ETH 等少数币，并填对的每格数量；跨 DEX 可只勾 `lighter` + `sodex` 减少组合。T1/step 低于该所对往返费时芯片发黄，应改阈值或加 override，不要硬开。

### 3.3 事件格子路径（`scan.enabled: false` 且 `execution.enabled: false`）

```
每次一侧盘口更新
  → skip wait / stale / thin_book / invalid / no_spread
  → net = raw − fee（不预扣滑点）
  → 每 5s 把 raw 写入 SQLite；nat 优先用库里快照
  → nat = 该方向 24h raw 中位数（首次满 10 点才落快照）
  → res = net − max(nat, 0)（只给监控看）
  → raw ≥ T1 且过持续性检查 → intent=open
  → 规划先挂后吃；monitor_only → skip_send
```

`skip_*` 是过滤，不是错过的开仓。开仓只看连续的 `intent=open`。

## 4. 价差公式

全部百分比。可成交价差，**不用中间价**。

```
raw  = (卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100

limit_then_market（当前默认）:
  fee  = 先挂所 maker + 后吃所 taker
  当前费率：RH 先挂 → 0.012 + 0.005 = 0.017%

market_taker:
  fee  = 两边 taker（0.005 + 0.035 = 0.040%）

net  = raw − fee
nat  = 该 pair + 该买卖方向、24h 内 raw 的中位数（SQLite 快照）
res  = net − max(nat, 0)
```

对齐参考 V3：决策只用卖一/买一，**不预扣滑点**。Ask1/Bid1 数量 < `base_qty` / `min_book_qty` → `thin_book`，不吃第二档。

滑点挪到成交之后，按实际成交价扣：

```
买入实滑点 = (成交价 − Ask1) / Ask1 × 100
卖出实滑点 = (Bid1 − 成交价) / Bid1 × 100
```

`cost.default_slip_pct: 0.01` 是成交后 overrun 阈值，不再当决策成本。`0` 表示不检查。

谁先挂：

1. taker 更高的所先挂限价  
2. taker 相同 → maker 更低的所先挂  
3. maker 也相同 → 两边都吃（fee = 两边 taker）

当前：RH taker 0.035% > 主网 0.005%，所以 **RH 先挂、主网后吃**。

开仓门槛：**`raw ≥ T1` 且过持续性检查**（默认秒桶，对齐参考），不扣手续费、不扣天然基差，也不按所对费率抬高 T1。毛价差刚过 0.03%、往返费 0.05% 时也会开——这是参考的取舍。净边 / 残差仍给监控页看，不进格子。

## 5. 格子与平仓条件

### 5.1 开仓：毛价差过 T1

对齐参考分段网格：空仓时 `raw ≥ T1` 且过持续性检查 → 价差落在第 n 格，目标就是 n 格（默认一次开满；`split_order_size>0` 则分批）。有仓后价差再涨到 Tn、或上次没吃满，只要 raw 还够就补到 n 格。

门槛就是该所对配置的 T1（`pairs.defaults` / `enabled` / `overrides`），**不按所对费率抬高**。T1 低于该所对往返费时启动日志打 warn，格子仍会开。

`net` / `res` 只给监控和扫描上榜用，不进 `GridEngine::decide`。

### 5.2 平仓：格子回落（方案 A / D1-c）

格子决定**减几格**（涨到 Tn 持 n 格；回落跌破 T(n−1) 减一格；跌破 T0 目标 0 格）。**加减格都看开仓视角 raw**（页面「毛价差」：卖所 Bid1 − 买所 Ask1）。格数够就发，**没有**往返止盈闸、**没有**往返止损。减格不要求往返净利为正。`round_trip_pct` 仍写入 journal / 面板，只作记录。

盈利性由 T1/step 相对该所对往返费自己扛。所对费率跨度约 5.7 倍，贵的所对不要把 step 开得比往返费还小。

平仓视角仍要算出来（往返记录、一档厚度）；拿不到 → Hold。一档撑不住**本笔**平仓量 → 丢掉格子/剥头皮平仓意图（`thin_book`）。超时/余额/费率清仓不走这条；格子减格仍走价格稳定性门（点差过宽同样拦加减格）。

可选剥头皮（`scalping_enabled`，默认关）：开仓视角格子按 T1/step **不封顶**，≥ `scalping_trigger_segment` 后该槽进入剥头皮。进入后仍可按毛价差补仓，但关掉滞后减仓；目标格 < 已持 **且** `建仓均毛价差 − 当前剩余毛价差 ≥ scalping_profit_threshold_pct` 才减到目标格。仓位归零才退出。`0.02%` 阈值只适合便宜所对（lighter↔entropy 往返约 0.016%）。

有仓时价差**锁定在持仓方向**，不再双向取优。

### 5.3 状态按「币 + 所对」隔离

三所两两组合下同一个 `pair_id` 有 C(3,2)=3 条 `Pair`。持仓、挂单、持续性计时全部按 `slot_key(pair_id, venue_a, venue_b)` 索引，不是 `pair_id`。

`max_segments` 默认 **3**，`grid_step` 默认 `0.03`。空仓时价差落在第 n 格目标即 n 格；有仓按格加减（涨到 Tn / 吃不满就补，回落减）。持续性默认对齐参考秒桶（`persistence_mode: bucket`）；`window` 仍可用原 `persistence_ms`。

## 6. 下单规划与执行（不发真实单）

### 6.1 规划（`exec/planner.rs`）

`limit_then_market` 计划：

1. 第一腿：taker 更高的所，限价（maker）  
2. 第一腿成交后：另一所市价  
3. 挂着期间 `res` 掉到 T1 以下，或超过 `limit_timeout_ms`（2000ms）→ 撤未成交单  
4. 已经成交（含撤单前成交）→ 另一边仍市价对冲（`late_hedge`），避免单边  

`order.style` 还可切 `market_taker`（双市价）或 `limit_maker`（双限价）。

### 6.2 执行（`exec/executor.rs`）

| 模式 | 行为 |
|------|------|
| `monitor_only: true` | 只到规划 + 日志（`skip_send`）。**不登记挂单状态**，所以不会占住决策环 |
| `paper_trading: true` | 走完整执行链，按当前 BBO 模拟两腿成交，更新内存持仓；不调交易所 |
| `paper_trading: false` | 经 `exchange_sidecar` 真实下单 |

第二腿失败时会 `emergency_close` 反向平掉第一腿（paper 同样模拟）；平不掉则记 `NAKED_FIRST_LEG`，
由 `execution.hedge_failed_legs` 在对手所补市价对冲。

`monitor_only` 与 `paper_trading` 都不会留下未清理的挂单状态——旧实现登记完 `pending` 就返回，
而 `pending` 只在执行回调里清理，于是第一个 open 信号就把整个决策环永久卡死。

## 6.5 可靠性守卫（C 类，对齐参考项目）

三道独立守卫，都挂在 `process_pair` 的决策路径上。执行顺序：**稳定性 → 人工介入 → reduce-only**。

点差过宽、价格稳定性对**格子加减格**都拦。费率/超时/余额清仓不走价格稳定性，仍会尝试离场。reduce-only 和错误退避只拦开不拦平——挡掉风控平仓会把敞口锁死在交易所里。格子/剥头皮减格在一档不够时丢掉意图（对齐参考）。只有「记账本身不可信」的情形才允许挡风控平仓。

### 6.5.1 价格稳定性（`app/stability.rs`）

判据是**窗口内极值波动** `(max − min) / min × 100`，买卖两腿各算一次，任一腿超阈值即失败。

用极值而不是标准差，是因为极值对单次插针敏感——而插针正是「先挂后吃」最怕的：挂单在插针价上成交，对冲腿却回不来。标准差会被大量正常样本稀释掉这根针。

| 状态 | 含义 | 放行 |
|------|------|------|
| `Collecting` | 窗口还没攒满 | 否 |
| `Volatile` | 超阈值，**已清空历史重新计时** | 否 |
| `Ok` | 平稳 | 是 |

`Volatile` 清空历史是刻意的惩罚（对齐参考 `reset_price_history`）：不清空的话，价格一稳下来就立刻放行，而此时窗口里还留着插针的尾巴。

采样 `record` **每轮无条件调用**，与是否真的要检查无关——历史断了窗口就永远攒不满。开仓 / 平仓各自独立记状态（key = `slot:action`），因为参考项目里这两条路径的日志和节流是分开的，混在一起会互相覆盖。格子加格、减格都要过这道门；超时/余额/费率清仓不走。

配置：`risk.price_stability_window_secs` / `risk.price_stability_threshold_pct`，任一为 `0` = 关闭。

### 6.5.2 人工介入状态机（`app/intervention.rs`）

用于「内存持仓已不可信」的情形。四个触发点：

| 触发 | 说明 |
|------|------|
| 单腿裸仓连续 3 次 | `SINGLE_LEG_STREAK_LIMIT`；两腿干净成交则连击归零 |
| orphan 挂单撤不掉（失败路径） | 残单状态不明，可能稍后成交 |
| orphan 挂单撤不掉（**成交成功但仍留单**） | 容易漏——成交了不等于没留下残单 |
| 紧急平仓失败 | 第一腿裸着且平不掉 |

**开仓和平仓都挡**（对齐参考 `should_block` 在两条路径上都查）。这与 reduce-only 相反，是刻意的：reduce-only 时仓位量是已知的，挡平仓等于锁死仓位；而介入态意味着记账本身不可信，按错的量去平会把敞口放大。

两条兜底防止永久锁死：

- **30 分钟自动解除**（`AUTO_RESUME`）
- **格数变化自动解除**——持仓量变了说明对账已经跟上

挂起瞬间打 `ERROR` 并写 journal；之后每轮只累加 `intervention` 跳过计数并降为 `debug`，避免刷屏。状态按 pair 隔离，一个币挂起不影响其他币。

### 6.5.3 reduce-only 熔断 + 整点探针（`app/reduce_only.rs`、`app/probe.rs`）

交易所进入 reduce-only（只许减仓）时开仓单必被拒。`is_reduce_only_error` 从下单失败文本里认出这类拒单并拉闸。

**只挡开仓，平仓始终放行**——挡掉平仓会把仓位锁死在交易所里，比开不了仓危险得多。

拉闸是纯内存状态，没有探针就只能靠重启清除，那意味着交易所早已恢复、机器人还在自我禁言。所以每小时 `HH:00:05` 起 60 秒窗口内发一轮最小量试单，能开就解闸：

- 一次 tick 只探一个 pair（探针要下真单，串行化避免 nonce 竞争）
- 优先探此前报错的那个所，它才是限制的来源
- `probed_hour` 保证每小时只探一次，不反复撞墙
- `monitor_only` / `paper_trading` / 有执行在飞时都不探

整点在任何**整小时偏移**的时区都是同一个瞬间，所以直接用 Unix 秒算，不引时区库。

配置：`risk.reduce_only_probe_enabled`（默认 `true`）、`risk.reduce_only_probe_second`（默认 `5`）。

## 8. 控制台字段

扫描模式：控制台和 `data/logs/` 打同一套代币行，不画面板。Windows 建议直接跑编译好的 exe。

### 8.0 扫描模式（`scan.enabled: true`）

```
pair=SOL-USD-PERP buy=lighter_rh sell=lighter raw=+0.1420% age=3.1s
pair=ETH-USD-PERP buy=sodex sell=lighter raw=+0.41% nat=+0.28% res=+0.13% age=2.0s
pair=ETH-USD-PERP buy=sodex sell=lighter gone
```

控制台和 `data/logs/` **同一行**。只打过线的币：上榜 / `raw` 或 `res` 变化 ≥ 0.05% / 仍在榜上每 `log_interval_secs`（默认 30 秒） / 下榜 `gone`。不刷 universe 快照，不画面板。

| 字段 | 含义 |
|------|------|
| `pair` / `buy` / `sell` | 币、买所、卖所 |
| `raw` / `nat` / `res` | 毛价差；跨 DEX 24h 中位数；residual（同协议家族不打 nat/res） |
| `age` | 该方向持续过线的时间 |
| `gone` | 该方向掉到门槛以下 |

`opp=0` 且 `ready>0` 正常，表示没有币达到 0.1%。拷回日志后可统计：`python scripts/analyze_scan_log.py dex-arbitr.log.YYYY-MM-DD`。

### 8.1 格子 / 统一执行环统计行（非 scan 模式）

```
decide  hold=2709  open=0  close=0  skip_send=0
filter  stale=4  thin=0  wide=0  spread=0  size=0  base=0  cancel_gone=0  cancel_to=0
```

| 字段 | 含义 |
|------|------|
| `hold` | 有完整价差，但不够开/平 |
| `open` / `close` | **决策层**：格子本轮给出开仓 / 平仓 |
| `skip_send` | **执行层**：已经做出计划，但 `monitor_only` 没发到交易所 |
| `stale` | 一侧盘口超过 `data_freshness_ms` |
| `thin` | 一档数量 < `min_book_qty` / `base_qty` / 两腿 `min_qty` 的较大者。空仓挡开仓；有仓时格子/剥头皮本笔平仓量不够也记这条并丢掉平仓意图 |
| `wide` | 单所自身点差 > `risk.max_venue_spread_pct`，该所报价不可信；格子加格和减格都不做 |
| `spread` | 算不出可成交方向（`no_spread`） |
| `size` | 容量校验不过（`no_margin` 保证金不够 / `thin_book` 一档太薄）。不再定仓，数量来自 `base_qty` |
| `base` | 拿不到第一腿 baseline 持仓，放弃本轮实盘执行（**不会**用 0 兜底） |
| `cancel_gone` | 挂单未成且价差不够，已置撤单标志 |
| `cancel_to` | 挂单超时，已置撤单标志 |
| `stability_collecting` | 稳定性窗口还没攒满（见 6.5.1）。刚启动时正常出现，攒满即消失 |
| `stability_volatile` | 窗口内极值波动超阈值，历史已清空重新计时 |
| `intervention` | 该 pair 处于人工介入态，开仓和平仓都挡（见 6.5.2） |
| `reduce_only` | 该 pair 被 reduce-only 拉闸，**只挡开仓**（见 6.5.3） |

`open`/`close`/`hold` 和 `skip_send` **不是互斥分桶**。同一轮：格子说开仓 → `open+1`，接着因监控不下单 → `skip_send+1`。所以监控时常见 `open` 与 `skip_send` 一起涨，价差行仍显示 `intent=open`，表示「识别到了，故意没发」。

`wait`、`invalid_bbo` 会计入 skip，不一定单独出现在这一行。

### 8.2 盘口行

`venue` `pair` `bid` `ask` `bq` `aq`（后两个是买一/卖一数量）  
`pair` 是标准化 id（`BTC-USD-PERP`），不是所方原始名。

### 8.3 价差行

第一行：`pair` `buy` `sell` `intent` `pts`  
第二行：`raw` `slip` `net` `nat` `res`

| 字段 | 含义 |
|------|------|
| `pair` | `BTC-USD-PERP` |
| `buy` / `sell` | 本轮买所 / 卖所 |
| `raw` | 可成交毛价差 % |
| `slip` | 决策为 0；成交后才按实际成交价填 |
| `net` | `raw − fee`（**未减** nat） |
| `nat` | 快照 / 24h raw 中位数；无快照显示 `--` |
| `res` | 决策用净边。无 nat 快照且空仓为 `+0` |
| `pts` | 有 nat 时是窗口样本数；否则 `已有/10`。**不是点位** |
| `intent` | `hold` / `open` / `close` / `scalp` / `scalp_tp` / `limit` / `skip` |

`intent=skip` 时看 `note`：`stale`、`thin_book`、`invalid_bbo`、`no_spread`、`wait`。

## 10. SQLite 与天然价差

两张表：

- `spread_samples`：`ts, pair_id, buy, sell, raw_pct, net_pct`（每 5 秒一条 raw）
- `natural_spreads`：该方向最新中位数快照（`value, points, updated_ts`）

**天然价差 `nat`** = 该 `pair_id + buy + sell` 在 24h 窗口内 **raw** 的中位数。首次至少 10 个点才写入快照。

启动：库存在且快照表有行 → **立刻用**，不用再等 10 个新点。旧库只有样本、没有快照表时，打开时按窗口回填。之后每 `refresh_interval_secs`（默认 1800 秒 / 30 分钟）用当前窗口重算并覆盖快照。窗口暂时不够 10 点时**保留旧快照**。

扫描跨 DEX 和格子路径都读写这个库。清空：停进程后删 `data/spreads.sqlite`。

## 12. 怎么判断「识别对了」

**扫描模式：** 看过线行的 `raw` / `nat` / `res` / `age`，以及 `gone`。长时间没有任何代币行，表示价差经常不到门槛，不是没扫。

**格子 / 执行环：** 看 `raw` / `net` / `nat` / `res` / `pts` / `intent`。开仓看毛价差是否过 T1 并过持续性检查。paper 且非 `monitor_only` 会出现 `filled_open` / `filled_close`。

确认稳定后再接线 REST 签名下单。不要当实盘。
