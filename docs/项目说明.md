# dex-arbitr 项目说明

版本：与仓库代码同步（2026-08-24）  
阶段：**P1 监控 + P1.5 决策/定仓/执行 + 实盘闭环**。默认 `monitor_only: true` 扫描发现毛价差；`execution.enabled: true` 走统一决策环（格子 + 定仓 + limit-then-market）。`paper_trading: false` 时经 Go **`exchange_sidecar`** 向 Lighter / SoDEX 发真实单。小额验证见 [实盘验证.md](实盘验证.md)。扫描说明见 [价差扫描与发现.md](价差扫描与发现.md)。

安装与启动见 [部署文档.md](部署文档.md)。与参考 Python 项目的差异见 [套利流程对比.md](套利流程对比.md)。早期规划稿见 [开发设计文档.md](开发设计文档.md)（部分目录与公式已过时，**以本文和代码为准**）。

## 1. 做什么

在 **Lighter 主网**（USDC）、**Lighter Robinhood**（USDG）和 **SoDEX**（vUSDC / `BTC-USD`）的永续订单簿之间做价差对冲：一侧开多、一侧开空，锁住可成交价差。稳定币按 **1:1**（`BTC-USDC` ≡ `BTC-USDG` ≡ `BTC-USD`）。热路径不搬家、不兑币、不跨链。

Lighter 主网和 RH 共用一个适配器、两份 venue 配置。SoDEX 是另一套 REST/WS，见 `src/exchange/sodex.rs`。扫描按 **所的两两组合** 比价（C(3,2)=3 条所对）。

默认 **`scan.enabled: true`**：白名单可空，订阅各所两两交集，按参考监控 V2 用毛价差 ≥ 0.1% 发现机会（见 [价差扫描与发现.md](价差扫描与发现.md)）。  
**`execution.enabled: true`**：走统一决策环（对齐参考项目分段网格 + limit-then-market），含定仓、槽位、paper 持仓；与 scan 互斥，开启后不再跑纯扫描环。  
格子事件路径（`scan.enabled: false` 且 `execution.enabled: false`）仍保留，用于单币调试。

| 阶段 | 状态 | 内容 |
|------|------|------|
| P1 | **进行中** | 交集扫描、毛价差 Top-N（对齐参考 V2） |
| P1.5 | **进行中** | 统一决策环、定仓、HedgePlan、paper / live 执行、持仓/槽位、执行 journal |
| P2 | **部分** | HTTP API + `web/index.html` 监控页（`http.enabled: true`） |
| P3 | 部分 | SoDEX / Lighter 实盘 bridge；资金费率独立路径未做 |

## 2. 架构与目录

单 crate、单进程。页面不直连交易所。新交易所只加适配器 + 配置，Controller 流程不变。

```
启动 main
  → 读 config/default.yaml + venues
  → Controller：拉市场、匹配、订 WS
  → execution.enabled: true（P1.5）
        WS 写内存 → 每 100ms 统一环：先平后开 → 定仓 → 格子 → HedgePlan
        → paper：内存持仓；live：exchange_sidecar 下单 + journal
  → execution.enabled: false && scan.enabled: true（默认 P1）
        WS 只写内存 → 每 50ms 毛价差 Top-N → 日志
  → 两者都 false
        每条盘口事件走格子 / nat / res（事件驱动，无定时环）
```

## 3. 端到端流程

启动后按配置三分叉（优先级：`execution` > `scan` > 事件格子）。

### 3.1 默认：扫描发现（对齐参考监控 V2）

```
启动
  → 加载各所（密钥可空）
  → 各所 REST 拉永续；whitelist 空则不过滤
  → 标准化 pair_id，各所两两交集 = universe
  → 各所一条 WS（Lighter 订 order_book，SoDEX 订 allBookTicker）
  → 回调只写 books[(所, pair_id)]，不算价差

每 50ms
  → 缺一侧 / 过期 / 非法 BBO → wait / stale / invalid
  → 两边齐：两个方向 raw = (卖 Bid1 − 买 Ask1) / 买 Ask1 × 100
  → raw ≥ 0.1% → 候选（同方向续 age）；跨 DEX 再看 residual
  → 控制台和文件打过线币的关键行
```

同协议（主网 ↔ RH）不扣费、不减 `nat`。  
SoDEX 与 Lighter **不同链**，扫描会采 raw 中位数当天然基差；`res = raw − max(nat,0) ≥ 0.1%` 才上榜。  
`nat` 写在 SQLite 快照表：库里已有则启动直接用，不必再等 10 个新点；之后每 `refresh_interval_secs` 用 24h 样本重算。首次、该方向还没有快照时记 `cross_hold`。  
决策只看卖一/买一，不走深、不预扣滑点、不下单。  
`opp=0` 且 `ready>0`：有盘口，只是没有币过门槛。

### 3.2 统一执行环（`execution.enabled: true`，P1.5）

对齐参考项目 **检测 → 决策 → 执行 → 仓位** 主路径。`paper_trading: true` 模拟成交；`paper_trading: false` 经 **exchange_sidecar** 实盘下单并写 journal。

```
启动（同扫描：拉 market、订 WS）
  → 周期性 refresh 各所余额/持仓（bridge account；失败时用 sizing.fallback_available_usdc）
  → 每 loop_interval_ms（默认 100ms）：
      ① 有持仓的 pair 优先（先平后开）
      ② 定仓 resolve_qty（fixed 或 margin）→ 覆盖 grid.base_qty
      ③ books_tradable / stable_ok / best_sequenced_spread
      ④ SQLite 采样 + nat；res = net − max(nat, 0)
      ⑤ GridEngine.decide → Open / Close / Hold
      ⑥ 槽位：open_count + pending ≤ max_concurrent_pairs
      ⑦ plan_hedge → limit-then-market 计划
      ⑧ monitor_only → 只记 skip_send
         paper_trading → 模拟成交 → HedgeExecutor → PositionStore
         live → bridge place/cancel → journal + PositionStore
```

**定仓模式**（`sizing.mode`，`src/app/sizing.rs`）：

| 模式 | 配置 | 行为 |
|------|------|------|
| `fixed` | `fixed_notional_usdc: "20"` | 每笔固定 USDC 名义（初期小额测试） |
| `margin` | `leverage_multiplier` + min/max | 保证金短板 × 杠杆 × 使用率（稳定后） |

**margin 模式公式**：

```
每所可用 = 该所稳定币余额 − 已有持仓占用保证金
可开名义_buy  = 可用_buy × leverage_buy × margin_utilization_pct
可开名义_sell = 可用_sell × leverage_sell × margin_utilization_pct
本笔 pair_cap = min(买所可开名义, 卖所可开名义) — **以保证金更少的一腿为准**；
A 200 / B 100 保证金、均 2× 时，名义上限按 B 的 100（→200 USDC 名义），**A/B 下同一 qty**，不会出现 A 150、B 100 两档。

全局 per_pair = min(各所余额) × leverage / max_concurrent_pairs
名义 USDC = min(pair_cap, 全局 per_pair, max_notional)，再 clamp min_notional
深度上限 = min(买所 Ask1, 卖所 Bid1) × depth_pct / 100 × mid
qty = 名义 / mid，精度取两腿 min(qty_precision)，min_qty 取 max
```

例：可用 200 USDC、2× 杠杆、`max_concurrent_pairs: 1` → 名义 **400 USDC**（在 min=20、max=500 内不被截断）。

挂单监视（limit-then-market 实盘）：

1. 第一腿：taker 更高的所挂限价（maker）；**post/hedge 在后台 task**，不阻塞 100ms 决策环  
2. **`pending` / `hedging` 的 pair 每 tick 必跑**（不受 `max_concurrent_pairs` 占槽影响），否则挂单监视会停  
3. paper：价差仍有效且等待 ≥ 100ms → 视为成交，执行第二腿  
4. 价差跌破 T1 或超过 `limit_timeout_ms` → **撤单前先 poll**；已成交或撤单后成交 → 仍对冲第二腿  
5. 已成交 → 第二腿市价（`late_hedge`），避免单边  
6. exchange_sidecar 单次调用默认 **45s** 超时（`DEX_SIDECAR_TIMEOUT_SECS` 可改）

### 3.2.1 匹配对数量与白名单（易混淆）

**控制「监控哪些币」的只有 `pairs.whitelist`**（base 符号，如 `BTC`、`ETH`）。**不是**下面这些：

| 字段 | 含义 | 不是 |
|------|------|------|
| `pairs.whitelist` | 各所 `list_perps` 后只保留这些 base；`[]` = 不过滤 | — |
| `sizing.depth_pct: 50` | 定仓时用 L1 深度的 **50%** | 50 个交易对 |
| `scan.analysis_interval_ms: 50` | 扫描环间隔 **50ms** | 50 个交易对 |
| `scan.watch_top: 20` | 仅 **scan 模式**日志/面板 Top-N | 执行模式下的监控数量 |

三所 `[lighter, lighter_rh, sodex]` 时，程序对 **C(3,2)=3** 种 venue 组合各做一遍交集（`match_all_pairs`）。  
因此 **「匹配对条数」≈ 唯一币种 × 最多 3**，不是唯一币种个数。例：`whitelist: []` 时日志常见 `matched perp pairs n=136`（约 36 + 74 + 26）。

Web 页（`http://8090`）：

| 显示 | 来源 | 含义 |
|------|------|------|
| 顶栏 **匹配对** | `stats.matched_pairs` | 内部 `Pair` 条数（含三所组合，可 >100） |
| 表格 **共 N 个** | `snap.pairs` | 按 `pair_id` 去重后的价差行（仍可能很多） |

实盘建议：`pairs.whitelist: [BTC, ETH, …]` 只盯少数 base；跨 DEX 套利可只开 `lighter` + `sodex` 两所以减少组合数。

### 3.3 事件格子路径（`scan.enabled: false` 且 `execution.enabled: false`）

```
每次一侧盘口更新
  → skip wait / stale / thin_book / invalid / no_spread
  → net = raw − fee（不预扣滑点）
  → 每 5s 把 raw 写入 SQLite；nat 优先用库里快照
  → nat = 该方向 24h raw 中位数（首次满 10 点才落快照）
  → res = net − max(nat, 0)；没有快照且空仓则 res=0
  → res ≥ T1 且站稳 1s → intent=open
  → 规划先挂后吃；monitor_only → skip_send
```

`skip_*` 是过滤，不是错过的开仓。开仓只看连续的 `intent=open`。

## 4. 价差公式

全部百分比。可成交价差，**不用中间价**。

```
raw  = (卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100

limit_then_market（当前默认）:
  fee  = 先挂所 maker + 后吃所 taker
  当前费率：RH 先挂 → 0.012 + 0.005 = 0.017%

market_taker:
  fee  = 两边 taker（0.005 + 0.035 = 0.040%）

net  = raw − fee
nat  = 该 pair + 该买卖方向、24h 内 raw 的中位数（SQLite 快照）
res  = net − max(nat, 0)
```

对齐参考 V3：决策只用卖一/买一，**不预扣滑点**。Ask1/Bid1 数量 < `base_qty` / `min_book_qty` → `thin_book`，不吃第二档。

滑点挪到成交之后，按实际成交价扣：

```
买入实滑点 = (成交价 − Ask1) / Ask1 × 100
卖出实滑点 = (Bid1 − 成交价) / Bid1 × 100
```

`cost.default_slip_pct: 0.01` 是成交后 overrun 阈值，不再当决策成本。`0` 表示不检查。

谁先挂：

1. taker 更高的所先挂限价  
2. taker 相同 → maker 更低的所先挂  
3. maker 也相同 → 两边都吃（fee = 两边 taker）

当前：RH taker 0.035% > 主网 0.005%，所以 **RH 先挂、主网后吃**。

开仓门槛：**`res ≥ 0.03%`（T1）且持续 1 秒**，不是看 `raw`。历史样本里 `res` 远小于 T1 时，一直 `hold` 是符合规则的。

## 5. 格子

```
T1 = initial_spread_threshold          # 0.03%
T0 = T1 × 0.4                          # 0.012%
Tn = T1 + (n − 1) × grid_step          # max_segments=1 时用不到
```

空仓：`res ≥ T1` 且持续 `persistence_ms` → `Open { qty: base_qty, buy, sell, grid: 1 }`  
有仓：`res < T0` 或买卖方向反了 → 持续同样时间后 `Close`  
同一交易所对禁止反向双开；反向信号走平仓。

`max_segments` 与 `grid_step` 已写入配置，决策里目前按 **一格** 处理。FIFO 多格未接。`positions` 只在内存，P1 扫描路径 **不会写入**；P1.5 paper 执行环会写入。事件格子路径在 `monitor_only` 下仍不写。

## 6. 下单规划与执行（不发真实单）

### 6.1 规划（`exec/planner.rs`）

`limit_then_market` 计划：

1. 第一腿：taker 更高的所，限价（maker）  
2. 第一腿成交后：另一所市价  
3. 挂着期间 `res` 掉到 T1 以下，或超过 `limit_timeout_ms`（2000ms）→ 撤未成交单  
4. 已经成交（含撤单前成交）→ 另一边仍市价对冲（`late_hedge`），避免单边  

`order.style` 还可切 `market_taker`（双市价）或 `limit_maker`（双限价）。

### 6.2 执行（`exec/executor.rs`）

| 模式 | 行为 |
|------|------|
| `monitor_only: true` | 只到规划 + 日志，`skip_send` |
| `paper_trading: true` | 按当前 BBO 模拟两腿成交，更新内存持仓；不调交易所 |
| `paper_trading: false` | 调用 `ExchangePort::place()`——**当前 stub，直接报错** |

第二腿失败时会尝试 `emergency_close` 反向平掉第一腿（paper 同样模拟）。  
**真实 REST 签名下单、撤单、订单状态轮询均未实现**，有意留到后续 PR。

| `grid.grid_step` | `0.03` | 多格间隔；一格时不影响决策 |
| `grid.max_segments` | `1` | 最大格数。决策实际按 1 格 |
| `grid.persistence_ms` | `1000` | 开/平信号需连续站稳的时间 |
| `grid.base_qty.BTC` | `0.001` | 定仓失败时的回退 qty；已知大币可手工覆盖 |
| `order.style` | `limit_then_market` | 见第 6 节 |
| `order.limit_timeout_ms` | `2000` | 第一腿限价最长等待 |
| `cost.default_slip_pct` | `0.01` | 成交后实际滑点 overrun 阈值（%）。决策不预扣 |
| `history.enabled` | `true` | 打开 SQLite：样本 + `nat` 快照 |
| `history.db_path` | `data/spreads.sqlite` | 相对工作目录。重启直接读快照 |
| `history.sample_interval_secs` | `5` | 同一方向最少间隔 |
| `history.window_hours` | `24` | 中位数窗口 |
| `history.min_points` | `10` | 首次落快照的最少样本；已有快照不受此限 |
| `history.refresh_interval_secs` | `1800` | 有快照后隔这么久用窗口样本重算（30 分钟） |
| `history.max_age_secs` | `200` | 兼容旧配置，读路径不再用它过期快照 |
| `risk.min_book_qty.BTC` | `0.001` | 两侧卖一/买一数量下限（与定仓 probe_qty 取大） |

百分比在 yaml 里写成 `"0.03"` 表示 **0.03%**，不是 3%。

## 8. 控制台字段

扫描模式：控制台和 `data/logs/` 打同一套代币行，不画面板。Windows 建议直接跑编译好的 exe。

### 8.0 扫描模式（默认）

```
pair=SOL-USD-PERP buy=lighter_rh sell=lighter raw=+0.1420% age=3.1s
pair=ETH-USD-PERP buy=sodex sell=lighter raw=+0.41% nat=+0.28% res=+0.13% age=2.0s
pair=ETH-USD-PERP buy=sodex sell=lighter gone
```

控制台和 `data/logs/` **同一行**。只打过线的币：上榜 / `raw` 或 `res` 变化 ≥ 0.05% / 仍在榜上每 `log_interval_secs`（默认 30 秒） / 下榜 `gone`。不刷 universe 快照，不画面板。

| 字段 | 含义 |
|------|------|
| `pair` / `buy` / `sell` | 币、买所、卖所 |
| `raw` / `nat` / `res` | 毛价差；跨 DEX 24h 中位数；residual（同协议家族不打 nat/res） |
| `age` | 该方向持续过线的时间 |
| `gone` | 该方向掉到门槛以下 |

`opp=0` 且 `ready>0` 正常，表示没有币达到 0.1%。拷回日志后可统计：`python scripts/analyze_scan_log.py dex-arbitr.log.YYYY-MM-DD`。

### 8.1 格子 / 统一执行环统计行（非 scan 模式）

```
decide  hold=2709  open=0  close=0  skip_send=0
filter  stale=4  thin=0  spread=0  cancel_gone=0  cancel_to=0  late_hedge=0
```

| 字段 | 含义 |
|------|------|
| `hold` | 有完整价差，但不够开/平 |
| `open` / `close` | **决策层**：格子本轮给出开仓 / 平仓。监控模式也会加 |
| `skip_send` | **执行层**：已经做出计划，但 `monitor_only` 没发到交易所 |
| `stale` | 一侧盘口超过 3s |
| `thin` | 累计深度 < `min_book_qty` 与 `base_qty` 的较大者 |
| `spread` | 卖一/买一不够或算不出方向（`no_spread`） |
| `cancel_gone` | 挂单未成且价差不够，应撤 |
| `cancel_to` | 挂单超时应撤 |
| `late_hedge` | 第一腿已成交，另一边仍应对冲 |

`open`/`close`/`hold` 和 `skip_send` **不是互斥分桶**。同一轮：格子说开仓 → `open+1`，接着因监控不下单 → `skip_send+1`。所以监控时常见 `open` 与 `skip_send` 一起涨，价差行仍显示 `intent=open`，表示「识别到了，故意没发」。

`wait`、`invalid_bbo`、`depeg` 会计入 skip，不一定单独出现在这一行。

### 8.2 盘口行

`venue` `pair` `bid` `ask` `bq` `aq`（后两个是买一/卖一数量）  
`pair` 是标准化 id（`BTC-USD-PERP`），不是所方原始名。

### 8.3 价差行

第一行：`pair` `buy` `sell` `intent` `pts`  
第二行：`raw` `slip` `net` `nat` `res`

| 字段 | 含义 |
|------|------|
| `pair` | `BTC-USD-PERP` |
| `buy` / `sell` | 本轮买所 / 卖所 |
| `raw` | 可成交毛价差 % |
| `slip` | 决策为 0；成交后才按实际成交价填 |
| `net` | `raw − fee`（**未减** nat） |
| `nat` | 快照 / 24h raw 中位数；无快照显示 `--` |
| `res` | 决策用净边。无 nat 快照且空仓为 `+0` |
| `pts` | 有 nat 时是窗口样本数；否则 `已有/10`。**不是点位** |
| `intent` | `hold` / `open` / `close` / `limit` / `skip` |

`intent=skip` 时看 `note`：`stale`、`thin_book`、`invalid_bbo`、`no_spread`、`depeg`、`wait`。

## 9. 核心类型

```
VenueId          "lighter" | "lighter_rh"
VenueMarket      venue, raw_symbol, pair_id, base, market_index, qty_precision, min_qty
Pair             pair_id（如 BTC-USD-PERP）+ 两腿 VenueMarket
Bbo              bid/ask/qty + 多档 bids/asks + ts
NetSpread        buy, sell, raw_pct, fee_pct, slip_pct, net_pct
Position         pair_id, buy, sell, qty, grid（内存；paper 执行环会写入）
PositionStore    持仓 + pending 占槽，max_concurrent_pairs 限制
Intent           Open { qty, buy, sell, grid } | Close { qty, grid } | Hold
HedgePlan        数量、买卖所、first/second 腿（style + is_buy）
HedgeExecutor    paper / live 框架；live 未接线
LimitWatch       StillWait | CancelSpreadGone | CancelTimeout | FilledHedgeNow
ExecResult       first/second 腿模拟或真实成交摘要
```

匹配规则：只取永续；`USDC` / `USDG` / `USDT` / `USD` / SoDEX `vUSDC` 都视为 USD；`pair_id = {BASE}-USD-PERP`；任意两所同一 `pair_id` 各成一条监控腿。下单仍用所方 `raw_symbol` 和 `market_index`。

## 10. SQLite 与天然价差

两张表：

- `spread_samples`：`ts, pair_id, buy, sell, raw_pct, net_pct`（每 5 秒一条 raw）
- `natural_spreads`：该方向最新中位数快照（`value, points, updated_ts`）

**天然价差 `nat`** = 该 `pair_id + buy + sell` 在 24h 窗口内 **raw** 的中位数。首次至少 10 个点才写入快照。

启动：库存在且快照表有行 → **立刻用**，不用再等 10 个新点。旧库只有样本、没有快照表时，打开时按窗口回填。之后每 `refresh_interval_secs`（默认 1800 秒 / 30 分钟）用当前窗口重算并覆盖快照。窗口暂时不够 10 点时**保留旧快照**。

扫描跨 DEX 和格子路径都读写这个库。清空：停进程后删 `data/spreads.sqlite`。

## 11. 已实现 / 未接线

| 已实现 | 未做（刻意留后） |
|--------|------------------|
| 三所两两扫描、过线币关键行（默认） | **真实** `place()` / `cancel()` / 订单状态轮询 |
| SoDEX 适配器 + 跨 DEX 扣 nat | REST 余额 / 持仓同步（`balances()` / `positions()` 现返回空） |
| L1 决策 + 成交后实滑点、先挂后吃规划 | 实盘发单（`paper_trading: false` 会调 stub 并报错） |

**原则：文档与默认配置均保持「先不实现实际下单」**；paper 只改进程内 `PositionStore`，与交易所无关。

## 12. 怎么判断「识别对了」

**扫描模式：** 看过线行的 `raw` / `nat` / `res` / `age`，以及 `gone`。长时间没有任何代币行，表示价差经常不到门槛，不是没扫。

**格子 / 执行环：** 看 `raw` / `net` / `nat` / `res` / `pts` / `intent`。连续 `open` 且 `res ≥ 0.03`。paper 模式下 `monitor_only: false` 会出现 `filled_open` / `filled_close` 行。

确认稳定后再接线 REST 签名下单。不要当实盘。
