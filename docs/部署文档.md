# dex-arbitr 部署文档

适用系统：**Windows 10/11**、**Linux（x86_64）**  
当前阶段：P1 **扫描发现** 或 P1.5 **统一决策环**（paper / 实盘）；小额实盘见 [实盘验证.md](实盘验证.md)。  
工作目录必须是仓库根目录，进程会读相对路径 `config/` 和 `data/`。  
当前实现、公式与字段见 [项目说明.md](项目说明.md)。流程对比见 [套利流程对比.md](套利流程对比.md)。

---

## 1. 你会得到什么

启动后连接配置里的所（默认 Lighter 主网、Lighter Robinhood、SoDEX、Entropy），**先加载各所两两交集全集，不订阅盘口**。配置页勾选交易对并点「启动套利」后，才按 `pairs.enabled` 订阅。控制台和文件只打每个过线币的一行：

`pair=... buy=... sell=... raw=... [nat= res=] age=...`

下榜为 `gone`。不上备用屏，避免刷屏。

密钥用于标识账户与实盘 bridge。`monitor_only: true` 或纯 scan 时**不会发单**。`execution.enabled: true` 且 `paper_trading: false` 时经 **`scripts/exchange_sidecar`** 下单（仅需 Go，见 [实盘验证.md](实盘验证.md)）。

`scan.enabled: false` 时才是旧面板（盘口 + `raw/slip/net/nat/res`）。

## 3. 安装 Rust

两边都用 [rustup](https://rustup.rs/)。

**Linux**

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
rustup default stable
```

**Windows**

1. 安装 [rustup-init.exe](https://rustup.rs/)。
2. 链接器二选一（本机若没有 Visual Studio，用 GNU）：

| 工具链 | 何时用 | 命令 |
|--------|--------|------|
| MSVC | 已装 VS Build Tools / Visual Studio | `rustup default stable-x86_64-pc-windows-msvc` |
| GNU | 未装 MSVC，使用 WinLibs / MinGW | `rustup toolchain install stable-x86_64-pc-windows-gnu` 后每次 `cargo +stable-x86_64-pc-windows-gnu ...` |

GNU 还要把 `mingw64\bin`（含 `gcc`、`ld`）加到 `PATH`。WinLibs 常见路径：

`%LOCALAPPDATA%\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin`

编译依赖走 rustls，**不需要**本机 OpenSSL。SQLite 用 `bundled`，**不需要**系统 libsqlite3。

检查：

```bash
rustc -V
cargo -V
```

## 4. 配置

### 4.1 目录

```
config/default.yaml                      # 策略；保持 monitor_only: true
config/venues/lighter.example.yaml       # 复制为 lighter.yaml 后填密钥
config/venues/lighter_robinhood.example.yaml
config/venues/sodex.example.yaml
config/venues/entropy.example.yaml
data/spreads.sqlite                      # 首次运行自动创建（已 gitignore）
```

本地密钥文件 `config/venues/*.yaml` **不要提交**。费率确认：

| | maker | taker |
|--|--|--|
| Lighter | 0.005% | 0.005% |
| RH | 0.012% | 0.035% |

先挂 RH 再吃主网，决策手续费 **0.017%**。两边都吃则是 **0.040%**。

决策只用卖一/买一，不预扣滑点。`cost.default_slip_pct` 是成交后实际滑点阈值。详见对比文档第 1 节。

### 4.2 `config/default.yaml`（常用项）

| 项 | 含义 | P1 建议 |
|----|------|---------|
| `system.monitor_only` | `true` 只监控 | **保持 true** |
| `scan.enabled` | 毛价差扫描 | **保持 true** |
| `scan.min_spread_pct` | 上榜门槛（%） | `0.1` |
| `pairs.enabled` | 监控/执行范围 | 勾选的 base + 每格 `base_qty`。空列表 = 只加载交集不交易 |
| `pairs.defaults` / `overrides` | STEP | `target_bp` / `max_segments`；窗口参数在 `grid` 段 |
| `history.*` | 天然价差 SQLite | 跨 DEX 扫描也用；重启读快照 |

费率按账户档位改 **venue 文件** 的 `fees.maker` / `fees.taker`，单位是百分比（`0.005` = 0.005%）。免费档写成 `"0"`。

### 4.3 交易所密钥

写在各自的 `config/venues/*.yaml`，**不要提交 git，不要发到聊天或截图**。

```yaml
id: lighter
rest: https://mainnet.zklighter.elliot.ai
ws: wss://mainnet.zklighter.elliot.ai/stream
chain_id: 304
quote: USDC
fees:
  maker: "0.005"
  taker: "0.005"
account_index: 123456
api_key_index: 0
api_key_private_key: "替换为你的私钥"
```

Robinhood 文件：`id: lighter_rh`，`rest` / `ws` / `chain_id` / `quote: USDG`，**必须用独立账户，不要复用主网密钥**。

SoDEX 模板：`config/venues/sodex.example.yaml`（`id: sodex`）。REST `https://mainnet-gw.sodex.dev/api/v1/perps`，WS `wss://mainnet-gw.sodex.dev/ws/perps`。密钥字段：`account_id` / `private_key` / `api_key_name`，也可用环境变量 `SODEX_ACCOUNT_ID`、`SODEX_PRIVATE_KEY`、`SODEX_API_KEY_NAME`。监控可不填。费率默认 Tier 0：maker 0.012% / taker 0.040%。SoDEX 与 Lighter 不同链，扫描用 24h 中位数扣天然价差。

Entropy 模板：`config/venues/entropy.example.yaml`（`id: entropy`）。Hyperliquid HIP-3（`dex=io`）。`account_address` 是主账户，`private_key` 是已授权 API 钱包，二者通常不是同一地址。

### 4.4 匹配对数量与 Web 页面

**进决策环的只有 `pairs.enabled`。** 启动加载交集全集供页面勾选，点启动才订阅。不要与下列配置混淆：

- `sizing.depth_pct: 50` → 单笔不得超过 L1 数量的 **50%**，不是 50 个对  
- `scan.watch_top: 20` → 仅 **scan.enabled: true** 时日志 Top-N；执行模式不受影响  

四所同时启用时，同一 `BTC-USD-PERP` 最多出现在 **C(4,2)=6 条** venue 组合里。`available` 条数可以很多；真正订阅的是勾选对 ∩ 所选交易所。

启用 `http.enabled: true` 后访问 `http://127.0.0.1:8090/`（不要直接打开 html 文件）：

| 页面元素 | 含义 |
|----------|------|
| 配置表「可用所对」 | 各所交集，按 symbol 聚合；芯片发黄 = 按往返费估的 Δ 低于该所对费（没有 live 点差中枢） |
| 顶栏「匹配对」 | 已激活（已订阅）的内部匹配条数 |
| 表格「共 N 个」 | 按 `pair_id` 去重的价差行数 |
| 配置页「交易所持仓」 | 一行一个已加载所：点差中枢、本次交易量、持仓汇总。两所点差中枢的平均折进 Δ |

要只盯少数币：配置页勾选 BTC/ETH 并填每格数量，或在 yaml 写 `pairs.enabled`。不合格的数量（低于 min_qty / 精度不对）启动时该对 skip，不整体退出。


`config/venues/*.yaml` 已在 `.gitignore` 中（保留 `*.example.yaml`），不要把填了私钥的文件提交上去。

## 5. 编译

一律在仓库根目录执行。

**Linux**

仓库不包含带密钥的 `config/venues/*.yaml`。`cargo test` 会自动用 `*.example.yaml` 里的费率。要跑监控，先复制并填密钥：

```bash
cp config/venues/lighter.example.yaml config/venues/lighter.yaml
cp config/venues/lighter_robinhood.example.yaml config/venues/lighter_robinhood.yaml
cp config/venues/sodex.example.yaml config/venues/sodex.yaml
cp config/venues/entropy.example.yaml config/venues/entropy.yaml
```

```bash
cd /path/to/dex-arbitr
cargo test
cargo build --release
```

产物：`target/release/dex-arbitr`

**Windows（MSVC）**

```powershell
cd D:\project\dex-arbitr
cargo test
cargo build --release
```

产物：`target\release\dex-arbitr.exe`

**Windows（GNU / 无 VS）**

```powershell
$mingw = "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin"
$env:Path = "$mingw;$env:USERPROFILE\.cargo\bin;" + $env:Path
cargo +stable-x86_64-pc-windows-gnu test
cargo +stable-x86_64-pc-windows-gnu build --release
```

开发调试可用 `cargo build`（`target/debug/`），启动更快、二进制更大。

## 6. 启动与停止

必须在仓库根目录启动，否则找不到 `config/default.yaml`。盯盘用前台进程，日志直接打在当前终端，**Ctrl+C** 停止。不要用 `nohup` / `&` / systemd 盯盘。

**Linux（前台）**

拉代码并重编后，在当前 shell 前台跑：

```bash
cd /path/to/dex-arbitr
git fetch origin
git checkout strategy/sliding-window
git pull --ff-only origin strategy/sliding-window

# sidecar（实盘下单）
cd scripts/exchange_sidecar
go build -o exchange_sidecar .
cd ../..

# 前端（进程只读 web/dist，不读 web/src；改 Vue 后必须重编）
cd web
npm install
npm run build
cd ..

cargo test
cargo build --release

export RUST_LOG=info
./target/release/dex-arbitr
# 停止：Ctrl+C
```

页面开 `http://127.0.0.1:8090/`（不要直接打开 html 或 `web/src`）。密钥在本机 `config/venues/*.yaml`，不进 git。HTTP 开着时 yaml 只是页面默认；点「启动套利」后策略跟页面走。执行带平仓列是 **盈亏 USDC**（所方已实现金额）；若仍显示 `%`，先 `cd web && npm run build` 再 Ctrl+F5（`cargo build` 不会更新页面）。

**Windows（前台）**

改过 `web/src` 时先 `cd web; npm run build`，再启动；只编 Rust 不会换页面。不要用 `cargo run` 看面板：Cargo 会转发输出，光标回退失效，盘口会一行行往下刷。直接跑编译好的 exe：

```powershell
cd D:\project\dex-arbitr
$env:RUST_LOG = "info"
.\target\release\dex-arbitr.exe
# 停止：Ctrl+C
```

调试版把路径改成 `.\target\debug\dex-arbitr.exe`。

启动后应看到账户已加载、`matched perp pairs` 和各所交集条数。之后控制台和文件只在有过线币时打一行；没有过线就不刷。Ctrl+C 退出。

### 6.1 Linux 后台（systemd）

面板依赖交互终端。当后台服务时，统计行可能无法原地刷新，但进程仍会采样 SQLite。适合挂机记账，不适合盯盘。

`/etc/systemd/system/dex-arbitr.service`：

```ini
[Unit]
Description=dex-arbitr P1 monitor
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=trader
WorkingDirectory=/opt/dex-arbitr
ExecStart=/opt/dex-arbitr/target/release/dex-arbitr
Environment=RUST_LOG=info
# 文本日志写 WorkingDirectory/data/logs/（进程自己落盘，按天滚动）
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dex-arbitr
sudo systemctl status dex-arbitr
sudo journalctl -u dex-arbitr -f
sudo systemctl stop dex-arbitr
```

### 6.2 Windows 后台

盯盘请用前台 PowerShell 窗口。需要关机后自启时，可用「任务计划程序」：

- 操作：启动 `D:\project\dex-arbitr\target\release\dex-arbitr.exe`
- 起始于：`D:\project\dex-arbitr`
- 建议勾选「只有登录时运行」，以便看到控制台

停止：任务管理器结束 `dex-arbitr.exe`，或：

```powershell
Stop-Process -Name dex-arbitr -Force
```

## 7. 日志与数据

进程在仓库根目录跑时，文本日志写到 **`data/logs/`**（`system.log_dir`，可用环境变量 `DEX_LOG_DIR` 覆盖）。

| 位置 | 内容 |
|------|------|
| 控制台 / stderr | 启动摘要 + 与文件相同的代币关键行 |
| `data/logs/dex-arbitr.log.YYYY-MM-DD` | **按天滚动的文本日志**（扫描 snapshot / top / 重连）。给本机分析用这个 |
| `RUST_LOG` | 默认 `info`；排错可 `debug` |
| `data/spreads.sqlite` | 跨 DEX raw 样本 + `nat` 快照；重启直接用，定期重算 |

`data/` 已 gitignore。空 `log_dir: ""` 则只打 stderr。

### 7.1 从 Linux 拷回本机分析

在服务器上（路径按你的 `WorkingDirectory` 改）：

```bash
ls -lh /opt/dex-arbitr/data/logs
```

本机 PowerShell / 终端：

```bash
scp user@你的Linux:/opt/dex-arbitr/data/logs/dex-arbitr.log.2026-08-23 ./
# 或整目录
scp -r user@你的Linux:/opt/dex-arbitr/data/logs ./logs-from-linux
```

如果以前只跑 systemd、还没有文件日志，也可以从 journal 导出一份再拷：

```bash
journalctl -u dex-arbitr --since "2026-08-23" --no-pager -o short-iso > /tmp/dex-arbitr.journal.log
scp user@你的Linux:/tmp/dex-arbitr.journal.log ./
```

拷回后可用脚本统计上榜次数、最大 raw/res、持续时间和闪烁占比：

```bash
python scripts/analyze_scan_log.py dex-arbitr.log.2026-08-24
python scripts/analyze_scan_log.py dex-arbitr.log.2026-08-24 --top 20 --csv scan-stats.csv
```

清 SQLite 历史：停进程后删 `data/spreads.sqlite`（只影响 `nat`）。日志文件直接删对应日期即可。

## 9. 常见问题

**找不到 `config/default.yaml`**  
工作目录不是仓库根。`cd` 到含 `config/` 的目录再启动。

**Windows：`linker link.exe not found`**  
没装 MSVC。改用 GNU 工具链，并把 MinGW 的 `bin` 加入 `PATH`。

**Windows：盘口一行行往下滚**  
用 exe 直接启动，不要 `cargo run`。

**`signing keys loaded` 没有出现**  
venue yaml 里 `api_key_private_key` 为空或 `0x`。监控仍可跑，只是账户未标记为已加载。

**扫描 `opp=0` 但 `ready>0`**  
两边盘口在，毛价差不到 `0.1%`。不是没扫到。

**`intent=skip note=thin_book`**  
卖一或买一数量不够 `base_qty` / 两腿 `min_qty`。空仓会跳过开仓；有仓时格子本笔平仓量不够也会丢掉平仓意图。

**`res` 一直为负 / 不开仓**  
仅 `scan.enabled: false`。开仓看窗口 μ 与 STEP，不是绝对 T1。`res` 只给监控。没有 nat 快照时空仓监控残差为 0。即使 `intent=open` 也只 `skip_send`（`monitor_only`）。

**两所时间不同步、面板卡住**  
看是否还有 `dex-arbitr` 进程；WebSocket 断开后会自动重连。Linux：`journalctl -u dex-arbitr -n 100`。

**启动后一直「等盘口」、毛价差/中枢全空**  
行情循环没连上 WS。旧版 `FeedGuard` 用 `watch::send` 在没有 Receiver 时会丢更新，循环立刻退出。当前代码已改 `send_replace`。日志里应出现 `entropy ws connected` / Lighter `subscribed order_book`（WS 那条，不是适配器登记那条）。

**Linux：`Too many open files` + `history sample failed` + `accept error`**  
同一件事：进程 FD 用光。Lighter 公共流约 120s 无 ping 会踢连接；旧代码不发 ping，每 124s 重连一次，每次再扫 `/etc/ssl/certs` 一两百个 PEM。当前：内存根证书、Lighter 30s ping。临时 `ulimit -n 65535`。

**毛价差一直为负**  
空仓「毛价差」是有符号 mid 差 \((\mathrm{mid}_L-\mathrm{mid}_R)/\mathrm{avg}\times 100\)，L=`legs[0]`（所选所对里靠前的那个，Lighter×Entropy 一般是 Lighter）。负号表示 L 比 R 便宜，不是算成「高价减低价」。STEP 方向靠这个符号。

**Lighter「签名→确认」一直是 —**  
还没成功走过签名+`sendTx`。下出主网单后配置页「交易所持仓」会显示 `sign_ms+send_ms=合计ms`。日志：`lighter place rtt venue=lighter ...`。不含拉 nonce、等锁、成交回查。

## 10. 安全

- 不要把 `api_key_private_key` 提交到 git 或发到聊天。
- 保持 `monitor_only: true`，直到签名下单完成并经过小仓验收。
- 生产机最小权限：只能读配置、写 `data/`、出网访问两个所。
- 同一 API key 不要在两台机器同时跑实盘（P1 监控可以，避免以后误开双实例发单）。
