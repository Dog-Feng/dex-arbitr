## A2 · 减仓量补最小下单量检查

### 现状

加仓分支有检查，减仓分支只查 `<= 0`：

```rust
// grid.rs:424-428
let qty = split_order_qty(close_delta, params);
if qty <= Decimal::ZERO {
    self.clear(slot);
    return Intent::Hold;
}
```

`split_order_qty` 只合并「切完剩下的尾巴太小」，整笔 `close_delta` 本身小于 `min_qty` 时会原样返回。

### 步骤

在 424-428 之后插入：

```rust
if params.min_qty > Decimal::ZERO && qty < params.min_qty {
    // 减仓量不足最小下单量，发出去必被交易所拒。
    // 不 clear：这不是「条件不满足」而是「条件满足但量太小」，
    // 价差继续回落会让 target_segments 更低、close_delta 变大，
    // 届时用已攒好的持续性立刻发单。
    return Intent::Hold;
}
```

`decide_scalp_close`（472-476 行）做同样处理。

### 边界：`target_segments == 0` 的死角

上面的「等 delta 变大」只在 `target_segments > 0` 时成立。若目标已是 0（全平）而 `pos.qty < min_qty`，`close_delta = pos.qty` 永远不会变大——**这笔残仓在交易所侧也平不掉**，属于灰尘仓位，必须人工处理。

在 `controller.rs` 的 `process_pair` 里，`grid.decide` 返回 `Hold` 之后加一段检测：

```rust
if matches!(intent, Intent::Hold) {
    if let Some(p) = pos.as_ref() {
        let dust = p.qty > Decimal::ZERO
            && params.min_qty > Decimal::ZERO
            && p.qty < params.min_qty;
        if dust {
            // 连续处于灰尘状态超过阈值才报，避免刚成交的瞬间误判
            let since = *self.dust_since.entry(slot.clone()).or_insert(Instant::now());
            if since.elapsed() > Duration::from_secs(300) {
                self.mark_intervention(&slot, /* 需构造一个最小 plan 或改签名 */,
                    Cause::NakedBelowMinQty,
                    format!("residual {} below min_qty {}", p.qty, params.min_qty));
            }
        } else {
            self.dust_since.remove(&slot);
        }
    }
}
```

`Cause::NakedBelowMinQty` 是现成但从未使用的枚举变体，正好用在这里。`mark_intervention` 当前签名要 `&HedgePlan`，这里没有 plan，需要抽一个只要 `pair_id + slot` 的内部版本。

新增字段 `dust_since: HashMap<String, Instant>`。

### 验收

新增两个单测：
- `close_delta_below_min_qty_holds` —— `pos.qty = 1.02 × base_qty`、`min_qty = 0.1 × base_qty`，`target = 1` 时返回 `Hold` 而非 `Close`。
- `close_delta_grows_when_target_drops` —— 同上但 `target = 0`，`close_delta = pos.qty` 应能正常发出（若 `pos.qty >= min_qty`）。

## A3 · 统一加减仓的量口径

### 现状

加仓用**格数差 × 单格量**，减仓用**量差**，两者不对称：

```rust
// grid.rs:368-370，加仓
let add_to = count_segments(open_net.raw_pct, &params.open_thresholds());
if add_to > current_segments {
    let open_delta = params.base_qty * Decimal::from(add_to - current_segments);
```

```rust
// grid.rs:408，减仓
let close_delta = pos.qty - params.base_qty * Decimal::from(target_segments);
```

问题：`current_segments = segments_held(...)` 向上取整，`pos.qty = 0.5 × base_qty` 会被算成 1 格。此时若价差仍在 T1，`add_to = 1`，`add_to > current_segments` 不成立，**欠的半格永远补不上**。

### 步骤

改成与减仓同一口径：

```rust
let add_to = count_segments(open_net.raw_pct, &params.open_thresholds());
let target_qty = params.base_qty * Decimal::from(add_to);
// 用量比较而非格数比较：segments_held 向上取整会把「欠了半格」的持仓
// 算作满格，格数比较发现不了欠仓。
if target_qty > pos.qty {
    let open_delta = target_qty - pos.qty;
    let qty = split_order_qty(open_delta, params);
    if qty > Decimal::ZERO
        && (params.min_qty <= Decimal::ZERO || qty >= params.min_qty)
    {
        if !self.persist_ready(slot, PersistKind::Open, params, now) {
            return Intent::Hold;
        }
        return Intent::Open {
            qty,
            buy: pos.buy.clone(),
            sell: pos.sell.clone(),
            grid: add_to,
        };
    }
    // 缺口不足一次最小下单量 → 不算「该加仓」，继续往下走减仓判断。
    // 注意这里既不 clear 也不 return。
}
```

### 关键差异：`min_qty` 检查要提到 `persist_ready` 之前

原代码顺序是「先 `persist_ready` 再查 `min_qty`，不满足就 `clear + Hold`」。改成量比较后，`target_qty > pos.qty` 会因为精度残差频繁成立（可能只差 0.001 格），如果沿用原顺序，每轮都会走进来并 `clear(slot)` 清掉持续性进度，导致真正需要加仓时永远攒不满。

所以必须：**先算 `qty` 并查 `min_qty`，不够就当作「不需要加仓」静默跳过**，不 clear、不 return，让流程继续到减仓判断。

### 验收

新增单测 `tops_up_partial_fill_by_quantity`：`base_qty = 1.0`、`pos.qty = 0.5`、价差在 T1（`add_to = 1`），期望返回 `Open { qty: 0.5 }`。当前代码会返回 `Hold`。

## B3 + B4 · `grid_for` 新签名与逐所对覆盖

两个任务一起做，因为改的是同一个函数。

### 三层取值：override → pair setting → defaults

```rust
pub fn grid_for(
    &self,
    symbol: &str,
    venue_a: &str,
    venue_b: &str,
    min_qty: Decimal,
) -> Option<GridParams> {
    let s = self.pair_setting(symbol)?;
    let d = &self.pairs.defaults;
    let ov = s.override_for(venue_a, venue_b);

    // 每个字段依次尝试 override / setting / defaults
    macro_rules! pick {
        ($field:ident, $def:expr) => {
            ov.and_then(|o| o.$field).or(s.$field).unwrap_or($def)
        };
    }

    Some(GridParams {
        base_qty: s.base_qty,                          // 不可被 override
        initial: pick!(initial_spread_threshold, d.initial_spread_threshold),
        step: pick!(grid_step, d.grid_step),
        max_segments: pick!(max_segments, d.max_segments),
        t0_ratio: pick!(t0_ratio, d.t0_ratio),
        split_order_size: pick!(split_order_size, d.split_order_size),
        scalping_enabled: pick!(scalping_enabled, d.scalping_enabled),
        scalping_trigger_segment: pick!(scalping_trigger_segment, d.scalping_trigger_segment),
        scalping_profit_threshold: pick!(scalping_profit_threshold_pct, d.scalping_profit_threshold_pct),
        min_qty,
        // 持续性仍是全局项，继续从 self.grid 读
        persistence: Duration::from_millis(self.grid.persistence_ms),
        persistence_mode: ...,
        spread_persistence_seconds: self.grid.spread_persistence_seconds,
        strict_persistence_check: self.grid.strict_persistence_check,
    })
}
```

## C1 · `sizing` 从定仓改为容量校验

### 新签名

```rust
/// 本次要开/加 `add_qty` 币，两腿保证金与盘口深度是否撑得住。
/// 不再返回数量——数量由配置决定，这里只做否决。
pub fn check_capacity(
    cfg: &SizingConfig,
    add_qty: Decimal,
    buy: LegMargin,
    sell: LegMargin,
    buy_book: &Bbo,
    sell_book: &Bbo,
    mid_price: Decimal,
) -> Result<(), &'static str> {
    if mid_price <= Decimal::ZERO {
        return Err("no_mid");
    }
    if add_qty <= Decimal::ZERO {
        return Err("no_size");
    }
    let need = add_qty * mid_price;

    // 保证金：两腿都要开得起（等价于原来的「短板腿」逻辑，只是从取 min 定量
    // 变成两边分别校验）
    let util = cfg.margin_utilization_pct;
    if buy.free_notional(util) < need || sell.free_notional(util) < need {
        return Err("no_margin");
    }

    // 深度：单笔下单量不得超过一档量的 depth_pct
    if cfg.depth_pct > Decimal::ZERO {
        let cap = buy_book.ask_qty.min(sell_book.bid_qty) * cfg.depth_pct / Decimal::from(100);
        if cap > Decimal::ZERO && add_qty > cap {
            return Err("thin_book");
        }
    }
    Ok(())
}
```

### 刻意去掉的约束

原 `resolve_qty` 里的全局预算 `global_min_available × leverage / max_concurrent_pairs`（`sizing.rs:77-88`）**不保留**。理由：那是「把总额切成 N 份分给各对」的定仓逻辑，用户显式指定数量后再拦一道会与用户意图冲突。多对并发的总量控制由 `reserved_margin_by_venue` 反映到 `LegMargin.reserved_usdc` 上，单所保证金校验已经隐含覆盖。

### 删除项

`preview_segment_qty`、`BindingLeg`、`ResolveQtyResult`、`SizingMode`。`LegMargin` 与 `free_notional` 保留不动。

11 个单测重写为：保证金不足→`no_margin`、深度不足→`thin_book`、正常→`Ok`、`depth_pct = 0` 时跳过深度检查。

## C2 + C3 · 决策环接线（两个任务合并）

### 关键简化

原流程是「先定仓算出 qty → 再 decide」，新流程 `base_qty` 已知，可以「先 decide → 再对 Open 意图校验容量」。这样**空仓开仓与加仓走同一条校验路径**，C3 自动完成，不必在两处各写一遍。

### 步骤

**第一步**，删除 `controller.rs:1347-1430` 整段（`if pos.is_none() { resolve_qty ... }`）。`params.base_qty` 现在由 B3 的 `grid_for` 从配置带出，无需覆盖。

**第二步**，在 `grid.decide` 与 `apply_funding` 之间（约 1470 行）插入容量校验：

```rust
        &self.cfg.sizing,
        *qty,
        self.leg_margin(&reserved, buy.as_str()),
        self.leg_margin(&reserved, sell.as_str()),
        bb, sb, mid,
    ) {
        self.panel.stats.bump_skip(reason);
        self.set_spread(pair_i, dashboard::skip_lines(&pair.pair_id, reason));
        self.fill_monitor_row(&slot, &pair, &net, pos.as_ref(),
            capacity_label(reason), &b0, &b1, Some(mid));
        return;
    }
    // 用**实际下单量**复核一档厚度（原 1407-1429 的作用，保留）
    if sequenced_spread(&self.cfg, buy, sell, bb, sb, *qty).is_none() {
        self.panel.stats.bump_skip("thin_book");
        self.set_spread(pair_i, dashboard::skip_lines(&pair.pair_id, "thin_book"));
        return;
    }
}
```

**第三步**，`plan.base_qty = params.base_qty`（1712-1714 行）保持不变——现在这个值直接来自配置，写进 `Position.base_qty` 后仍然是整个持仓周期的尺。

**第四步**，`record_ui_pair` / `fill_monitor_row` 里 `preview_segment_qty` 的调用（2741 行）改为直接读 `params.base_qty`。

**第五步**，`dashboard.rs` 的 `bump_skip` 增加 `no_margin` / `no_capacity` 分支，`controller.rs:2680` 附近的中文状态映射同步加。

### 顺序上的一个注意点

容量校验放在 `apply_funding` / `apply_risk_limits` **之前**还是之后？建议**之前**：容量不足是硬约束，先拦掉能省下后面几道门的计算。但要确保它只作用于 `Intent::Open`——`Close` 意图绝不能被容量校验拦住，否则仓位平不掉。上面的 `if let Intent::Open` 已经保证了这点。

### 验收

paper 模式跑通「开 1 格 → 加到 2 格 → 减回 1 格 → 全平」；把 `fallback_available_usdc` 调到很小，加仓时应被 `no_margin` 拦住并出现在面板 skip 计数里。

```rust
/// 启动时执行一次。只加载不订阅。
async fn load_available_pairs(&mut self) -> Result<()> {
    let mut listed: Vec<Vec<VenueMarket>> = Vec::new();
    for id in &self.cfg.venues {
        let Some(adapter) = self.adapters_by_id.get(id).cloned() else { continue };
        match adapter.list_perps().await {
            Ok(m) => listed.push(m),
            Err(e) => warn!(venue = %id, error = %e, "list_perps failed; venue excluded"),
        }
    }
    if listed.len() < 2 {
        anyhow::bail!("need at least two venues with market data");
    }
    self.available_pairs = match_all_pairs(&listed);
    info!(n = self.available_pairs.len(), "available pairs loaded");
    Ok(())
}

/// 页面点启动或 rematch 时执行。只订阅选中的对。
async fn activate_pairs(&mut self) -> Result<()> {
    self.sync_page_config();
    let active_venues = self.live_params()
        .map(|lp| lp.active_venues.clone())
        .unwrap_or_else(|| self.cfg.venues.clone());

    let selected: Vec<Pair> = self.available_pairs.iter()
        .filter(|p| {
            let v0 = p.legs[0].venue.as_str();
            let v1 = p.legs[1].venue.as_str();
            active_venues.is_empty()
                || (active_venues.iter().any(|v| v == v0)
                    && active_venues.iter().any(|v| v == v1))
        })
        .filter(|p| self.cfg.pair_setting(&p.legs[0].base).is_some())
        .filter(|p| self.validate_pair_qty(p))     // 3.1 第三层硬校验
        .cloned()
        .collect();

    self.pairs = self.merge_kept_pairs(selected);
    self.subscribe_for_active().await?;            // 原 443-471 行的订阅逻辑
    self.panel.resize(...);
    self.seed_matched_pairs();
    self.start_private_streams(&active_venues).await;  // 原 498-510 行
    Ok(())
}
```

### 硬校验

```rust
fn validate_pair_qty(&self, pair: &Pair) -> bool {
    let symbol = &pair.legs[0].base;
    let Some(s) = self.cfg.pair_setting(symbol) else { return false };
    let min_qty = pair.min_qty();
    let precision = pair.legs.iter().map(|l| l.qty_precision).min().unwrap_or(8);

    if s.base_qty < min_qty {
        tracing::error!(
            pair = %pair.pair_id, base_qty = %s.base_qty, min_qty = %min_qty,
            "configured base_qty below venue minimum; pair skipped"
        );
        return false;
    }
    if s.base_qty != s.base_qty.round_dp(precision) {
        tracing::error!(
            pair = %pair.pair_id, base_qty = %s.base_qty, precision,
            "configured base_qty violates venue precision; pair skipped"
        );
        return false;
    }
    true
}
```

**跳过单个对而不是整体 bail**——一个币配错不该让其他币也不能跑。

### 订阅的增量性

原 `subscribed_markets: HashSet<(String, String)>` 机制保留：用户后续勾选新币时，只为新增的 `(venue, pair_id)` 拉 WS，已订阅的不动。SoDEX 的全市场 `allBookTicker` 特例（448-460 行）也照旧——它只订一次，用**全集**建别名表。

- 无 HTTP：直接 `activate_pairs()`

## F1 · 启用剥头皮模式（零代码）

### 为什么它现在等于关着

不是因为 `scalping_enabled: false`，而是 `scalping_trigger_segment: 10`——触发要求 `open_grid_level >= 10`，即价差达到 `T1 + 9 × step = 0.30%`，实盘几乎不出现。

### 它做什么

正常减仓用 `close_thresholds`（滞后一格），剥头皮用 `open_thresholds`（`grid.rs:452`）：

```rust
let target_segments = count_segments(relative, &params.open_thresholds());
```

**滞后被完全取消**——第 3 格跌破 0.09% 就减，不必等跌破 0.06%。且这条路径**不走持续性门**（`decide_scalp_close` 里没有 `persist_ready`），响应更快。收敛下界改由 `scalping_profit_threshold` 单独把关。

### 调参

```yaml
grid:                                  # B 阶段后移入 pairs.defaults / overrides
  scalping_enabled: true
  scalping_trigger_segment: 2          # 原 10
  scalping_profit_threshold_pct: "0.02"
```

`0.02%` 的止盈阈值对 lighter↔entropy（往返 0.016%）净赚 0.004%，对 sodex↔lighter_rh（往返 0.0916%）是纯亏损。**所以 B4 完成前只能在便宜所对上单独测**，完成后写进该所对的 `override`。

### 一个副作用

`scalping` 状态一旦进入，只有仓位归零才退出（`exit_scalping` 在空仓时调用）。中途改配置关掉 `scalping_enabled` 不会让已进入的槽退出——`maybe_activate_scalping` 只管进不管出。如果需要热关，得在 `decide_held` 里加一句：`if !params.scalping_enabled { self.exit_scalping(slot); }`。

### 验收

paper 模式跑一段，对比启用前后的：减仓次数、单笔净收益中位数、单笔净收益为负的比例。第三项若上升明显，说明 `scalping_profit_threshold` 相对该所对费率偏低。

## G1 · 保证金占用按市价重估

### 现状

`entry_notional_usdc` 记的是开仓那一刻的名义，之后只在减仓时按比例缩（`positions.rs:158-161`），**不按市价重估**。`reserved_margin_by_venue` 拿它估算已占用保证金，币价上涨后会低估占用、高估可用额度。

### 改法

`reserved_margin_by_venue` 增加一个取价回调：

```rust
    leverage_fn: F,
    mid_fn: P,                       // 新增：按 pair_id 取当前中价

where
    F: Fn(&str) -> Decimal,
    P: Fn(&str) -> Option<Decimal>,
{
    // 占用 = qty × 当前 mid / 杠杆；取不到 mid 时回退 entry_notional_usdc
}
```

调用点 `controller.rs:1342`、`2739` 传入 `|pid| self.book(...).and_then(...)`。

`entry_notional_usdc` 保留原义（建仓成本），继续用于往返盈亏与 `NotionalLimits`。

### 为什么不直接改 `entry_notional_usdc`

它同时承担「建仓成本」与「保证金占用」两个语义。往返盈亏必须用建仓时的成本，实时重估会污染它。拆开是正解。
