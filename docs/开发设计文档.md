## 1. 目标与范围

### 1.1 要做成什么

在不同 DEX 订单簿永续之间做价差对冲：一边开多、一边开空，锁住价差；价差扩大按格加仓，收敛按格减仓。两边保证金预先放好，**热路径不搬家、不兑币、不跨链**。

稳定币按 1:1 处理：`BTC-USDC` ≡ `BTC-USDG`。USDC/USDG 偏离超过熔断阈值时只停开，不改计价公式。

### 1.2 三阶段

| 阶段 | 内容 | 产出 |
|------|------|------|
| P1 | 两所永续发现、匹配、净价差、机会识别、分段下单 | 无界面的 Linux 后台进程，日志 + 本地状态可观察 |
| P2 | 监控界面 | 浏览器打开的实时控制台，同一进程对外提供 HTTP/WS |
| P3 | 更多 DEX、资金费率套利 | 新适配器 + 可选决策路径，不改核心流水线 |

### 1.3 明确不做（P1）

- 现货、原子成交、跨链转账
- 资金费率独立开仓（P3）
- （已改）P1 用 SQLite 记价差、中位数当天然价差；资金费率套利仍是 P3
- 复杂领域事件总线、CQRS、微服务拆分
- 桌面客户端、终端主界面

## 2. 架构：MVC + 前后端

就用 MVC，不再叠 DDD / 六边形。

```
View         web/ 静态页（浏览器）
  ↕ HTTP / WebSocket
Controller   匹配、计价、决策、下单、把快照推给前端
Model        交易对、盘口、价差、格子、持仓
```

- **Model**：内存里的业务数据。
- **Controller**：Rust 后台，连交易所、跑分段、提供 API。
- **View**：静态 HTML/CSS/JS。P1 可以先打开本地文件看效果；P2 由 Rust 直接提供页面和数据。

约束：

1. 前后端分离：页面不直连交易所，只读自己的后端。
2. 新交易所只加适配代码 + 配置，Controller 流程不变。
3. 内存态为主。P1 不引入数据库。
4. 一个 Rust 进程：交易 +（P2）HTTP。不加 Nginx、Grafana、独立前端服务。

## 4. 一阶段流程

```
启动
  → 连接 lighter、lighter_rh
  → 拉取永续市场列表
  → 标准化并匹配成 Pair
  → 订阅两侧 orderbook
循环（事件驱动，不做固定 100ms 空转）
  → 盘口更新（带时间戳）
  → 新鲜度检查
  → 算可成交毛价差（Ask 买 / Bid 卖，双向）
  → 扣手续费、预估滑点
  → 分段决策（target − actual = delta）
  → 风控
  → 双腿下单 / 平仓
  → 更新持仓与格子
```

`monitor_only: true` 时决策照跑，不发单，方便先核对匹配和净价差。

### 4.1 交易对发现与匹配

每所只取永续。标准化后匹配：

| 字段 | 规则 |
|------|------|
| base | BTC、ETH… 大小写归一 |
| quote | USDC / USDG / USDT 一律视为 USD（P1） |
| 类型 | 仅 perp |
| pair_id | `{base}-USD-PERP`，如 `BTC-USD-PERP` |
| venue_symbol | 所方原始名，下单仍用它 |

两侧都能映射到同一 `pair_id` 才进监控。一侧没有的币直接丢弃。P1 默认只跑配置里的白名单（建议先 BTC、ETH）。

### 4.2 价差

可成交价差，不用中间价：

```
方向 A：在 venue_x 用 Ask1 买，在 venue_y 用 Bid1 卖
spread_pct = (bid_y − ask_x) / ask_x

方向 B：反过来再算一次
取净边更大的方向作为开仓方向
```

已有持仓时，开仓方向用记忆方向，平仓用真实反向盘口重算，不能把买卖价对调一下了事。

盘口超过 `data_freshness_ms`（默认 3000）不参与本轮。

### 4.3 成本与净边

```
fee_pct      = 由 order.style 决定：market_taker 扣 taker+taker，limit_maker 扣 maker+maker
slip_pct     = 配置的滑点预留
net_spread   = spread_pct − fee_pct − slip_pct
natural      = 该方向历史毛价差的中位数（SQLite，对齐参考项目）
residual     = net_spread − max(natural, 0)
```

格子开仓看 residual ≥ T1，不是看毛价差。样本不足（默认 <10 点）只记账、不开仓。P1 滑点用配置常数，不读多档深度仿真。深度只做下限：Ask1/Bid1 数量 < `min_book_qty` 则本轮跳过。

USDC/USDG 默认 1:1。`|usdc_usdg − 1|` 超过 `stable_depeg_bps`（建议 20bp）时拒绝新开仓，已有仓仍允许平。

### 4.4 分段决策

沿用参考项目的库存公式，P1 只做 SEG-GRID，不做剥头皮、不做拆单变体（一格一单）。`max_segments` 建议先设 1，管道稳定后再加大。

```
T1 = initial_spread_threshold
Tn = T1 + (n − 1) × grid_step
T0 = T1 × 0.4

当前格子 = 净边所在格
目标仓   = min(格子, max_segments) × base_qty
delta    = 目标 − 实际
```

- `delta > 0` 且净边在该格持续 `persistence_ms` → 开仓 `|delta|`（不超过一格）
- `delta < 0` 且回落持续同样时间 → 平仓 `|delta|`
- 同一交易所对禁止反向双开；反向信号走平仓
- 段只记账（FIFO 平仓），不参与决策

### 4.5 下单

双腿对冲，热路径不转资金。

1. 按所优先级决定先后（建议被动限价先、吃单后；两所都是 Lighter 协议时可并行或固定「主网先 / RH 先」写在配置）。
2. 一腿成交、另一腿失败 → 立即补对冲腿（市价或激进限价），补不上则记敞口告警，禁止该 pair 继续开仓。
3. 数量按所方精度截断；小于最小下单量则本轮放弃。
4. 每所一把执行锁，避免同一 pair 重入。

默认 **limit_then_market**：吃单费率高的一所先挂限价，成交后再对另一所市价。挂着期间价差不够或超时则撤未成交单；若已经成交（含撤单前成交），另一边仍市价对冲，避免单边。`order.style` 可切回 `market_taker` / `limit_maker`。手续费写在各所 `config/venues/*.yaml`。P1 先 `monitor_only` 看日志。

### 4.6 风控（P1 最小集）

- 数据新鲜度
- 稳定币脱锚熔断
- 单 pair 最大格数 / 最大持仓
- 单所可用保证金不足 → 停开
- 单腿敞口 → 停开 + 告警
- `monitor_only`

不加全局日交易次数、历史稳定性这类 CEX 遗留项。

## 5. 核心类型（领域层）

```rust
struct VenueId(String);          // "lighter" | "lighter_rh"

struct NormSymbol {
    base: String,                // BTC
    kind: MarketKind,            // Perp only in P1
}

struct VenueMarket {
    venue: VenueId,
    raw_symbol: String,          // BTC-USDC / BTCUSDG
    norm: NormSymbol,
    qty_precision: u32,
    min_qty: Decimal,
}

struct Pair {
    pair_id: String,             // BTC-USD-PERP
    legs: [VenueMarket; 2],
}

struct Bbo {
    bid: Decimal,
    ask: Decimal,
    bid_qty: Decimal,
    ask_qty: Decimal,
    ts: Timestamp,
}

struct NetSpread {
    buy: VenueId,
    sell: VenueId,
    raw_pct: Decimal,
    fee_pct: Decimal,
    slip_pct: Decimal,
    net_pct: Decimal,
}

enum Intent {
    Open { qty: Decimal, buy: VenueId, sell: VenueId, grid: u32 },
    Close { qty: Decimal, grid: u32 },
    Hold,
}
```

应用层只组合这些类型，不把 REST 响应结构泄漏进来。

## 6. 交易所端口

```rust
#[async_trait]
trait ExchangePort: Send + Sync {
    fn id(&self) -> VenueId;
    async fn list_perps(&self) -> Result<Vec<VenueMarket>>;
    async fn subscribe_bbo(&self, symbols: &[String], tx: BboTx) -> Result<()>;
    async fn place(&self, req: OrderReq) -> Result<OrderAck>;
    async fn positions(&self) -> Result<Vec<VenuePosition>>;
    async fn balances(&self) -> Result<Vec<Balance>>;
}
```

P1 实现：`LighterAdapter`，构造时注入：

```yaml
# config/venues/lighter.yaml  — 该所自己的 URL / 费率 / 密钥
# config/venues/lighter_robinhood.yaml
```

每所一份 yaml：连接、手续费、`account_index` / `api_key_index` / `api_key_private_key` 都写在该文件里。私钥不要提交 git。`market_index` 启动时按交易对从 `orderBooks` 拉取。

```yaml

  monitor_only: true
  data_freshness_ms: 3000
  stable_depeg_bps: 20

venues:
  - lighter
  - lighter_rh
```

## 11. P1 实现顺序

1. 领域类型 + 匹配 + 净价差单元测试（不连网）
2. Lighter 适配器：拉市场、订 BBO（先只读）
3. 两实例跑通匹配，日志打印每对净边
4. 格子决策（`max_segments = 1`）+ `monitor_only`
5. 双腿市价 taker 下单 + 持仓核对
6. 单腿补单、新鲜度、脱锚、保证金停开
7. 打开格子数（仍无界面）

P2 在第 3 步之后随时可插总线，不阻塞交易闭环。

## 12. 测试

- 匹配：BTC-USDC ↔ BTC-USDG 合成一对；缺腿丢弃；现货过滤掉。
- 价差：构造 Ask/Bid，断言方向和净边；过期盘口不算。
- 格子：净边穿过 T1/T2 时的目标仓；回落到 T0 全平。
- 适配器：用录制的 REST/WS 做集成，不默认打实盘。
- 实盘前：`monitor_only` 至少对完一个完整交易日的匹配与净边分布。

## 13. 风险与默认选择

| 项 | 默认 | 原因 |
|----|------|------|
| USDC=USDG | 是 | 产品约定；脱锚只熔断 |
| 主界面 | P2 Web，不是 TUI | Linux 远程值班 |
| 一进程 | 是 | 避免两份持仓真相 |
| 一所一适配器协议 | Lighter 协议复用 | RH 是 fork，不是新协议 |
| P1 下单 | 双市价 taker（可切 maker） | 优先锁双边，避免单边巨亏 |
| max_segments | 先 1 | 先验证对冲，再放大网格 |

这份文档只覆盖能开工的决策。协议字段、签名细节进适配器实现时再补，不在这里展开。
