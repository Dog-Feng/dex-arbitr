# 参考项目核心套利流程（crypto-trading-open-main）

版本：与本地参考目录同步梳理（2026-08-24）  
参考路径：`crypto-trading-open-main/`（`.gitignore` 忽略，本地参考）  
核心模块：`core/services/arbitrage_monitor_v2/`

本文档汇总参考项目的 **套利检测 → 决策 → 下单执行 → 仓位控制** 全流程，供 dex-arbitr 后续对齐与实现时查阅。  
与本项目的差异见 [套利流程对比.md](套利流程对比.md)。

## 1. 系统概览

### 1.1 三代演进

| 版本 | 入口 | 用途 |
|------|------|------|
| **V1** | `run_arbitrage_monitor.py` | 早期监控 + 历史决策 + 执行 |
| **V2 纯监控** | `run_arbitrage_monitor_v2.py` | 仅 Rich 终端 UI，不下单 |
| **分段执行（生产主路径）** | `main_unified.py` | 监控 + 分段网格决策 + 实盘执行 |
| **V3 基础套利** | `run_arbitrage_execution_v3.py` | 历史基准（net − 中位数）+ 资金费率条件 |

dex-arbitr P1 扫描对齐 **V2 检测**；格子/执行对齐 **`main_unified.py` 分段路径**。

### 1.2 分层架构

```
入口 main_unified.py
  └── UnifiedOrchestrator          # 主循环 ~100ms
        ├── SpreadPipeline           # 价差流水线：行情 → 开/平检查
        ├── UnifiedDecisionEngine    # 格子决策、总量驱动、持仓
        ├── ArbitrageExecutor        # 双腿下单、回滚
        │     ├── OrderStrategyExecutor   # limit_market / market_market / limit_limit
        │     ├── OrderMonitor            # WS/REST 等成交
        │     └── ReduceOnlyHandler
        ├── DataProcessor            # 内存 orderbook
        ├── SpreadCalculator         # 价差计算
        └── GlobalRiskController     # 余额、总持仓上限（V3 更完整）
```

### 1.3 配置文件

| 文件 | 用途 |
|------|------|
| `config/arbitrage/monitor_v2.yaml` | 监控：交易所列表、symbols、阈值、分析间隔 |
| `config/arbitrage/arbitrage_segmented.yaml` | 分段执行：格子、数量、风控、每币 override |
| `config/arbitrage/multi_exchange_arbitrage.yaml` | 多所一对多 / 多对多配对 |
| `config/arbitrage/multi_leg_pairs.yaml` | 多腿套利（同所不同代币等） |
| `config/exchanges/*_config.yaml` | 各所 API、订阅、下单模式 |
| `config/symbol_conversion.yaml` | 跨所 symbol 标准化 |

启动示例：

```bash
python main_unified.py \
  --config config/arbitrage/arbitrage_segmented.yaml \
  --monitor-config config/arbitrage/monitor_v2.yaml
```

## 2. 套利检测流程（V2 监控核心）

纯监控与分段执行**共用**同一套价差计算；分段执行在主循环里额外走决策链。

### 2.1 数据流水线

```
WebSocket 推送
  → DataReceiver（入队，零延迟）
  → DataProcessor（维护最新 orderbook / ticker）
  → SpreadCalculator（两两所、两方向价差）
  → OpportunityFinder（仅纯监控路径：阈值 + age）
  → UIManager / 日志
  → SpreadHistoryRecorder（可选 SQLite）
```

**关键原则：WS 回调只写内存，不在回调里算价差或下单。**

### 2.2 分析环（纯监控 Orchestrator）

文件：`core/services/arbitrage_monitor_v2/core/orchestrator.py` → `_analysis_loop()`

- 默认间隔：**10ms**（`monitor_v2.yaml` → `performance.analysis_interval_ms`）
- 遍历 `config.symbols` 中每个 symbol
- 收集各所 orderbook，至少 2 所有数据才计算
- 调用 `SpreadCalculator.calculate_spreads()`

### 2.3 可成交价差公式

**统一公式**（dex-arbitr 与之相同）：

```
spread_pct = (卖所 Bid1 − 买所 Ask1) / 买所 Ask1 × 100
```

- **买**：在 `exchange_buy` 的 **Ask1** 成交  
- **卖**：在 `exchange_sell` 的 **Bid1** 成交  
- 每对所算 **两个方向**（A 买 B 卖、B 买 A 卖）  
- N 所组合：C(N,2) 所对 × 2 方向  

文件：`analysis/spread_calculator.py`

### 2.4 机会识别（OpportunityFinder，纯监控）

文件：`analysis/opportunity_finder.py`

| 步骤 | 规则 |
|------|------|
| 阈值 | `spread_pct ≥ min_spread_pct`（默认 **0.1%**） |
| 追踪 | 同 key `{symbol}_{buy}_{sell}` 续 **duration_seconds** |
| 排序 | 按 `spread_pct` 降序 Top-N |
| 资金费率 | 可选附带 `funding_rate_diff`（监控展示，非分段格子主条件） |
| 扣费 / nat | **监控层不扣** |

### 2.5 盘口校验（SpreadCalculator）

- Bid / Ask 存在且 > 0  
- Bid < Ask（自有点差合理）  
- 数量 > 0  

### 2.6 与 dex-arbitr 扫描路径对照

| 项 | 参考 V2 | dex-arbitr `scan.enabled=true` |
|----|---------|--------------------------------|
| 分析间隔 | ~10ms | 50ms |
| 门槛 | raw ≥ 0.1% | raw ≥ 0.1% |
| 跨所 nat | 监控不扣 | 跨 DEX 扣 nat 后 residual |
| 扣手续费 | 否 | 否 |

## 3. 分段执行主循环（检测 + 决策入口）

文件：`core/unified_orchestrator.py` → `_main_loop()`，`core/spread_pipeline.py`

### 3.1 循环节奏

- 间隔：约 **100ms**（`loop_interval`）
- 全局风控暂停时跳过本轮
- **并行** `asyncio.gather` 处理各 symbol（及 multi_exchange / multi_leg）

### 3.2 单 symbol 流水线（`SpreadPipeline.process_symbol`）

```
1. 拉各所 orderbook（data_freshness_seconds 内）
2. calculate_spreads_multi_exchange_directions → 所有方向价差
3. 有持仓？
     是 → 从记忆方向 build 开仓/平仓视角价差
     否 → 选最优正价差为 opening_spread
4. build_closing_spread_from_orderbooks → 平仓视角（必须用当前盘口重算）
5. 先 _check_and_close（平仓）
6. 再对每个正价差 _check_and_open（开仓）
```

**顺序：先平后开。** 平仓视角必须来自 `build_closing_spread_from_orderbooks()`，不能简单对调买卖字段。

### 3.3 多所 / 多腿扩展

| 模式 | 配置 | 持仓 key |
|------|------|----------|
| 单 symbol 多所 | `monitor_v2.symbols` | `symbol` |
| 多交易所配对 | `multi_exchange_arbitrage.yaml` | `trading_pair_id` |
| 多腿套利 | `multi_leg_pairs.yaml` | `pair_id` |

多交易所配对可通过 `register_config_alias(trading_pair_id, "BTC-USDC-PERP")` **复用** BTC 的数量配置。

## 4. 决策流程（UnifiedDecisionEngine）

文件：`decision/unified_decision_engine.py`  
配置：`arbitrage_segmented.yaml` → `default_config` + `symbol_configs`

### 4.1 核心哲学

1. **分段网格**：价差扩大 → 逐格加仓；价差收敛 → 逐格减仓（滞后阈值）  
2. **总量驱动**：`target − actual = delta`，不按「段 ID」做复杂状态机（段仅记录）  
3. **决策常用 raw 毛价差** 对格子（`deduct_fees: true` 在配置里，格子链路主要仍看 `spread_pct`）  
4. **持续性**：`spread_persistence_seconds`（默认 1s）连续满足才触发  

### 4.2 格子 ID 计算

```python
if spread_pct < initial_spread_threshold:  # T1，默认 0.03%
    grid = 0
else:
    grid = int((spread_pct - T1) / grid_step) + 1
```

默认：`T1=0.03%`，`grid_step=0.03%`，`max_segments=5`

| raw | 格子 |
|-----|------|
| < 0.03% | 0 |
| 0.03% ~ 0.06% | 1 |
| 0.06% ~ 0.09% | 2 |
| … | … |
| ≥ 0.15% | 5（封顶） |

### 4.3 开仓决策 `should_open()`

```
1. 错误避让：交易所在 backoff → 不开
2. current_grid = f(spread_pct)
3. grid == 0 → 不开
4. threshold = T(current_grid) 的开仓阈值
5. spread_pct < threshold → 不开
6. 持续性检查（默认 1s）
7. target = min(grid, max_segments) × base_quantity   # 或 value 模式
8. actual = 当前持仓；carry = pending_open_shortfall
9. delta = target − (actual + carry)
10. delta <= 0 → 不开
11. order_qty = _calculate_order_quantity(delta)  # 拆单
12. return True, order_qty
```

**反向持仓保护**：同一所对已有反向持仓 → 不开，设 `_reverse_open_detected` 触发平仓检查。

### 4.4 平仓决策 `should_close()`

使用 **平仓视角** 的 `spread_data`（当前盘口重新计算）。

```
1. actual > 0 否则不平
2. current_grid = f(spread_pct)
3. relative_spread = 按持仓方向归一后的价差
4. target = _calculate_target_position_by_spread(relative_spread)  # 滞后减仓
5. close_delta = actual − target
6. close_delta <= 0 → 不平
7. 持续性检查（comparison="le"）
8. close_qty = _calculate_order_quantity(close_delta)
9. return True, close_qty, reason
```

### 4.5 对称平仓阈值（默认 `use_symmetric_close: true`）

```
T0 = T1 × 0.4     # 例：T1=0.03% → T0=0.012%

开仓在 Tn → 平仓回落到 T(n-1) 以下：
  第 1 格 → 平 when ≤ T0
  第 2 格 → 平 when ≤ T1
  第 3 格 → 平 when ≤ T2
  …
```

**开高平低、滞后期**，避免价差在阈值附近抖动频繁开平。

### 4.6 目标持仓 `_calculate_target_position_by_spread`

```
open_segments  = 按 open_thresholds 数 spread 能开几格
keep_segments  = 按 close_thresholds 数 spread 还能 hold 几格

若 open_segments > current_segments → target = open_segments × base_qty  # 加仓
否则 → target = keep_segments × base_qty                              # 减仓
```

### 4.7 三种分段模式

| 模式 | 说明 |
|------|------|
| **SEG-GRID** | 标准分段网格 |
| **SEG-SCALP** | 达到 `scalping_trigger_segment` 后锁定，止盈退出 |
| **SEG-GRID+** | 单格允许多笔累积（拆单变体） |

## 5. 执行前风控（Orchestrator 层）

`_check_and_open` / `_check_and_close` 在调用 Executor 前额外检查：

| 检查 | 说明 |
|------|------|
| reduce-only 封锁 | 所处于只平模式 → 跳过开仓 |
| 休市 | 跳过开仓 |
| 价格稳定性 | `price_stability_window_seconds` 内波动 ≤ 阈值 |
| 自有点差 | 单所 bid-ask ≤ `max_local_orderbook_spread_pct` |
| 对手盘深度 | `min_orderbook_quantity`，深度 ≥ 下单量 |
| 符号等待状态 | 上次失败人工介入 / defer → 跳过 |
| 重复执行锁 | 同 symbol/所对已有 async 任务 → 跳过 |

通过后才 `asyncio.create_task` 异步下单，**不阻塞主循环**。

## 6. 下单执行流程（ArbitrageExecutor）

文件：`execution/arbitrage_executor.py`，`execution/order_strategy_executor.py`

### 6.1 执行请求 ExecutionRequest

| 字段 | 含义 |
|------|------|
| `exchange_buy` / `exchange_sell` | 开：便宜所买、贵所卖；平：已是平仓视角 |
| `price_buy` / `price_sell` | Ask / Bid 决策价 |
| `quantity` | 本次数量（决策层 delta 或拆单后） |
| `is_open` | 开 / 平 |
| `grid_level` | Tn，日志用 |
| `slippage_tolerance_pct` | 市价滑点上限 |

### 6.2 执行计划 `determine_execution_plan()`

按各所 `order_mode`（limit / market）+ `priority`：

| 买 mode | 卖 mode | 计划 |
|---------|---------|------|
| market | market | **market_market** 并行 |
| limit | limit | 默认降为 **limit_market**（priority 高者先挂） |
| limit | market | 买先挂、卖后吃 |
| market | limit | 卖先挂、买后吃 |

**生产默认：limit_market（一挂一吃）。**

Lighter 特例：

- 市价腿可走 `place_market_orders_ws_batch`  
- `force_limit_when_second_leg` → 第二腿激进限价 IOC  
- `force_sequential_limit` → 双 limit 也顺序执行  

### 6.3 limit_market 顺序（最常见）

**第一腿（限价 / Maker 侧）**

```
1. 取最新盘口价 + limit_price_offset
2. _place_limit_order()
3. OrderMonitor.wait_for_order_fill(timeout=limit_order_timeout，默认 3~60s)
4. 未成交 → 撤单 → 可重试 max_retry_count 次
5. 0 成交 → failure_code=limit_zero_fill，结束
6. 部分成交未达目标 → emergency_close 已成交部分 → partial_failure
```

**第二腿（市价 / Taker 侧）**

```
1. 数量 = 第一腿实际成交量（严格对冲）
2. _place_market_order() 或激进限价
3. 失败 → _retry_market_submission
4. 仍失败 → _fail_limit_market_second_leg → emergency_close 第一腿
```

### 6.4 订单监控 OrderMonitor

```
优先 WebSocket order fills
  → 超时 → 限价单撤单 → REST 确认
  → 撤单竞态（可能已成交）→ 额外等待确认
市价单：WS 超时 → REST 查成交
```

### 6.5 执行成功后回写

**开仓** `_execute_and_record_open`：

```
record_open(symbol, quantity, spread_data, entry_prices, filled_quantity)
report_open_shortfall()  # 部分成交记入 pending，下轮补齐
```

**平仓** `_execute_and_record_close`：

```
record_close(symbol, filled_qty, spread_data, reason)  # FIFO 减段
```

### 6.6 失败与回滚

| 场景 | 处理 |
|------|------|
| 限价 0 成交 | 放弃，不开第二腿 |
| 第一腿部分成交、目标未达 | emergency_close 第一腿 |
| 第二腿失败 | emergency_close 第一腿（+ 第二腿若有） |
| 回滚失败 | `symbol_state_manager` 标记「需人工介入」 |
| reduce-only | ReduceOnlyHandler 撤已成交腿 |
| 系统退出 | `emergency_close_all_positions()` |

## 7. 仓位控制（详细）

### 7.1 配置层级

```
arbitrage_segmented.yaml
├── default_config          # 全局默认（格子、数量、风控）
└── symbol_configs:         # 每币 override（须 enabled: true 才执行）
      "BTC-USDC-PERP": ...
```

`SegmentedConfigManager`：

- 每币配置与 default **合并**  
- `get_config(symbol)`：有专门配置用专门配置，否则 **克隆 default**  
- **`is_symbol_enabled(symbol)`**：仅在 `symbol_configs` 中且未 `enabled: false` 的币才进入 unified 主循环执行  

**重要：monitor 列表里有 50 个币 ≠ 50 个都交易**；须在 `symbol_configs` 启用或走 multi_exchange 别名。

### 7.2 目标持仓公式

**固定数量模式**（`quantity_mode: fixed`，默认）：

```
target = min(current_grid, max_segments) × base_quantity
```

**按金额模式**（`quantity_mode: value`）：

```
target = min(current_grid, max_segments) × (target_value_usdc / 当前价格)
```

同一 `target_value_usdc` 可让 BTC / SOL / 小币 **名义价值对齐**，无需 50 条 qty yaml。

### 7.3 本次下单量（拆单）

```
delta = target − (actual + carry)

order_qty = min(split_order_size, delta)   # split < base 则拆多笔
order_qty = round(order_qty, quantity_precision)

若 order_qty < min_order_size → 记入 pending_open_shortfall，本次不下
```

默认 `split_order_size: 1.0` 且等于 `base_quantity` 时不拆单。

### 7.4 持仓数据结构

```python
positions: Dict[str, SegmentedPosition]           # symbol → 总量 + 段列表
pair_positions: Dict[str, Dict[str, SegmentedPosition]]  # 多所对细分
open_direction: Dict[pair_key, ±1]                 # 方向记忆
pending_open_shortfall: Dict[symbol, Decimal]      # 未凑够的最小量
```

- 每个 symbol（或 trading_pair_id）**独立** actual / target  
- SOL 的 2 格 **不占用** BTC 的额度  
- 共享的是 **交易所账户** 里的 USDC / 保证金  

### 7.5 满仓估算（单币）

```
满仓数量 ≈ max_segments × base_quantity
满仓名义 ≈ max_segments × base_quantity × price   # fixed 模式
         ≈ max_segments × target_value_usdc        # value 模式
```

示例（BTC 配置）：`base=0.004`, `max_segments=5` → 满仓 **0.02 BTC**。

### 7.6 多币并行（50 个 symbol）

主循环 **并行** 处理各 symbol，各自：

```
delta = target − actual  →  独立 order_qty  →  独立 async 下单任务
```

**没有**「50 币共用一个 delta 池」；总敞口靠：

| 机制 | 配置 / 代码 |
|------|-------------|
| 每币格子封顶 | `max_segments × base_quantity` |
| 每币名义上限 | `risk_config.max_position_value`（配置项，分段 unified 路径 enforcement 有限） |
| 账户余额 | `min_balance_warning` / `min_balance_close_position` |
| 全局总持仓 | `GlobalRiskController.max_total_position`（**V3** 路径 `check_position_limits` 更完整） |
| 全局暂停 | `risk_controller.is_paused` |

### 7.7 全局风控 GlobalRiskController

文件：`risk_control/global_risk_controller.py`

- 周期性拉各所 **balance**、**positions**  
- `check_position_limits(symbol, new_qty)`：单币上限 + 总持仓上限（V3 调用）  
- 余额低于阈值 → 警告 / 强平 / 暂停  

分段 unified 主路径更依赖 **每币 grid 封顶 + 余额监控**。

## 9. 端到端时序（单币开仓 → 平仓）

```
[T0] WS 更新 orderbook → DataProcessor 内存
[T1] 主循环 100ms：SpreadPipeline
[T2] raw=0.05% → grid=1 → should_open → delta=0.004 BTC
[T3] _check_and_open：深度/稳定性 OK
[T4] ExecutionRequest → determine_execution_plan → limit_market
[T5] RH 挂限价买 0.004 → 成交
[T6] Lighter WS 市价卖 0.004
[T7] record_open → positions[BTC].actual += 0.004
...
[Tn] 价差收敛 → 平仓视角 spread → should_close → close_qty
[Tn+1] limit_market 反向双腿 → record_close FIFO
```

## 10. 与 dex-arbitr 对齐建议

| 参考能力 | dex-arbitr 现状 | 建议 |
|----------|-----------------|------|
| V2 毛价差扫描 | ✅ `scan.rs` | 保持 |
| 格子 + res 决策 | 公式在，scan 默认不跑 | 晋升扫描 Top 再开格子 |
| 分段多格 | max_segments=1 | 首版单格；稳定后再多格 |
| limit_market 执行 | 规划在，未接线 | 接 ExchangePort::place |
| 每币 yaml 定仓 | base_qty 表，未知=0 | 改为全局 sizing（见讨论稿） |
| 拆单 / 短缺 | 无 | 二期 |
| emergency_close | 无 | 执行层必做 |

## 12. 附录：分段多格 vs 单格

| | 多格（参考默认 max_segments=5） | 单格（dex-arbitr 现状） |
|--|--------------------------------|-------------------------|
| 价差扩大 | 逐格加仓，多锁价差 | 只锁一格 |
| 价差收敛 | 逐格减仓（滞后 Tn→T(n−1)） | 一次全平 |
| 保证金 | 随格数线性增 | 可预期、上限低 |
| 执行次数 | 多，手续费/单腿风险↑ | 少 |
| 多币并行 | 总敞口难控 | 更易控 |
| 适用 | 单币深度优化、价差波动大 | 首版实盘、多币自动发现 |
