# 参考项目套利流程

对象：仓库旁的 `crypto-trading-open-main`（Python）。本文只梳它自己的套利链，不写本仓库实现。对照见 [套利流程对比.md](套利流程对比.md)。

参考项目不是一个程序。套利相关至少三条入口，调度器、决策、是否下单都不同。

---

## 1. 三条入口

| 入口 | 调度器 | 决策 | 下单 |
|------|--------|------|------|
| `run_arbitrage_monitor_v2.py` | `ArbitrageOrchestrator` | `OpportunityFinder`（毛价差过线） | 否，只扫 |
| `main_unified.py` | `UnifiedOrchestrator` | `UnifiedDecisionEngine`（分段网格） | 是 |
| `run_arbitrage_execution_v3.py` | `ArbitrageOrchestratorV3` | `arbitrage_decision.py`（价差 + 资金费率） | 是 |

本仓库对齐的是 **第二条统一分段网格**。扫描环对第一条。资金费率闸门、天然价差是从 **第三条 V3** 抽出来当滤网，不是把 V3 当开平仓引擎。

下面先写网格主链，再写 V3 和扫描，避免混成一套策略。

---

## 2. 统一分段网格（`main_unified.py`）

赌的是：**价差会在一个区间里来回扩缩**。拉宽加仓，缩回去减仓。利润来自「异常变大 → 部分回归」，不要求一次回到零。

### 2.1 启动

```
python main_unified.py
  → 读 arbitrage_segmented.yaml + monitor_v2.yaml
  → ExchangeFactory 建各所适配器（lighter / paradex / edgex / hyperliquid …）
  → 连交易所、订订单簿
  → 实盘再订私有订单 WS
  → 起风险控制器后台环、reduce-only 探针、终端 UI
  → _main_loop 每 0.1s
```

### 2.2 主循环

`unified_orchestrator._main_loop` 每轮：

1. 风险控制器若 `is_paused` → 整轮空转。
2. 配置里的 `symbols` 若已在多交易所配对表里，跳过旧的 pair 构造。
3. 对每个可交易 pair：拉双边订单簿 → 算毛价差 → `UnifiedDecisionEngine` 出意图。
4. **先处理平仓意图，再处理开仓意图**。
5. 执行层：先挂后吃（高 taker 所先挂限价，成交后对手所市价）。失败则回滚 / 紧急平仓。
6. 成交后 `_reset_spread_persistence`，下一笔重新攒持续性。

### 2.3 格子本身

`_build_grid_thresholds`：

```
开仓阈值  [T1, T1+step, …]  共 max_segments 格（yaml 里可按币各写一套）
平仓阈值  [T0, T1, T2, …]   T0 = T1 × 0.4（写死）
```

| 规则 | 行为 |
|------|------|
| 判据 | **毛价差** `spread_pct`，不扣手续费、不扣天然基差 |
| 空仓 | 价差落在第 n 格 → 目标 = n × 单格量，第一笔开到目标格 |
| 有仓加仓 | 涨到 Tn 补到 n 格 |
| 减仓滞后 | 回落必须跌破 T(n−1) 才减一格 |
| 全平 | 跌破 T0 |
| 格数 | 向上取整 |
| 资金费率 | **不参与**开仓和平仓格子 |
| 按币参数 | 每币一套 T1 / step / 格数 |
| `segment_quantity_ratio` | 配置有，热路径基本不用 |
| 对称平仓 / 按段利润阈 | 配置有；现行热路径走总量滞后，这段是旧逻辑 |

### 2.4 持续性（宽松 / 严格秒桶）

网格怕插针：价差刚碰 T1 就开，下一秒缩回去等于白付手续费。所以规定条件要连续满足 N 秒才准交易。参考做成两种秒桶：

**宽松（每秒至少一次达标）**  
时间切成 1 秒一个桶。这一秒里只要有一次采样过线，这一秒就算过。中间空掉 1 秒以上整段清零。同一秒扫 10 次只算 1 秒。

**严格（窗口里每一次采样都得过）**  
从第一次达标开始计时，之后任意一次掉到阈值下就清零。N 秒内不能有毛刺。

宽松吃得住偶发抖动；严格几乎要求钉在线上。越严越少开、手续费越少，机会也越少。

成交后 `_reset_spread_persistence`，避免下一 tick 立刻再开/再平。

### 2.5 开仓执行细节（网格链上有、本仓库未全搬）

热路径里还有这些，本仓库没有对齐或不需要：

| 能力 | 作用 |
|------|------|
| 双限价 | 两腿都挂 maker |
| 休市 | 某所维护窗口整段停 |
| 多腿 | 不同币两条腿（不是「同一币两个所」） |

剥头皮（`SEG-SCALP`）本仓库已对齐，默认关。盘口过薄丢掉平仓意图已对齐。开仓拆单 + 缺口补齐本仓库已对齐：每轮用 `目标格 − 已持格` 重算，不必另记 shortage。

先挂后吃失败会回滚。风险控制器可暂停整轮。reduce-only 探针在整点附近试最小量，确认交易所是否恢复。

## 3. 价差 + 资金费率 V3（`run_arbitrage_execution_v3.py`）

完整代码梳理见 [参考项目V3套利流程.md](参考项目V3套利流程.md)。这里只留骨架。

和网格不是同一策略的两个版本，而是在赌另一件事：**要么价差会一次性收敛到能赚走，要么价差暂时没戏但费率能当主收益**。一个币同一时间只有一仓，开满等到止盈 / 止损 / 费率恶化，全进全出。

### 3.1 开仓：两条互斥路径

先试价差，不行再试费率。调度器只把**最优正毛价差**送进决策；没有正毛价差时连决策都不进。

**价差套利（必须同时过）**

- 扣手续费后净边 > 0，且 ≥ 阈值 X。
- 真实空间 = 净边 − max(天然价差, 0) ≥ X。天然价差不够 10 个点、或超过 200 秒没更新 → 直接拒绝。
- 持续性连续满足 N 秒（yaml 默认 2s）。
- 费率：源码里 `diff` 取绝对值，年化 F 在开仓路径上实际挡不住；缺费率数据也会放行。

**资金费率套利**

- 调度层已要求存在正毛价差，因此真正能进这条的，是「毛为正、扣费后净边 ≤ 0」。
- 费率差为正、方向对持仓有利、差 ≥ Y。
- 价差亏损还没碰到止损线 Q。
- 历史费率和价差都要「稳定」。

V3 每个币只能有一仓，不能按格加仓。

### 3.2 平仓：三点触发全平

| 触发 | 默认 | 行为 |
|------|------|------|
| 止盈 | 往返盈利 ≥ P（约 0.02%） | 全平 |
| 止损 | 亏损 ≥ Q（约 0.3%） | 全平 |
| 费率不利 | 方向反转或年化 ≥ F，持续 ≥ M 分钟 | 全平 |

没有 T1/T2/T3，没有回落减一格。无正毛价差时调度器不调用平仓决策。平仓失败进人工黑名单。

## 4. 监控 V2（`run_arbitrage_monitor_v2.py`）

只发现、不下单。

- 各所订盘口，分析环扫内存。
- 毛价差 ≥ `min_spread_pct`（常用 0.1%）记为机会。
- Top-N 展示、按年龄续上榜。
- 跨所可减天然基差再判断是否上榜。

本仓库的 `loop_scan` 对这条，和网格执行环互斥。
