# 参考项目 V3 套利流程（代码梳理）

对象：仓库旁 `crypto-trading-open-main` 的 **V3 基础模式**（`V3-BASE`）。  
入口：`python run_arbitrage_execution_v3.py`。  
调度器：`ArbitrageOrchestratorV3`。决策：`ArbitrageDecisionEngine`。

本文只写参考 V3 **源码实际怎么跑**，不写本仓库网格。对照见 [套利流程对比.md](套利流程对比.md)。网格主链见 [参考项目套利流程.md](参考项目套利流程.md) 第 2 节。

V3 和分段网格不是同一策略的两个版本。它赌的是：**要么扣费后的净价差够一次性赚走，要么价差暂时没油水但资金费率能当主收益**。一个币同一时间只有一仓，开满等到止盈 / 止损 / 费率恶化，全进全出。没有 T1/T2/T3，没有按格加减仓。

下面阈值默认取 `config/arbitrage/arbitrage_unified.yaml`（dataclass 缺省值写在括号里，仅当 yaml 没覆盖时生效）。

---

## 1. 模块与入口

```
run_arbitrage_execution_v3.py
  默认 --unified-config  config/arbitrage/arbitrage_unified.yaml
  默认 --monitor-config  config/arbitrage/monitor_v2.yaml
  → ArbitrageOrchestratorV3.start()
```

| 模块 | 路径 | 职责 |
|------|------|------|
| 调度 | `core/arbitrage_orchestrator_v3.py` | 主循环、开平仓编排、费率组装、平仓上下文 |
| 决策 | `decision/arbitrage_decision.py` | 开仓两条路径、平仓三点、持仓字典 |
| 价差 | `analysis/spread_calculator.py` | 多所方向价差；决策只用**最优正毛价差** |
| 历史 | `history/spread_history_recorder.py` + `history_calculator.py` | 60s 采样入库；天然价差=中位数；稳定性 |
| 执行 | `execution/arbitrage_executor.py` | `is_segmented_mode=False`，轮次间隔 `round_pause_seconds` |
| 风控 | `risk_control/global_risk_controller.py` | 暂停、日交易次数、仓位上限、余额、网络 |
| 盘口 | `data/data_receiver.py` + `data_processor.py` | WS 入队、内存订单簿/ticker |

启动顺序（`start()`）：历史记录器 → 历史计算器 → 风险控制器 → 数据收发 → 连所并订阅 → 实盘再订私有订单 WS → UI → `_main_loop`（100ms）。

`system_mode.monitor_only: true` 时全流程照跑，执行器不下真实单。

---

## 2. 主循环

`_main_loop` 每 100ms 一轮：

1. `risk_controller.is_paused()` → 睡 1s，整轮空转。
2. `check_daily_trade_limit()` 不通过 → 同样空转。
3. 对 `monitor_config.symbols` 逐个 `_process_symbol`。

`_process_symbol`：

1. 该币被风控禁用 → 跳过。
2. `_get_orderbooks_for_symbol`：只保留新鲜度 ≤ `data_freshness_seconds`（yaml 默认 **3s**）的所；少于 2 所 → 跳过。
3. **有仓走平、无仓走开**。持仓按 `symbol` 索引，一个币同时只能有一仓（不能换所对加第二仓，也不能按格加仓）。

```
有仓 → _handle_close_position
无仓 → _handle_open_position
```

---

## 3. 开仓 `_handle_open_position`

历史记录和决策分开：先把**所有方向**的原始价差写进 recorder，再拿最优方向去做决策。

```
0. 所有方向价差 + ticker 费率 → history_recorder（与开不开仓无关）
1. calculate_spreads_multi_exchange → 最优正毛价差；没有正毛价差则直接 return
2. _get_funding_rate_data(buy所, sell所)
3. executor.calculate_order_quantity（币本位，yaml quantity_config）
4. 决策引擎里已有开放仓 → 跳过
5. risk_controller.check_position_limits
6. decision_engine.should_open_position → (should, mode, condition)
7. executor.execute_arbitrage(is_open=True)
8. 成功 → record_open_position + risk_controller.record_trade()
```

关键前置：**没有正毛价差时调度器直接返回，决策引擎根本进不去。** 注释里「两个方向价差都为负才走费率套利」在调度层已经被滤掉。费率路径实际只能在「毛价差为正、扣费后净边 ≤ 0」时被走到（见 4.2）。

---

## 4. 开仓决策 `should_open_position`

开关：`decision.enabled`、`enable_spread_arbitrage`、`enable_funding_rate_arbitrage`。  
已有 `positions[symbol].is_open` → 拒绝。

先价差，不行再费率。两条互斥：价差通过就不再看费率路径。

### 4.1 价差套利 `_check_spread_arbitrage_conditions`

手续费按该所配置的 `limit` / `market` 费率拆成买腿 + 卖腿（单位 %）：

```
net = spread_pct − (buy_fee% + sell_fee%)
```

必须同时过：

| 条件 | 代码行为 | yaml 默认 |
|------|----------|-----------|
| 有 `spread_data` | 没有则清持续性、拒绝 | — |
| 净边 > 0 | `net ≤ 0` 拒绝 | — |
| 净边 ≥ X | `spread_arbitrage_threshold` | **0.02%** |
| 天然价差有数 | `get_natural_spread` 返回 None → 拒绝 | 历史中位数；&lt;10 个点不入库 |
| 天然价差新鲜 | `now − last_update > 200s` → 拒绝 | 写死 200s |
| 真实空间 ≥ X | `net − max(nat, 0) ≥ X`；nat 为负当 0 | 同 X |
| 持续性 | `spread_persistence_seconds`；默认 yaml **2s**（dataclass 1s） | 中间任一项失败就清零 |

过了以上才看费率。**源码真实行为**（和注释不一致，见第 8 节）：

- ticker 里没有费率 → 打警告，**仍然开仓**，`mode=spread / condition1`。
- 有费率且 `funding_rate_diff > 0` → 直接开仓。因为 diff 被算成 `abs(sell−buy)×100`，只要两边费率不相等就恒正，**方向是否有利、年化是否超 F 都不再检查**。
- `funding_rate_diff < 0` 再比年化 F 的分支是死代码。

所以价差路径上，F（年化 10%）**挡不住开仓**。F 只在平仓的「费率幅度过大」分支里还活着。

### 4.2 资金费率套利 `_check_funding_rate_arbitrage_conditions`

注释写「价差两边都没油水才进」。代码实际：

| 条件 | 代码行为 | yaml 默认 |
|------|----------|-----------|
| 有费率数据且 `diff > 0` | 两边费率相等则拒绝 | — |
| `is_favorable_for_position` | `sell_rate ≥ buy_rate`，否则拒绝 | — |
| `diff ≥ Y` | `funding_rate_diff_threshold` | **0.01%**（已是百分数，见 5） |
| 当前这条最优腿扣费后净边 ≤ 0 | `net > 0` 视为价差仍有油水，**不进费率路径** | — |
| 价差亏损 &lt; Q | `abs(net) ≥ loss_stop_threshold` 拒绝 | **0.3%** |
| 无 `spread_data` | 决策里会假设价差无利可图；但调度器在无正毛价差时早已 return，这条几乎走不到 | — |
| 历史费率稳定 + 历史价差稳定 | `history_calculator.is_*_stable`；没数据当 False | 见下 |

通过则 `mode=funding_rate / condition1`。

稳定性（`history_calculator`，阈值在 yaml `thresholds`）：

- 费率：波动系数、持续占比、极端波动次数，三项都过才算稳。
- 价差：波动系数 + 极端波动。
- 最少 10 个点。采样间隔 60s，刚启动往往不够点。

净边仍为正但低于 X 时：价差路径失败，费率路径又因 `net > 0` 失败 → **两边都不开**。

---

## 5. 资金费率怎么算 `_get_funding_rate_data`

从两所 ticker 取 `funding_rate`（小数，如 `0.0001`）。缺一边 → `None`。

```
funding_rate_diff         = abs(sell − buy) × 100          # 恒 ≥ 0，单位已经是「百分数」
funding_rate_diff_annual  = funding_rate_diff × 365 × 3     # 写死 8h 结算、每天 3 次
is_favorable_for_position = (sell ≥ buy)
```

有利含义：空腿所费率 ≥ 多腿所费率（空头收得更多或付出更少）。

历史记录里年化用的是 `abs_diff × 1095 × 100`（`1095=365×3`），和决策路径 `×365×3` 且已经 `×100` 过，口径不同。决策热路径以 `_get_funding_rate_data` 为准。

## 6. 平仓 `_handle_close_position`

1. 该币在 `_manual_close_blocklist` → 不再自动平，等人工。
2. 再算一遍最优正毛价差；**没有正毛价差则直接 return，连 `should_close_position` 都不调用**。两边盘口都吃不下（两向毛价差都 ≤ 0）时，止盈/止损/费率平仓都会卡住。
3. 费率按**持仓方向**的 buy/sell 所拉，不是当前最优方向。
4. `_build_close_position_context`：用持仓所的盘口算往返。
5. `should_close_position` 三点任一触发 → 反向两腿 `execute_arbitrage(is_open=False)`。
6. 平仓数量来自 `calculate_order_quantity`（配置单笔量），**不是** `position.quantity`。两者不一致或部分成交 → 剩仓进人工黑名单。

### 6.1 往返盈亏 `_build_close_position_context`

平多腿：在开仓买入所卖出（用该所 **best bid**）。  
平空腿：在开仓卖出所买入（用该所 **best ask**）。

```
long_leg  = (平多价 − 开多价) / 开多价 × 100
short_leg = (开空价 − 平空价) / 开空价 × 100
total_profit_pct = long_leg + short_leg
```

这是相对开仓价的两边收益率之和，不是「当前毛价差 − 开仓毛价差」。

### 6.2 三点触发 `should_close_position`

无持仓或没有 `spread_data` → 不平。

有 `close_context` 时用 `total_profit_pct`；否则回退 `_calculate_profit_percentage` = `当前最优毛价差 − 开仓毛价差`（口径更差，且可能不是持仓那条所对）。

| 触发 | 条件 | yaml 默认 | 原因字符串 |
|------|------|-----------|------------|
| 止盈 | `profit ≥ P` | **0.02%** | `profit_target_reached` |
| 止损 | `profit < 0` 且 `abs(profit) ≥ Q` | **0.3%** | `spread_loss_stop_loss` |
| 费率不利 | 见下，持续 ≥ M 分钟 | **60 min** | `funding_rate_unfavorable_stop_loss` |

没有格子、没有减一格、没有 T0。触发即按配置量平；仓归零才 `record_close_position`。

### 6.3 费率不利 `_check_funding_rate_unfavorable`

满足任一即进入「不利」，从第一次不利起计时，持续 ≥ M 才平。恢复有利则清计时。

1. **方向反转**：`is_favorable_for_position == False`（现在 `sell < buy`）。
2. **幅度过大**（`elif`）：`abs(funding_rate_diff_annual) ≥ F`（yaml **10%/年**）。

因为 diff 已是绝对值，有利且年化很大时第一条不过，第二条仍会把状态标成不利。强有利的大费率差也可能被这条平掉。

## 7. 执行与风控

### 7.1 执行

`ArbitrageExecutor(..., is_segmented_mode=False)`。基础模式保留轮次间隔：yaml `order_execution.round_pause_seconds` 默认 **60s**（分段网格强制 0）。一笔开或平打完，下一笔同执行器要等这个窗口。

下单模式、优先级、tick 内侧、双限价、滑点与分段网格共用 `arbitrage_execution` 段。V3 数量只读 `quantity_config`（`single_order_quantity` / `max_position_quantity`），不读网格的 `base_quantity`。

开仓两腿方向 = 决策里的 buy 所开多、sell 所开空。  
平仓两腿对调：`exchange_buy=持仓空腿所`（买回），`exchange_sell=持仓多腿所`（卖出）。

### 7.2 风控（调度层会挡循环的）

`GlobalRiskController` 后台自己转，和决策解耦。调度每轮只问：

- 是否 `paused`（网络故障、维护、余额等可把整系统停住）
- 每日交易次数
- 开仓前 `check_position_limits`
- 单币是否 disabled

yaml `risk_control` 还有余额警告/清仓阈值、价格异常、持仓最长时间、单笔亏损上限等。`on_close_all_positions` 回调在调度器里只打日志，**不会自动把 V3 持仓扫一遍平掉**。

平仓失败或数量对不上 → `_manual_close_blocklist`，该币停自动平直到人工处理。

## 8. 代码和注释不一致（读源码时以代码为准）

| 注释 / 文档说法 | 源码 |
|-----------------|------|
| 费率差可正可负，要付时年化不能超 F 才开价差仓 | `diff = abs(...)`，价差路径上 `diff < 0` 分支死；F 开仓用不上 |
| 两个方向价差都为负才走费率套利 | 调度器用 `calculate_spreads_multi_exchange`，无正毛价差直接 return |
| 天然价差「运行时间 &lt; 3 分钟拒绝」 | 决策只看 `get_natural_spread` 是否有结果；计算器 &lt;10 点不写入。`min_runtime_minutes=3` 用来拉动态窗口，不是决策硬闸 |
| 平仓「当前价差 − 开仓价差」 | 有 `close_context` 时用两边开平价收益率之和 |
| 订单簿注释写「2 秒内」 | yaml `data_freshness_seconds: 3.0` |

## 9. 一张图串起来

```
100ms 主循环
  暂停 / 日限额？ → 空转
  每个 symbol
    新鲜盘口 < 2 所？ → 跳过
    有仓？
      ├─ 人工黑名单 → 跳过
      ├─ 无正毛价差 → 跳过（平仓也进不去）
      ├─ 持仓方向拉费率 + 往返盈亏
      └─ 止盈 P / 止损 Q / 费率不利满 M 分钟
           → 反向两腿平；失败进黑名单
    无仓？
      ├─ 记全部方向历史
      ├─ 无正毛价差 → 跳过
      ├─ 数量 / 仓位上限
      └─ 决策：价差路径（净边、nat、持续性）
               不过再费率路径（有利、Y、净边无油水、稳定）
           → execute_arbitrage 开仓
           → 成功记 PositionInfo（按 symbol）
```

## 10. 默认阈值速查（`arbitrage_unified.yaml`）

| 符号 | 字段 | 默认 |
|------|------|------|
| X | `spread_arbitrage_threshold` | 0.02% |
| 持续性 | `spread_persistence_seconds` | 2s |
| Y | `funding_rate_diff_threshold` | 0.01% |
| P | `profit_target_threshold` | 0.02% |
| Q | `loss_stop_threshold` | 0.3% |
| F | `funding_rate_annual_threshold` | 10%/年 |
| M | `unfavorable_funding_rate_duration_minutes` | 60 |
| 盘口新鲜 | `system_mode.data_freshness_seconds` | 3s |
| 轮次间隔 | `round_pause_seconds` | 60s |
| nat 过期 | 写死 | 200s |
| nat 点数 | `min_data_points` | 10 |

`ignorable_spread_threshold` / `ignorable_funding_rate_diff_threshold` 在决策热路径里没有引用。
