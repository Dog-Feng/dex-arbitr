# 价差均值算法与步数停滞问题：分析与改造方案

日期：2026-10-21
状态：方案 B（z-score 入场）与 z 单位阶梯（`step_z`）已实现并通过单日回放验证，
可通过配置切换；方案 C 已部分实现：`strategy.z_close`（z 回归强制平）与
`strategy.close_hold`（时长强制平）+ `strategy.forced_close_cooldown`（强制平后同方向冷却），
默认关闭、逐项开关；浮亏止损（`loss_stop_bps`）仅在回放工具中模拟。
实现分支：`codex/zscore-spread`（从 `feat/entropy-venue-20261019` 拉出）。

## 1. 背景：观察到的现象

多次实盘运行（ANTH：rhlighter × entropy）呈现一致的模式：

1. 预热结束后，行情处于振荡区间时，步数能正常加减（churn 期单桶 100+ 笔执行、开≈平）。
2. 行情进入**单边漂移**（如 2.5 小时漂移约 -35 bps）或**极静**（σ 降至 0.25~0.5 bps）后，
   步数爬满 `max_steps`，随后长时间冻结（数十分钟到数小时零成交）。
3. 状态机始终 RUNNING、errors≈0、status 每分钟正常采样——不是进程或决策循环卡死，
   而是每次 Decide 都命中拦截条件返回空动作。

冻结期特征告警：`full_load`（满仓超 30 分钟）、`silent`（零成交超 30 分钟）、
`oldest_step_age`（最老一步超 60 分钟）。

## 2. 根因分析

### 2.1 均值滞后：2h SMA 追不上漂移

- 锚是 2h 简单均值，单边漂移时滞后可达几十分钟。
- `dev = 当前价差 - mu` 在漂移期持续为正，策略沿"均值回归"方向持续开仓（接飞刀），
  一路开到 `max_steps`。
- 观测到的价差长期带约 -190 ~ -70 bps（中心约 -130），漂移段可达 30~50 bps，
  远超短周期 σ（0.25~1.3 bps）。

### 2.2 开平仓之间的"死区"让高位无法减仓

- 开仓门槛（volume 模式）：`dev ≥ openFeeBps(≈1.8 bps) + VolK×σ`，顶部带再加 1σ。
- 平仓门槛：单步毛利 ≥ `入场费摊销(0.9 bps) + 出场费(0.9 bps)` ≈ 1.8 bps；
  再计入两所顶档盘口宽度 w（约 0.5~1.5 bps），实际需要价差从该步入场水平
  回撤 **1.8 + w ≈ 2.3~3.3 bps**。
- 在 σ ≈ 0.5 bps 的静默期，价差振荡幅度够不到这个回撤量；漂移期则全部浮亏。

### 2.3 没有强制减仓出口

策略只有"获利才平"，没有止损、持仓时长上限或基于浮亏的反向平仓。
因此满仓 + 无利可平 + 无止损三者同时成立时，步数进入终态。

### 2.4 结论

`max_steps`（10/50/100）只决定"在哪里冻结"，不阻止冻结。问题本质是：
慢均值锚 + 不对称开平门槛 + 无强制减仓，三者叠加。

## 3. 方案 A：不改算法，仅调整配置（缓解）

目标：漂移期接得少、满得慢、包更小。**不解决冻结终态**，属于过渡方案。

| 配置项 | 现值 | 建议 | 作用 |
|---|---|---|---|
| `estimator.window` | 2h | 30m（可试 15m） | 均值更快跟随局部水平，减少接飞刀 |
| `estimator.min_warmup` | 60m | 15m | 同上，缩短无法交易的预热期 |
| `strategy.vol_k` | 1 | 2~3 | 开仓只做更显著的偏离 |
| `pairs[].max_steps` | 50 | 10~20 | 封顶库存，冻结时浮亏包缩小 |
| `strategy.cap_band` | 1 | 2~3 | 满仓回落后不立即再次冲满 |
| `strategy.cap_hysteresis_sigma` | 1 | 0 | 去掉 max-1 处的额外 1σ，减少高位吸住 |
| `strategy.interval_min / max` | 1s / 2s | 5s / 15s | 爬坡减速，给均值追赶时间 |
| `strategy.depth_mult` | 3 | 2 | 减少薄盘挡住本可盈利平仓 |

风险：窗口缩短后，均值本身更"抖"，dev 信号更频繁、单笔质量下降；需要配合
`vol_k` 提升来过滤。改完应先回放历史样本对比再上实盘。

## 4. 方案 B：z-score 入场算法（改造）

> 实现状态：已完成。`estimator.kind: zscore` + `strategy.kind: zscore` +
> `strategy.z_open` 可切换；常规平仓规则与 Arbitrage 完全一致。2026-10-24 起新增
> 强制退出：`z_close`（同方向 z 回到该值以内强制平，可能小亏，用于兑现回归）、
> `close_hold`（持仓超时强制平，用于解冻）、`forced_close_cooldown`（强制平后同方向重开冷却）。

### 4.1 原理

把"偏离多少 bps 开仓"改为"偏离多少个标准差开仓"：

```text
z = (q.Mid - μ) / σ_long
开仓：|z| ≥ z_open（建议 2）
平仓：|z| 回归到 z_close（建议 0.5）以内且毛利覆盖出场费
止损：|z| ≥ z_stop（建议 3）或浮亏超过阈值，强制减仓
```

- μ：短周期锚，EMA half-life 10~30 分钟（替代 2h SMA），跟随局部公平价值；
- σ_long：价差的长周期标准差，EWMA half-life 2~4h（替代 500ms σ 做归一化），
  并设下限（如 0.5 bps）避免极静行情放大噪声。

### 4.2 为什么适合"价差波动大"的场景

- 阈值随行情的波动尺度自动缩放：价差长期宽幅震荡时 σ_long 大，z=2 需要真实的大
  偏离才开仓，不再对着慢均值一路接飞刀；价差紧贴局部均值时 σ_long 小，小回撤即可
  触发，churn 更勤。
- 短锚 μ 跟随漂移，单边行情下 dev 始终很小，z 不会持续为正 → 不再爬满。

### 4.3 代价与注意点

- z-score 只解决**入场闸门**，出场仍需补规则：z 回归平仓 + 止损是必须项。
- σ_long 的估计要防突变：用 EWMA 而非滚动窗口；μ 与 σ_long 的 half-life 需要
  用历史数据标定。
- 收益来源被收窄为"局部极端偏离的均值回归"：交易频率下降、单笔质量上升，
  与 volume 策略"刷量"的初衷有冲突，`z_open` 需要按目标折中。
- 方向翻转逻辑可简化：`|z|` 穿过 `z_open` 才翻方向，替代现有 flip hysteresis。

### 4.4 与现有代码的接缝

- `internal/spread/estimator` 增加 `zscore` 实现（EMA 均值 + EWMA std），实现现有
  `Estimator` 接口（`Update/Mean/Stats/ReadyAt`）；
- `internal/strategy` 新增 `zscore` 策略：开仓用 z 阈值（z_open + 翻转/容量滞回，
  仍要求 dev ≥ 往返费），平仓沿用 Arbitrage 的毛利规则；未新增止损候选；
- `internal/config` 增加 `estimator.kind: zscore`（`mu_half_life/sigma_half_life/
  sigma_floor`）与 `strategy.kind: zscore`（`z_open`）；
- 两个方案的指标统一经 `cmd/backtest` 输出，便于 A/B。

## 5. 方案 C（建议）：z-score 入场 + 强制减仓出口

> 实现状态：`z_close` 与 `close_hold` 已实现（2026-10-24）；`loss_stop_bps` 仍未实现，
> 仅在回放工具中模拟。

无论采用 A 还是 B，都建议新增至少一条**无条件减仓路径**，配在 `strategy` 下可开关：

- `hold_time_limit`：单步持仓超过 N 分钟强制平（默认关闭）；
- `loss_stop_bps`：单步未实现毛利低于 -X bps 强制平（默认关闭）。

已落地为 `strategy.z_close`（默认 0.5 语义：同方向 z <= z_close 即强制平，不设毛利门，
因为毛利为正的情况常规平仓规则已覆盖）与 `strategy.close_hold`（默认关闭），
并配套 `strategy.forced_close_cooldown` 防止平后立刻同方向重开。

2026-10-24 用 2.7 天 100ms 样本（209.5 万行）回测结论：
`close_hold=180m + forced_close_cooldown=15m + z_close=0` 为当前最优——净 PnL +5.15
（基线 +3.87），结束时零冻结步数；`z_close` 无论 0.5 还是 0.2 都因低 σ 时段
毛利覆盖不了手续费而显著亏损（-36 / -7.9），建议保持关闭；`close_hold=60m` 过度
churn（净 -14.7）。配置按此调整。

这是"满仓冻结"的根治项，独立于入场算法。

## 6. 回测验证（已完成：单日样本）

数据来源（服务器）：

- `state-anth/samples/ANTHROPIC_rhlighter_entropy.jsonl`：100ms 价差样本
  （15 列，`cmd/opencount` 已支持该格式），建议至少 24h、3 天更佳；
- `state-anth/trades/trades.jsonl`：成交事件，用于校准；
- `state-anth/ANTHROPIC_rhlighter_entropy.json`：状态文件，用于核对各步入场价（可选）。

步骤：

1. **校准**：用现有算法（2h SMA + volume 阈值）原样回放样本，目标复现实盘
   "预热 → churn → 爬满 → 冻结"的时点；复现度高才认为回放引擎可信。
2. **A/B**：同一数据跑方案 A（配置调整版）与方案 B（z-score 版）。
3. **报告**：逐项对比开仓/平仓次数、峰值步数、满仓冻结时长、平均持仓时长、
   模拟净 PnL（费率模型：RH 0、HL taker 0.009%）、最大回撤与关键事件时间线。

模拟边界（结论不夸大）：

- 成交近似：决策价 + tick 让价、顶档深度门，无法模拟真实延迟/部分成交/拒单/救援；
- 样本由系统在 600ms 新鲜度门控下记录，代表"可交易时刻"，适合决策层回放；
- z-score 的 σ_long 需要历史预热，窗口越长评估越稳。

回放结果（2026-10-21 08:21Z~17:36Z 样本，`cmd/zbacktest`）：

1. **校准通过**：SMA+volume 复现实盘——首开 09:22（实盘 09:22）、峰值 50、
   冻结 7h10m（实盘约 6.7h），计数与实盘同量级。
2. **z-score 无阶梯**：净 PnL +1.00（现状 +0.44，约 2.3 倍）；漂移期零开仓
   （末笔 10:20 比 sma 更早收手）；但仍满仓 50 冻结 7h15m。
3. **z-score + step_z 阶梯**：step_z=0.5/1.0 时入场带从 3.1 bps 扩到 ~76 bps
   （覆盖当天整段可交易区间）；冻结从 7h+ 降到 55m~1h14m；净 PnL +2.85/+3.15；
   自然停在 17~33 步。step_z 过小（≤0.25）或过大（≥2）均退化。
4. **止损模拟**（未实现到系统，仅在回放工具中模拟）：本样本日任何止损组合均
   亏损（固定冷却 -5~-22；z 归零重开 -7~-11），因为当日为约 100+ bps 的单边
   漂移，止损只会把浮亏实亏化。止损价值需跨日样本验证。

结论：**z-score + step_z（0.5~1.0）是当前数据下的推荐组合**；冻结残余由
max_steps 控制（实际冻结步数随阶梯自动降到 17~33，无需手动调小）。

## 8. 风险与回滚

- 方案 A 只改配置，随时可回滚；
- 方案 B/C 为新增 estimator 与策略分支，默认关闭、配置切换，回滚即改回
  `estimator.kind: sma`；
- 任何阈值/止损改动在 dry_run 下观察至少一个完整"预热→漂移→冻结"周期后再上线。
